1.1 What is "Cloud Native"?

Cloud Native is about how you build and run applications, not where you run them. It's a set of practices and technologies that fully exploit the cloud computing model — even if you're running on your own servers (on-premises).

📖 Key Term: Cloud Native

Cloud Native refers to building and running applications that fully exploit the cloud computing delivery model. It's about how applications are created and deployed, not where they run. The Cloud Native Computing Foundation (CNCF) is the organization that governs Kubernetes and many other cloud native projects.

The 5 pillars of cloud native work together like interlocking gears:

📦 Containers

Standardized packaging for applications. Every container includes the app + all its dependencies — runs the same everywhere.

🧩 Microservices

Breaking big apps into small, independent services. Each service does ONE thing well and can be deployed separately.

🕸️ Service Mesh

Infrastructure layer for service-to-service communication. Handles mTLS, traffic management, and observability automatically.

🏗️ Immutable Infrastructure

Never modify running servers. Deploy NEW ones and destroy old ones. No configuration drift, no snowflake servers.

📜 Declarative APIs

You declare WHAT you want ("3 replicas of anihpj"), not HOW to do it. Kubernetes figures out the HOW.

1.2 How Software Deployment Evolved

Software deployment has gone through four major eras. Each solved the problems of the previous era — but created new challenges that the next era had to solve. Understanding this evolution helps you understand WHY Kubernetes exists.

🖥️
2000-2010
Physical Servers

One application per physical server. No isolation between apps. Massive resource waste — most servers ran at 5-15% capacity. Deploying anihpj meant buying and racking a new server, installing the OS, configuring networking — weeks of work.

❌ Wasteful, slow, expensive
💻
2010-2015
Virtual Machines

Multiple VMs per physical server via hypervisors. Better resource utilization and isolation. But each VM runs a full OS — gigabytes of RAM just for the operating system. Still slow to provision (minutes per VM).

⚠️ Heavy OS overhead, slow boot
📦
2015-2020
Containers + Docker

Lightweight, portable, share the host kernel. Start in seconds instead of minutes. But managing hundreds of containers across dozens of servers manually? That's a nightmare — which pod crashed? Which server has capacity?

🟡 Almost there...needs orchestration
☸️
2020+
Cloud Native + Kubernetes

Automated orchestration of containers. Declarative configuration. Self-healing, auto-scaling, rolling updates. anihpj deployed with one command across multiple servers — K8s handles everything.

✅ Perfect — automated, scalable, resilient

🔑 KCNA Decision Rule

Start with a monolith. Split into microservices ONLY when you have: (1) a clear team boundary, (2) independent scaling needs, or (3) different technology requirements per component. Kubernetes makes microservices manageable — but it doesn't mean you must use them.

│  │  Each item: DIFFERENT sizes, shapes, handling requirements      │  │

│                                                                      │

📝 Chapter 1 — KCNA Practice Questions (10 MCQs)

Q1
Which of the following is NOT one of the 5 pillars of Cloud Native?
Show Answer
Answer

Virtual Machines. The 5 pillars are: Containers, Microservices, Service Mesh, Immutable Infrastructure, and Declarative APIs.

Explanation

VMs are a deployment technology that preceded cloud native. Cloud native specifically emphasizes containers as the packaging mechanism.

Q2
What is the correct order of CNCF project maturity levels?
Show Answer
Answer

Sandbox → Incubating → Graduated. Projects progress from experimental (Sandbox) through growing adoption (Incubating) to production-ready and widely adopted (Graduated).

Explanation

Kubernetes, Prometheus, Envoy, etcd, Helm, Jaeger, Linkerd are all Graduated CNCF projects.

Q3
Which deployment era introduced the concept of running multiple isolated operating systems on a single physical server?
Show Answer
Answer

Virtual Machines (Era 2, ~2010-2015). VMs allowed multiple OS instances on one physical server via hypervisors, improving resource utilization over bare metal.

Explanation

While VMs improved utilization, each VM still runs a full OS — making them much heavier than containers.

Q4
What is the primary advantage of a monolithic architecture for a small application like anihpj?
Show Answer
Answer

Simplicity — a monolith is simpler to develop, test, deploy, and debug. Everything is in one codebase, one process, and one deployment unit.

Explanation

KCNA expects you to know WHEN each architecture is appropriate. Small teams and simple apps = monolith first.

Q5
The shipping container analogy explains software containers by comparing them to:
Show Answer
Answer

Standardized physical shipping containers that transformed global trade by providing a uniform, stackable, any-ship/any-port compatible packaging system.

Explanation

Just as physical containers standardized cargo shipping (any ship, any port, any crane), software containers standardize application deployment (any server, any cloud, any environment).

Q6
In the maritime port metaphor, what Kubernetes component corresponds to the "Berth Planner"?
Show Answer
Answer

kube-scheduler. The scheduler watches for new pods with no assigned node and decides which worker node is the best fit for each pod.

Explanation

The scheduler uses filtering (which nodes CAN run it?) and scoring (which node is BEST?) to make placement decisions.

Q7
Which of these is a CNCF Graduated project?
Show Answer
Answer

Prometheus is a CNCF Graduated project. Other Graduated projects include Kubernetes, Envoy, etcd, Helm, Jaeger, Linkerd, containerd, and Fluentd.

Explanation

Argo, Cilium, Falco, and Knative are Incubating (not yet Graduated). Backstage and KubeVirt are Sandbox.

Q8
What is the key difference between "immutable infrastructure" and traditional server management?
Show Answer
Answer

With immutable infrastructure, you never modify running servers — you deploy NEW ones and destroy old ones. Traditional management involves SSH-ing into servers to make changes, leading to configuration drift.

Explanation

Immutable infrastructure eliminates "snowflake servers" — every server is created from a known, versioned template.

Q9
A company's job board gets 10x normal traffic during a holiday sale. Without Kubernetes, the server crashes. With Kubernetes, what handles this automatically?
Show Answer
Answer

Horizontal Pod Autoscaler (HPA) detects increased CPU/memory usage and automatically adds more pods to handle the traffic spike.

Explanation

This is one of the 8 superpowers of Kubernetes — auto-scaling. When traffic drops, HPA scales back down to save resources.

Q10
According to the 4-week study plan, approximately how many total hours should you dedicate to KCNA preparation?
Show Answer
Answer

~32 hours over 4 weeks (about 8 hours per week, or roughly 1-2 hours per day).

Explanation

Week 1: 8h (Foundations), Week 2: 10h (K8s Core), Week 3: 10h (Workloads & Networking), Week 4: 4h (Advanced + Exam Prep).
