"This category is about where your application's data lives and how to

  ST1: PVC Stuck in Pending — No StorageClass
       Symptom: kubectl get pvc shows Pending forever. No PV provisioned.
       anihpj: PostgreSQL PVC for anihpj-db won't bind

  ST2: PVC Access Mode Mismatch — RWO vs RWX
       Symptom: PV exists but PVC won't bind. accessModes don't match.
       anihpj: Two API pods on different nodes need same volume (RWX required)

  ST3: Volume Not Expanding — allowVolumeExpansion Not Set
       Symptom: Edited PVC to increase size, but it stays at old capacity.
       anihpj: Database growing, need to expand from 5Gi to 20Gi

  ST4: CSI Driver Not Found — Dynamic Provisioning Fails
       Symptom: StorageClass references a provisioner that doesn't exist.
       anihpj: Using AWS EBS CSI driver but not installed

  ST5: PV in Released State — Can't Reuse
       Symptom: Deleted PVC, but PV shows "Released" not "Available"
       anihpj: Cleaning up test namespace, need to reuse the EBS volume

  ST6: Pod Can't Mount Volume — Permission Denied
       Symptom: Pod stuck in ContainerCreating, events show "permission denied"
       anihpj: fsGroup not set, PostgreSQL can't write to data directory

  ST7: DiskPressure — Node Evicting Pods
       Symptom: Node shows DiskPressure=True, pods being evicted
       anihpj: Container logs filling up /var on worker node

  ST8: hostPath Volume — Data Lost After Pod Reschedule
       Symptom: Pod restarted on different node, data missing
       anihpj: Used hostPath for database storage (wrong choice!)

  ST9: ConfigMap Too Large — Can't Mount as Volume
       Symptom: ConfigMap exceeds 1MB etcd limit
       anihpj: Large nginx config file as ConfigMap

  ST10: Volume SubPath Not Updating
        Symptom: Updated ConfigMap, but subPath mount still shows old content
        anihpj: Mounted specific config file via subPath, changes not reflected
