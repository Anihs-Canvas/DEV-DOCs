                <p><strong>Tenet:</strong> etcd is EXTREMELY sensitive to disk I/O latency. The absolute requirements: fsync latency must be <10ms (SSD mandatory), at least 50 sequential IOPS, no other workloads sharing the disk. If latency exceeds the RAFT heartbeat interval (100ms), leader elections cascade and the cluster becomes unstable. Always run etcd on dedicated SSD storage. Use <code>iostat -x 1</code> to monitor await (average I/O latency). On CKA: you'll need to diagnose etcd performance issues from logs and metrics.</p>

sudo mv /etc/kubernetes/manifests/kube-apiserver.yaml /tmp/
sleep 15

<span class="token comment"># Step 2: Take a snapshot before migration (safety first!)</span>
sudo ETCDCTL_API=3 etcdctl snapshot save /backup/pre-migration.db \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key

<span class="token comment"># Step 3: Move etcd data to SSD location (e.g., /ssd/etcd)</span>
sudo mkdir -p /ssd/etcd
sudo cp -a /var/lib/etcd/. /ssd/etcd/
sudo chown -R etcd:etcd /ssd/etcd

<span class="token comment"># Step 4: Update etcd manifest to use new data-dir</span>
sudo sed -i 's|/var/lib/etcd|/ssd/etcd|g' /etc/kubernetes/manifests/etcd.yaml

<span class="token comment"># Step 5: Kubelet restarts etcd with new data-dir</span>
sleep 15

<span class="token comment"># Step 6: Restore API server</span>
sudo mv /tmp/kube-apiserver.yaml /etc/kubernetes/manifests/
sleep 15
kubectl get nodes</code></pre>
