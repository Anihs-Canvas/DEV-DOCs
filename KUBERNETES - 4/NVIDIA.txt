    NVIDIA CERTIFICATION — EXAM TOP 10 MISTAKES TO AVOID
    ─────────────────────────────────────────────────────
    ┌──────────────────────────────────────────────────────────────┐
    │  ❌ COMMON MISTAKES                 ✅ WHAT TO DO INSTEAD    │
    │                                                              │
    │  1. Confusing GPU memory types     Draw the memory hierarchy│
    │     (global vs shared vs register) before starting          │
    │                                                              │
    │  2. Not understanding Tensor Core  Remember: MMA operations │
    │     precision modes (FP8/FP16/TF32) in one clock cycle      │
    │                                                              │
    │  3. Forgetting NVLink bandwidth    Memorize key numbers:    │
    │     numbers across generations      600→900→1800 GB/s       │
    │                                                              │
    │  4. Mixing up CUDA thread hierarchy Grid > Block > Warp     │
    │     (grid/block/warp/thread)        > Thread                 │
    │                                                              │
    │  5. Not knowing MIG partitioning    A100: max 7 instances   │
    │     limits for A100 vs H100         H100: max 7 instances   │
    │                                                              │
    │  6. Confusing InfiniBand speeds     HDR=200, NDR=400,       │
    │     (HDR vs NDR vs XDR)             XDR=800 Gb/s            │
    │                                                              │
    │  7. Not knowing GPU generation order Kepler→Maxwell→Pascal  │
    │     and key features per gen        →Volta→Turing→Ampere    │
    │                                      →Hopper→Blackwell       │
    │                                                              │
    │  8. Forgetting the 4 CUDA memory    Global, Shared, Local,  │
    │     transfer optimization patterns  Pinned, Unified, Async  │
    │                                                              │
    │  9. Not understanding FP16/FP32     FP16=fast but range     │
    │     precision tradeoffs              FP32=stable but slow    │
    │                                                              │
    │  10. Skipping hands-on labs         Use NVIDIA DLI + NGC    │
    │      and only reading theory         containers for practice │

    3.2  CUDA Programming Model — Threads, Blocks, Grids
         - Thread: Smallest unit of execution (one CUDA core)
         - Warp: 32 threads executing in lockstep
         - Block: Group of threads (up to 1024) with shared memory
         - Grid: All blocks for a kernel launch
         - Hierarchy: Grid → Blocks → Warps → Threads
         - Key insight: Write code for ONE thread, launch MILLIONS

    3.3  CUDA Memory Model
         - Global Memory: Largest, slowest, accessible by all threads (HBM)
         - Shared Memory: Per-block, fast, programmer-managed (on-chip)
         - Local Memory: Per-thread, spills from registers
         - Registers: Per-thread, fastest, limited (~255 per thread)
         - Constant Memory: Read-only, cached, for uniform data
         - Texture Memory: Read-only, spatially cached, for 2D/3D data

    4.1  GPU vs CPU Architecture — The Fundamental Difference
         - CPU: Latency-optimized, few powerful cores, large caches, branch prediction
         - GPU: Throughput-optimized, thousands of simple cores, hide latency with parallelism
         - Key metric: CPU ~50-100 GFLOPS vs GPU ~1000+ TFLOPS (10,000x difference!)

    4.2  Streaming Multiprocessor (SM) Deep Dive
         - Each SM on H100: 128 FP32 CUDA Cores + 4 Tensor Cores + 1 RT Core
         - H100 has 132 SMs running at ~1.8 GHz
         - Warp scheduler picks 32 threads (one warp) per cycle
         - 4 warp schedulers per SM = can issue 4 warps simultaneously
         - Occupancy: up to 2048 threads active per SM (64 warps)

    4.3  Tensor Cores — The AI Engine
         - Tensor Cores perform D = A × B + C in one clock cycle (MMA operation)
         - 4th Gen Tensor Cores (H100): Support FP8, FP16, BF16, TF32, FP64, INT8
         - Transformer Engine: Dynamically chooses FP8 vs FP16 for each layer
         - Performance: 989 TFLOPS (FP16) vs A100's 312 TFLOPS (3x improvement)
         [ILLUSTRATION: How Tensor Cores do matrix multiply in one clock cycle]

    4.5  GPU Memory Architecture (HBM vs GDDR)
         - GDDR (Graphics DDR): Outside chip, wider bus, higher latency (GeForce RTX)
         - HBM (High Bandwidth Memory): Stacked on interposer, narrower bus, 3D stacked
         - HBM3 on H100: 80GB, 3.35 TB/s bandwidth, 5 stacks of 8 layers each
         - Key advantage of HBM: closer to GPU die = lower latency, higher bandwidth

         [WARP DIVERGENCE — Why if/else kills GPU performance]
         ┌──────────────────────────────────────────────────────────┐
         │  ❌ BAD (Thread-level branching — 2x slower):            │
         │  if (threadIdx.x % 2 == 0) do_A(); else do_B();         │
         │  → 16 threads run A, THEN 16 run B = serialized!        │
         │                                                           │
         │  ✅ GOOD (Warp-level branching — full speed):            │
         │  if (threadIdx.x / 32 % 2 == 0) do_A(); else do_B();   │
         │  → Entire warps take same path = no divergence!         │
         │                                                           │
         │  Rule: All 32 threads in a warp must follow same branch  │
         └──────────────────────────────────────────────────────────┘

          [DIAGRAM: All-Reduce animation — ring algorithm]

          [NCCL COLLECTIVE OPERATIONS — VISUAL GUIDE]
          ┌──────────────────────────────────────────────────────────┐
          │                                                           │
          │  ALL-REDUCE (Most common — gradient sync in training)    │
          │  ┌──────────────────────────────────────────────────┐   │
          │  │  GPU0: [A]──┐           ┌──[A+B+C+D]→ GPU0      │   │
          │  │  GPU1: [B]──┤  Ring    ├──[A+B+C+D]→ GPU1      │   │
          │  │  GPU2: [C]──┤ AllReduce├──[A+B+C+D]→ GPU2      │   │
          │  │  GPU3: [D]──┘           └──[A+B+C+D]→ GPU3      │   │
          │  │  Every GPU ends with the SUM of all gradients    │   │
          │  └──────────────────────────────────────────────────┘   │
          │                                                           │
          │  ALL-GATHER (Collect data from all GPUs)                  │
          │  GPU0: [A] → [A][B][C][D]  (every GPU gets all data)   │
          │                                                           │
          │  REDUCE-SCATTER (Reduce then scatter result)             │
          │  All GPUs sum → Each gets a unique slice of result       │
          │                                                           │
          │  BROADCAST (One GPU shares to all)                        │
          │  GPU0: [model] → GPU1, GPU2, GPU3 all get [model]       │
          │                                                           │
          │  NCCL Performance (8x H100, NVLink + IB):                 │
          │  • All-Reduce 1GB: ~200 µs                                │
