PRE-LEARNING: DOCKER & CONTAINER FOUNDATIONS (Novice Foundation)
═══════════════════════════════════════════════════════════════════════
Before diving into the exam domains, this section builds your container
mental model. Essential for novices; useful refresher for everyone.

F.1 What Problem Does Docker Solve?
    • The "It Works on My Machine" Problem — dev vs prod parity
    • From Bare Metal → VMs → Containers — the evolution of compute isolation
    • Monolith vs Microservices — why anihpj splits Django + PostgreSQL + Redis
    • The 12-Factor App methodology and how Docker implements each factor
    • Docker vs Podman vs containerd — the container ecosystem explained
    🟢 Novice

F.2 Containers 101 — What IS a Container?
    • Process isolation, NOT a "mini VM" (shared kernel, separate namespaces)
    • Linux primitives: namespaces (PID, NET, MNT, UTS, IPC, USER, cgroup)
    • cgroups — limiting CPU, memory, I/O per container
    • Union filesystems (overlay2) — how image layers work
    • Docker architecture: Client → daemon (dockerd) → containerd → runc
    • OCI (Open Container Initiative) — runtime spec + image spec
    🟢 Novice | 🟡 Intermediate: Deep namespace dive, cgroup v2

F.3 Dockerfile Anatomy & Image Lifecycle
    • FROM — base image selection (alpine vs slim vs distroless)
    • WORKDIR — setting the working directory
    • COPY vs ADD — when to use each (hint: prefer COPY)
    • RUN — build-time commands, layer caching strategies
    • CMD vs ENTRYPOINT — the "default command" vs "the executable"
    • ENV vs ARG — build-time vs run-time variables
    • EXPOSE — documentation, not enforcement
    • .dockerignore — speeding up builds, excluding secrets
    • docker build → tag → push → pull → run lifecycle
    • Multi-stage builds — separate build deps from runtime
    🟢 Novice | 🟡 Intermediate: BuildKit features, --mount=type=cache

F.4 The anihpj/jobpost Application Stack — Containerized
    • Web tier (Django templates + static files) — anihpj-web (nginx + static)
    • API tier (Django REST Framework) — anihpj-api (gunicorn + Django)
    • Database tier (PostgreSQL 15) — anihpj-db
    • Redis (Celery task queue + caching) — anihpj-redis
    • How these tiers talk to each other (Docker network DNS)

    🐳 DOCKERFILE (see Appendix I for full annotated version):
    # Stage 1: Builder — compile dependencies
    FROM python:3.12-slim@sha256:abc... AS builder
    WORKDIR /app
    COPY requirements.txt .
    RUN pip install --no-cache-dir --user -r requirements.txt

    # Stage 2: Runtime — minimal production image
    FROM gcr.io/distroless/python3-debian12:nonroot
    COPY --from=builder /root/.local /home/nonroot/.local
    COPY --from=builder /app /app
    WORKDIR /app
    USER 1000:1000
    ENV PATH="/home/nonroot/.local/bin:$PATH"
    CMD ["gunicorn", "anihpj.wsgi:application", "--bind", "0.0.0.0:8000"]
    🐳 End of Dockerfile

      operating registries like Mirantis Secure Registry (MSR, formerly DTR)

    • Logging & Metrics: Configuring logging drivers (json-file, journald,

      Mirantis Kubernetes Engine (MKE, formerly UCP)

    • Network Drivers: Configuring and choosing between bridge, overlay,
      host, macvlan, and none structures
    • Port Mapping: Publishing internal container ports to the external host
      infrastructure

      understanding service discovery mechanisms

    • Content Trust: Configuring Docker Content Trust (DCT) to enforce
      image verification and signature validation
    • Secrets & Configs: Securely mounting passwords, API keys, and
      sensitive environment data inside Swarm services
    • Isolation: Restricting system privileges using Linux namespaces,
      cgroups, and user namespace remapping

    • Data Persistence: Configuring anonymous volumes, named volumes, and
      local bind mounts
    • Storage Drivers: Managing volume data layers and understanding driver
      choices like overlay2
    • Clean-up: Executing routine maintenance to prune unused block layers
      and dangling storage volumes
