    EX267 EXAM STRATEGY — TOP 10 MISTAKES TO AVOID
    ───────────────────────────────────────────────
    ┌──────────────────────────────────────────────────────────────────────┐
    │  ❌ COMMON MISTAKES                    ✅ WHAT TO DO INSTEAD          │
    │                                                                       │
    │  1. Not knowing oc commands           Practice oc CLI daily — it's   │
    │     (only knowing kubectl)            kubectl + OpenShift additions  │
    │                                                                       │
    │  2. Skipping OpenShift Console UI     Learn both CLI AND web console │
    │     (EX267 tests both!)               — some tasks are UI-only       │
    │                                                                       │
    │  3. Not setting up GPU node labels    Always label GPU nodes before  │
    │     before deploying workloads        scheduling AI workloads        │
    │                                                                       │
    │  4. Forgetting to configure PVCs      Data science needs persistent  │
    │     for notebook workspaces           storage — check PVC first      │
    │                                                                       │
    │  5. Ignoring SecurityContext for AI   AI pods often need privileged  │
    │     workloads (GPUs need special)     access — know when & why       │
    │                                                                       │
    │  6. Not verifying model serving       Always curl the endpoint after │
    │     endpoint after deployment         deploying inference service    │
    │                                                                       │
    │  7. Miscounting resources in quotas   AI workloads are resource-heavy│
    │     (GPU requests vs limits)          — verify quotas carefully      │
    │                                                                       │
    │  8. Forgetting data connection YAML   Triple-check S3/storage conn-  │
    │     syntax for pipelines              ection secrets and configs     │
    │                                                                       │
    │  9. Not using oc explain for CRDs     OpenShift AI uses many custom  │
    │     (Custom Resource Definitions)      resources — oc explain is key │
    │                                                                       │
    │  10. Skipping pipeline validation     Always run a test pipeline     │
    │     before declaring job complete     before marking task done       │
    └──────────────────────────────────────────────────────────────────────┘

    EXAM DAY TERMINAL SETUP — YOUR oc/kubectl ALIASES
    ──────────────────────────────────────────────────
    ┌──────────────────────────────────────────────────────────────────────┐
    │  Run these FIRST when your EX267 exam terminal opens:                │
    │                                                                       │
    │  alias oc='oc'                         # OpenShift CLI               │
    │  alias k='kubectl'                     # Shorthand                    │
    │  alias ogp='oc get pods'               # Get pods                    │
    │  alias ogd='oc get deployment'         # Get deployments             │
    │  alias ogs='oc get svc'                # Get services                │
    │  alias ogr='oc get routes'             # Get routes (OpenShift)      │
    │  alias odn='oc describe node'          # Describe node               │
    │  alias oaf='oc apply -f'               # Apply YAML                  │
    │  alias ogn='oc get nodes'              # Get nodes                   │
    │  alias olog='oc logs'                  # Get logs                    │
    │  export do="--dry-run=client -o yaml"  # YAML preview                │
    │                                                                       │
    │  Quick project switch:                                               │
    │  oc project <name>                     # Switch OpenShift project    │
    │                                                                       │
    │  Quick YAML generation:                                              │
    │  oc new-app --name=anihpj --image=registry/anihpj:latest $do        │
    │  oc create route edge --service=anihpj --hostname=anihpj.apps.com   │

B.2  STEP-BY-STEP OPERATOR INSTALLATION (Console + CLI)
─────────────────────────────────────────────────────────
    Via WEB CONSOLE:
        1. Administrator view → Operators → OperatorHub
        2. Search: "Red Hat OpenShift AI" (or "OpenShift Data Science")
        3. Click Install → Choose "redhat-ods-operator" namespace
        4. Update channel: "stable" (or "fast" for preview features)
        5. Approval strategy: "Manual" (production) or "Automatic" (dev)
        6. Click Install → Wait for CSV to show "Succeeded"

    Via CLI:
        # Create namespace
        oc create namespace redhat-ods-operator

        # Create OperatorGroup
        cat <<EOF | oc apply -f -
        apiVersion: operators.coreos.com/v1
        kind: OperatorGroup
        metadata:
          name: redhat-ods-operator
          namespace: redhat-ods-operator
        spec:
          targetNamespaces: []
        EOF

        # Create Subscription
        cat <<EOF | oc apply -f -
        apiVersion: operators.coreos.com/v1alpha1
        kind: Subscription
        metadata:
          name: rhods-operator
          namespace: redhat-ods-operator
        spec:
          channel: stable
          name: rhods-operator
          source: redhat-operators
          sourceNamespace: openshift-marketplace
          installPlanApproval: Manual
        EOF

        # Approve install plan
        oc get installplan -n redhat-ods-operator
        oc patch installplan install-xxxxx -n redhat-ods-operator \
          --type merge -p '{"spec":{"approved":true}}'

    # deployment.yaml
    apiVersion: apps/v1

    spec:
      replicas: 3

        matchLabels: { app: anihpj }

        spec:
          containers:

              initialDelaySeconds: 15, periodSeconds: 10

              httpGet: { path: /ready, port: 8080 }
              initialDelaySeconds: 5, periodSeconds: 5
    ---
    # service.yaml
    apiVersion: v1
    kind: Service
    metadata:
      name: anihpj
      labels: { app: anihpj }
    spec:
      selector: { app: anihpj }
      ports:
      - port: 8080, targetPort: 8080, name: http

    apiVersion: route.openshift.io/v1

      name: anihpj

E.2  PREPROCESSING COMPONENT (Skill Extraction)
─────────────────────────────────────────────────
    @dsl.component(
        base_image="registry.access.redhat.com/ubi9/python-311",
        packages_to_install=["pandas", "scikit-learn", "nltk"]
    )
    def preprocess_features(
        input_data: dsl.Input[dsl.Dataset],
        preprocessed_data: dsl.Output[dsl.Dataset]
    ):
        import pandas as pd, re, nltk
        nltk.download("stopwords")
        from sklearn.feature_extraction.text import TfidfVectorizer

        df = pd.read_csv(input_data.path)
        # Extract skills from description
        skills = ["python", "java", "docker", "kubernetes", "aws", "azure"]
        for skill in skills:
            df[f"skill_{skill}"] = df["description"].str.contains(skill, case=False).astype(int)
        df["text_length"] = df["description"].str.len()
        df.to_csv(preprocessed_data.path, index=False)
        print(f"Preprocessed: {df.shape[1]} features created")

E.3  TRAINING COMPONENT (Scikit-learn + PyTorch)
───────────────────────────────────────────────────
    @dsl.component(
        base_image="registry.access.redhat.com/ubi9/python-311",
        packages_to_install=["pandas", "scikit-learn", "joblib", "xgboost"]
    )
    def train_model(
        preprocessed_data: dsl.Input[dsl.Dataset],
        model_output: dsl.Output[dsl.Model],
        metrics_output: dsl.Output[dsl.Metrics]
    ):
        import pandas as pd, joblib
        from sklearn.model_selection import train_test_split
        from xgboost import XGBClassifier
        from sklearn.metrics import accuracy_score, f1_score

        df = pd.read_csv(preprocessed_data.path)
        X = df.drop(columns=["title", "description", "category"])
        y = df["category"]
        X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2)

        model = XGBClassifier(n_estimators=100, max_depth=6, learning_rate=0.1)
        model.fit(X_train, y_train)
        y_pred = model.predict(X_test)

        joblib.dump(model, model_output.path)
        metrics_output.metadata["accuracy"] = accuracy_score(y_test, y_pred)
        metrics_output.metadata["f1_score"] = f1_score(y_test, y_pred, average="weighted")

    @dsl.component(

E.5  MODEL EXPORT COMPONENT
──────────────────────────────
    @dsl.component(
        base_image="registry.access.redhat.com/ubi9/python-311",
        packages_to_install=["boto3", "joblib"]
    )
    def export_model(
        model_input: dsl.Input[dsl.Model],
        s3_bucket: str,
        model_name: str,
        version: str
    ):
        import boto3, joblib, json
        from datetime import datetime

        s3 = boto3.client("s3")
        key = f"{model_name}/v{version}/model.joblib"
        s3.upload_file(model_input.path, s3_bucket, key)

        # Write metadata
        metadata = {
            "model": model_name, "version": version,
            "exported_at": datetime.now().isoformat(),
            "s3_uri": f"s3://{s3_bucket}/{key}"
        }
        s3.put_object(Bucket=s3_bucket, Key=f"{model_name}/v{version}/metadata.json",
                      Body=json.dumps(metadata))
        print(f"Model exported: s3://{s3_bucket}/{key}")

G.2  GPU TAINTS & TOLERATIONS PATTERNS
─────────────────────────────────────────
    # TAINT: Prevent non-GPU workloads from using expensive GPU nodes
    oc adm taint node gpu-worker-1 nvidia.com/gpu=true:NoSchedule
    oc adm taint node gpu-worker-2 nvidia.com/gpu=true:NoSchedule

    # TOLERATION: Allow only AI workloads to run on GPU nodes
    # Add to your pod/deployment spec:
    tolerations:
    - key: nvidia.com/gpu
      operator: Equal
      value: "true"
      effect: NoSchedule

    # NODESELECTOR: Pin GPU workloads to GPU nodes
    nodeSelector:
      nvidia.com/gpu.present: "true"

    # COMBINED: Node affinity + toleration for production AI workloads
    affinity:
      nodeAffinity:
        requiredDuringSchedulingIgnoredDuringExecution:
          nodeSelectorTerms:
          - matchExpressions:
            - key: nvidia.com/gpu.product
              operator: In
              values: ["A100-SXM4-40GB", "H100-PCIe-80GB"]

APPENDIX J: Troubleshooting Flowcharts — 10 Common EX267 Scenarios
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

J.1  NOTEBOOK WON'T START — DECISION TREE
───────────────────────────────────────────
    Notebook pod status?
    ├── ImagePullBackOff → Wrong image name? Private registry without pull secret?
    │   Fix: oc describe pod → check image; oc create secret docker-registry
    ├── Pending (0/1 nodes) → No resources?
    │   ├── No GPU available? → Check node labels: oc describe node | grep nvidia
    │   ├── Quota exceeded? → oc describe quota
    │   └── PVC not bound? → oc get pvc → check StorageClass default
    ├── CrashLoopBackOff → OOMKilled?
    │   Fix: Increase memory in Notebook CR → oc edit notebook <name>
    └── Running but UI unreachable? → Route issue?
        Fix: oc get route -n <project> → check hostname

J.2  PIPELINE STEP FAILURE — DECISION TREE
────────────────────────────────────────────
    Step pod status?
    ├── OOMKilled → oc describe pod → increase step memory in pipeline
    ├── Error (exit code 1) → oc logs <step-pod>
    │   ├── ImportError → Python dependency missing → add to requirements.txt
    │   ├── PermissionError → S3 access denied → check Data Connection secret
    │   └── KeyError → Wrong column name → data schema changed
    ├── Timeout → Increase timeout in pipeline step config
    └── Evicted → Node disk pressure → check node storage: oc adm top node

J.3  MODEL SERVING TIMEOUT — DECISION TREE
────────────────────────────────────────────
    curl the endpoint → what happens?
    ├── 503 Service Unavailable → Cold start?
    │   Fix: Wait 30-60s. OR set minReplicas=1 to prevent scale-to-zero
    ├── Connection Refused → Pod not running?
    │   Check: oc get is → conditions → StorageNotAccessible? PredictorPending?
    ├── 504 Gateway Timeout → Model loading too slow?
    │   Fix: Increase memory, check model size, pre-warm by sending test request
    └── 200 but high latency → Performance issue?
        Fix: Check GPU utilization (DCGM), add HPA replicas, upgrade GPU

J.4  GPU NOT DETECTED — DECISION TREE
───────────────────────────────────────
    oc describe node <gpu-node> | grep nvidia → labels present?
    ├── No labels → NFD not detecting GPU?
    │   Check: oc get pods -n node-feature-discovery
    │   Fix: Reinstall NFD Operator
    ├── Labels present but pods pending → GPU Operator?
    │   Check: oc get pods -n nvidia-gpu-operator → all Running?
    │   Check: oc get clusterpolicy → created?
    └── Labels + Operator OK → Pod can't use GPU?
        ├── SCC issue? → oc adm policy add-scc-to-user privileged -z default
        ├── Quota? → oc describe quota
        └── Taint not tolerated? → Add toleration to pod spec

J.5  PVC MOUNT FAILURE — DECISION TREE
────────────────────────────────────────
    PVC status?
    ├── Pending → No default StorageClass? → oc patch sc <name> -p '{"metadata":{"annotations":{"storageclass.kubernetes.io/is-default-class":"true"}}}'
    ├── Bound but mount fails → Access mode mismatch?
    │   ReadWriteOnce can only mount to 1 pod → use ReadWriteMany (RWX) for shared
    └── Lost → PV deleted? → CSI snapshot restore if available

J.6  OPERATOR INSTALL FAILURE — DECISION TREE
───────────────────────────────────────────────
    oc get csv -n redhat-ods-operator → status?
    ├── Pending → InstallPlan not approved → oc get installplan → approve it
    ├── Failed → Dependency missing?
    │   Check: oc get csv -A → all dependency operators Succeeded?
    │   Common: Serverless Operator, Pipelines Operator, ServiceMesh
    └── Succeeded but pods crashing → Insufficient resources
        Fix: Add worker nodes or increase existing node resources

J.7  ROUTE NOT ACCESSIBLE — DECISION TREE
───────────────────────────────────────────
    curl the route → what happens?
    ├── DNS not resolving → Hostname not propagated?
    │   Wait 5 min OR check DNS with nslookup
    ├── Connection Refused → Service selector wrong?
    │   oc describe svc <name> → verify selector matches pod labels
    └── TLS cert error → Self-signed?
        Fix: oc create route edge --service=<name> --hostname=<fqdn>

J.8  AUTHENTICATION FAILURE — DECISION TREE
─────────────────────────────────────────────
    oc login fails?
    ├── "unauthorized" → Wrong credentials or expired token
    │   oc login --token=<new-token> --server=<api-url>
    ├── "certificate signed by unknown authority" → Self-signed cluster
    │   oc login --insecure-skip-tls-verify=true (dev only!)
    └── OAuth pod not running → oc get pods -n openshift-authentication

J.9  RESOURCE QUOTA EXCEEDED — DECISION TREE
──────────────────────────────────────────────
    oc describe quota → which resource is exhausted?
    ├── CPU → Reduce CPU requests or increase quota
    │   oc patch resourcequota <name> -p '{"spec":{"hard":{"cpu":"10"}}}'
    ├── Memory → Same as CPU
    ├── GPU (nvidia.com/gpu) → Free GPU by stopping unused notebooks
    │   OR enable MIG/time-slicing to share GPUs
    └── PVC count/storage → Delete unused PVCs or increase quota

J.10 OOM KILL (Out of Memory) — DECISION TREE
───────────────────────────────────────────────
    oc describe pod → State: OOMKilled
    ├── Training job? → Reduce batch size OR increase node memory
    ├── Inference? → Model too large → use smaller model OR add GPU memory
    ├── Data processing? → Process in chunks (Dask/Spark) instead of full dataset
    └── Memory leak? → Check pod memory trend: oc adm top pod --containers
