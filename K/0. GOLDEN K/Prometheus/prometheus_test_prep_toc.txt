PRE-LEARNING: PROMETHEUS & OBSERVABILITY FOUNDATIONS (Novice Foundation)
═══════════════════════════════════════════════════════════════════════
Before diving into the exam domains, this section builds your mental model
of what Prometheus IS, what observability means, and how everything fits together.
Essential for novices; useful refresher for experienced engineers.

P.1 What Problem Does Prometheus Solve?
    • The "My App Is Down and I Didn't Know" Problem
    • From SSH-and-check → Nagios/Zabbix → Prometheus (pull-based revolution)
    • Monitoring vs Observability — knowing WHEN vs knowing WHY
    • Blackbox monitoring vs Whitebox monitoring
    • Why monitoring anihpj/jobpost matters — users, jobs, applications, DB health
    • The RED Method (Rate, Errors, Duration) and USE Method (Utilization, Saturation, Errors)
    🟢 Novice

P.2 The Three Pillars of Observability
    • Metrics — numeric measurements over time (Prometheus's domain)
    • Logs — timestamped event records (Loki, Elasticsearch)
    • Traces — request journeys across services (Tempo, Jaeger)
    • How they complement each other — metrics tell you WHAT, logs tell you WHY, traces tell you WHERE
    • The anihpj/jobpost observability stack: Prometheus + Loki + Tempo + Grafana
    🟢 Novice | 🟡 Intermediate: Correlating metrics, logs, and traces

P.3 Prometheus Core Concepts — The "Big Picture" Mental Model
    • Pull model vs Push model — Prometheus SCRAPES targets, targets don't push
    • Time Series = metric name + labels (key-value pairs)
    • The TSDB (Time Series Database) — how Prometheus stores data
    • PromQL — the query language (like SQL but for metrics)
    • Architecture diagram: Scrape → TSDB → HTTP API → Grafana/Alertmanager
    • Push vs Pull — when to use Pushgateway (batch jobs, short-lived processes)
    🟢 Novice | 🟡 Intermediate: WAL, compaction, retention, chunks

P.4 Metrics & Labels — The Language of Prometheus
    • What IS a metric? (a named measurement over time with labels)
    • Counter (only goes up), Gauge (goes up and down), Histogram (buckets), Summary (quantiles)
    • Labels — the "WHERE" dimension (instance, job, namespace, pod, status_code)
    • Cardinality — why too many unique label combinations explode memory
    • Exposition format — the /metrics page format (HELP, TYPE, metric + labels + value)
    • Best practices: label naming conventions, what NOT to put in labels
    🟢 Novice | 🟡 Intermediate: Histogram quantile calculation, summary vs histogram tradeoffs

P.5 The anihpj/jobpost Application — What We Monitor
    • Web tier (Django) — HTTP request rate, latency, error rate, active users
    • API tier (DRF) — API endpoint usage, response times, status codes
    • Database tier (PostgreSQL) — connections, query duration, cache hit ratio
    • Redis — memory usage, keyspace, hit/miss ratio, connected clients
    • Infrastructure — CPU, memory, disk, network per node
    • Business metrics — jobs posted, applications submitted, user signups
    • Complete monitoring architecture diagram with all components
    • SLIs, SLOs, SLAs for anihpj — what "good" looks like for the job board
    🟢 Novice | 🔴 Advanced: Custom Django metrics, django-prometheus integration

"This is the heaviest category — and the heart of Prometheus. PromQL is

    Q89:  Label matching — = (equals), != (not equals), =~ (regex match), !~ (not regex)
    Q90:  Multiple selectors — http_requests_total{job="anihpj-api", status=~"5.."}
    Q91:  Offset modifier — what was the value 5 minutes ago? (offset 5m)
    Q92:  @ modifier — query at a specific Unix timestamp
    Q93:  __name__ selector — select by metric name pattern ({__name__=~"http_.*"})

    Q95:  The expression browser — testing queries at /graph before building dashboards

    Q101: idelta() — difference between last 2 samples (instant delta)

    Q103: predict_linear() — predict future value based on linear regression (disk full in 4h?)

3.4 Aggregating Over Dimensions (8 Qs)

    Q116: quantile() — aggregate percentile (⚠️ NOT the same as histogram_quantile!)
    Q117: count_values() — frequency histogram of metric values

3.5 Binary Operators (8 Qs)
