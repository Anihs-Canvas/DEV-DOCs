    WHAT IS A CLOUD NATIVE PLATFORM ENGINEER?
    ─────────────────────────────────────────
    ┌──────────────────────────────────────────────────────────────┐
    │                                                              │
    │  A Cloud Native Platform Engineer builds and maintains       │
    │  the INTERNAL DEVELOPER PLATFORM (IDP) that enables          │
    │  developers to deploy, run, and manage applications          │
    │  without needing deep infrastructure knowledge.              │
    │                                                              │
    │  Think of it as:                                             │
    │  ┌─────────────────────────────────────────────────────┐    │
    │  │ 🏗️ Platform Engineer = Building the HOUSE (platform) │    │
    │  │ 🎨 Developer = DECORATING the rooms (apps)           │    │
    │  └─────────────────────────────────────────────────────┘    │
    │                                                              │
    │  You are the bridge between:                                 │
    │    • Infrastructure (servers, networks, storage)             │
    │    • Operations (monitoring, security, compliance)           │
    │    • Development (CI/CD, developer tools, self-service)     │
    └──────────────────────────────────────────────────────────────┘

    CNPE EXAM STRATEGY — TOP 10 MISTAKES TO AVOID
    ─────────────────────────────────────────────
    ┌──────────────────────────────────────────────────────────────┐
    │  ❌ COMMON MISTAKES                 ✅ WHAT TO DO INSTEAD    │
    │                                                              │
    │  1. Over-engineering the platform   Start simple, iterate    │
    │     before proving need             fast. Minimum Viable     │
    │                                     Platform (MVP) first     │
    │                                                              │
    │  2. Not treating platform as a      Apply product management │
    │     PRODUCT — building what devs    principles. Survey devs, │
    │     don't actually need             measure adoption         │
    │                                                              │
    │  3. Manual infrastructure changes   Everything as code —     │
    │     (click-ops, SSH)                Tofu/Terraform, GitOps   │
    │                                                              │
    │  4. Ignoring developer experience   Self-service portal,     │
    │     — forcing complex workflows     Backstage, templates,    │
    │                                     platform APIs (Domain 3) │
    │                                                              │
    │  5. No observability from day one   Prometheus, Grafana,     │
    │     (Domain 4 — 20% of exam!)       Loki, OpenTelemetry      │
    │                                                              │
    │  6. Security as afterthought        Shift-left security:     │
    │     (Domain 5 — 15% of exam!)       scan images, RBAC, PSA,  │
    │                                     Kyverno policies         │
    │                                                              │
    │  7. Single cluster for everything   Multi-tenancy, resource  │
    │     (Domain 1 — Platform Arch 15%)  optimization, right-size │
    │                                                              │
    │  8. Not automating repetitive tasks GitOps workflows, CI/CD  │
    │     (Domain 2 — GitOps & CD 25%)    pipelines, progressive   │
    │                                     delivery (Blue/Green)    │
    │                                                              │
    │  9. Ignoring cost optimization      Kubecost, right-sizing,  │
    │     (Domain 1 — cost management)    spot instances, HPA/VPA  │

    │  10. Building everything from       Leverage CNCF ecosystem: │
    │      scratch instead of using       Argo, Kyverno, Crossplane│

Chapter 1: What is Cloud Native Platform Engineering?
--------------------------------------------------------------------------------
    1.1  The Problem Before Platform Engineering
         - Traditional Ops: "File a ticket, wait 2 weeks for a VM"
         - Developers drowning in infrastructure complexity
         - The "it works on my machine" production gap
         - Real scenario: anihpj team wants to deploy jobpost app —
           needs a database, secrets, ingress, monitoring, backups...
         - The cognitive load problem: devs must know K8s, networking,
           storage, security, CI/CD, monitoring — just to ship code
         [PAIN POINT DIAGRAM: Developer vs Infrastructure complexity]

         [THE COGNITIVE LOAD PROBLEM]
         ┌────────────────────────────────────────────────────────────┐
         │  What a Developer Needs to Know WITHOUT a Platform:        │
         │                                                            │
         │  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐   │
         │  │ K8s  │ │Docker│ │Helm  │ │Terra-│ │Net-  │ │Moni- │   │
         │  │ YAML │ │Image │ │Chart │ │form  │ │work  │ │toring│   │
