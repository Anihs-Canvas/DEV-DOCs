PRE-LEARNING: AI & ACCELERATED COMPUTING FOUNDATIONS (Novice Foundation)
═══════════════════════════════════════════════════════════════════════
Before diving into the exam domains, this section builds your mental model
of what AI infrastructure IS, why GPUs matter, and how everything fits together.
Essential for novices; useful refresher for experienced engineers.

F.1 What Is AI, ML, and Deep Learning? — The Big Picture
    • Artificial Intelligence → Machine Learning → Deep Learning (nested hierarchy)
    • Training vs Inference: "Learning from data" vs "Making predictions"
    • Why now? Big Data + GPU Compute + Better Algorithms = The AI Revolution
    • Real-world analogy: Training = studying for an exam; Inference = taking the exam
    • Key industries transformed by AI: healthcare, automotive, finance, retail, manufacturing

F.2 CPU vs GPU — Why GPUs for AI?
    • CPU: Few powerful cores, sequential processing (the "brain" of a general-purpose computer)
    • GPU: Thousands of simpler cores, massively parallel (the "army of calculators")
    • Why parallel processing matters for AI: matrix multiplications (every neural network is math)
    • Analogy: CPU = a few PhD mathematicians; GPU = 10,000 high school students with calculators
    • GPU architecture basics: CUDA cores, Tensor Cores, RT Cores
    • NVIDIA GPU families: H100, A100, L40S, L4 — what each is designed for
    🟢 Novice | 🟡 Intermediate: GPU microarchitecture (SM, warp scheduler, memory hierarchy)

F.3 The NVIDIA Software Stack — An Overview
    • CUDA: the parallel computing platform and programming model (the foundation)
    • cuDNN: CUDA Deep Neural Network library (optimized primitives for deep learning)
    • TensorRT: high-performance inference optimizer and runtime
    • NCCL: NVIDIA Collective Communications Library (multi-GPU, multi-node communication)
    • NVIDIA Driver → CUDA Toolkit → cuDNN/TensorRT → Framework (PyTorch/TensorFlow)
    • Stack diagram showing how each layer builds on the one below

F.4 AI Development Lifecycle — From Idea to Production
    • Phase 1: Data collection & preparation (ETL, data lakes, feature engineering)
    • Phase 2: Model development (experimentation, Jupyter notebooks, PyTorch/TensorFlow)
    • Phase 3: Training (single GPU → multi-GPU → multi-node distributed training)
    • Phase 4: Evaluation & validation (accuracy, precision, recall, F1 score, benchmark)
    • Phase 5: Deployment/Inference (TensorRT optimization, Triton Inference Server, NIM)
    • Phase 6: Monitoring & retraining (data drift detection, model versioning, MLOps)
    • Diagram: The AI lifecycle loop (like a CI/CD pipeline for models)

F.5 Key NVIDIA Solutions — What's in the Portfolio?
    • DGX Systems: purpose-built AI supercomputers (DGX H100, DGX B200)
    • HGX Platform: GPU baseboard for OEM servers (8-GPU, NVLink connected)
    • NVIDIA Networking: InfiniBand (Quantum), Ethernet (Spectrum-X), NVLink Switch
    • NVIDIA AI Enterprise (NVAIE): software suite for production AI (NIM, Triton, NeMo)
    • Base Command: NVIDIA's AI cluster management and orchestration platform
    • DPU (BlueField): data processing unit for offloading infrastructure tasks
    • Quick-reference table: What each product is, what problem it solves

F.6 Data Center 101 for AI — The Physical Foundation
    • What is a data center? Racks → Servers → GPUs → Networking → Power → Cooling
    • Power: kW per rack, PDU, UPS, power redundancy (N+1, 2N)
    • Cooling: air cooling vs liquid cooling (direct-to-chip, immersion)
    • Why GPUs change everything: an H100 can draw 700W — 8x that's 5.6kW per server!
    • The "GPU data center" is different from a "CPU data center"
