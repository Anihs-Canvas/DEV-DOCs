PRE-LEARNING: GITOPS & ARGOCD FOUNDATIONS (Novice Foundation)
═══════════════════════════════════════════════════════════════════════
Before diving into ArgoCD specifics, this section builds your GitOps
mental model. Essential for novices; useful refresher for everyone.

F.1 What Is GitOps & Why Does It Matter?
    • The "GitOps" definition — Git is the single source of truth for declarative infrastructure
    • Traditional CI/CD (Push) vs GitOps (Pull) — the architectural paradigm shift
    • The 4 GitOps Principles: Declarative, Versioned & Immutable, Pulled Automatically, Continuously Reconciled
    • Real-world: How Intuit, Bloomberg, and Ticketmaster use GitOps at scale
    • The "Single Pane of Glass" — why ArgoCD's web UI is a game-changer
    • Why anihpj/jobpost is your learning vehicle: Django + PostgreSQL + Redis via GitOps
    🟢 Novice

F.2 GitOps vs Traditional CI/CD — The Paradigm Shift
    • Push Model: CI server has cluster credentials → pushes changes → security risk
    • Pull Model: GitOps agent INSIDE cluster → pulls from Git → no external credentials needed
    • Drift Detection: Manual kubectl edit → GitOps auto-reverts (self-healing!)
    • Audit Trail: git log = complete history of every infrastructure change
    • Disaster Recovery: Point ArgoCD at new cluster → everything recreates from Git
    • Rollback: git revert → ArgoCD syncs → instant rollback (no kubectl rollout needed)
    • Why enterprises are moving from Push to Pull for infrastructure
    🟢 Novice

F.3 The Argo Project Ecosystem — Beyond Just ArgoCD
    • ArgoCD — GitOps deployment (pull-based, drift detection, sync)
    • Argo Workflows — Kubernetes-native workflow engine (DAGs, steps, artifacts)
    • Argo Rollouts — Progressive delivery (Blue/Green, Canary, automated analysis)
    • Argo Events — Event-driven automation (sources → triggers → sensors)
    • How the 4 Argo projects work together: Events triggers → Workflows executes → Rollouts deploys → CD syncs
    • The CGOA Exam: tests ALL 4 Argo projects, not just ArgoCD
    🟢 Novice | 🟡 Intermediate: Project internals, CRD architecture across all 4 projects

F.4 ArgoCD Core Concepts — The Building Blocks
    • Application: What to deploy (source repo), Where to deploy (destination cluster), How (sync policy)
    • AppProject: Logical grouping of Applications with RBAC, source/destination restrictions
    • Sync Policy: Manual, Automated (auto-sync + self-heal + prune)
    • Health Checks: Built-in (Deployment, StatefulSet) + Custom (Lua/script checks)
    • Sync Waves & Hooks: PreSync → Sync → PostSync (control deployment ordering)
    🟢 Novice

F.5 The anihpj/jobpost Application — Your Argo Learning Lab
    • Full application architecture: Web tier → API tier → Database + Cache
    • Owner: Anihs-Canvas (GitHub) | Project: anihpj | App: jobpost
    • Django jobpost features: Employers post jobs, applicants apply, admin manages
    • PostgreSQL 15 stores: users, jobs, applications (persistent data)

DOCKERFILE (Multi-Stage Distroless):
─────────────────────────────────────

  # Stage 1: Build dependencies
  FROM python:3.11-slim AS builder
  WORKDIR /app
  COPY requirements.txt .
  RUN pip install --no-cache-dir --user -r requirements.txt

  # Stage 2: Collect static files
  FROM python:3.11-slim AS static-builder
  WORKDIR /app
  COPY --from=builder /root/.local /root/.local
  COPY . .
  ENV PATH=/root/.local/bin:$PATH
  RUN python manage.py collectstatic --noinput

  # Stage 3: Production image (distroless)
  FROM gcr.io/distroless/python3-debian12
  WORKDIR /app
  COPY --from=builder /root/.local /root/.local
  COPY --from=static-builder /app/staticfiles /app/staticfiles
  COPY . .
  ENV PATH=/root/.local/bin:$PATH
  ENV PYTHONUNBUFFERED=1
  EXPOSE 8000
  USER 1000:1000
  CMD ["gunicorn", "anihpj.wsgi:application", "--bind", "0.0.0.0:8000", "--workers", "4"]

LOCAL DEMONSTRATION QUICKSTART:
────────────────────────────────

  # 1. Start local Kubernetes (kind or minikube)
  kind create cluster --name argo-lab

  # 2. Install Argo Workflows
  kubectl create namespace argo
  kubectl apply -n argo -f https://github.com/argoproj/argo-workflows/releases/latest/download/install.yaml

  # 3. Install Argo CD
  kubectl create namespace argocd
  kubectl apply -n argocd -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml

  # 4. Install Argo Rollouts
  kubectl create namespace argo-rollouts
  kubectl apply -n argo-rollouts -f https://github.com/argoproj/argo-rollouts/releases/latest/download/install.yaml

  # 5. Install Argo Events
  kubectl create namespace argo-events
  kubectl apply -n argo-events -f https://raw.githubusercontent.com/argoproj/argo-events/stable/manifests/install.yaml

  # 6. Build and push Docker image locally
  docker build -t jobpost:dev .
  kind load docker-image jobpost:dev --name argo-lab

  # 7. Deploy via Argo CD
  argocd app create jobpost-dev \
    --repo https://github.com/anihpj/jobpost \
    --path k8s/overlays/dev \
    --dest-server https://kubernetes.default.svc \
    --dest-namespace dev \
    --sync-policy automated

  # 8. Submit a CI workflow
  argo submit argo/workflows/ci-pipeline.yaml \
    -p branch=main -p image-tag=dev

  # 9. Watch the pipeline
  argo watch @latest
  kubectl argo rollouts get jobpost-api -n dev -w

  # 10. Access Argo CD Web UI
  kubectl port-forward svc/argocd-server -n argocd 8080:443
