    WHAT IS KCSA? — THE ELEVATOR PITCH
    ─────────────────────────────────────
    The Kubernetes and Cloud Native Security Associate (KCSA) is a pre-professional
    certification from the Linux Foundation and CNCF. It validates your foundational
    knowledge of security in the cloud native ecosystem — from securing Kubernetes
    clusters to understanding threat models, compliance frameworks, and supply chain
    security.

    Think of it like this:
    ┌──────────────────────────────────────────────────────────────┐
    │                                                              │
    │   🔒 YOU (Security Practitioner)    ☸️ KUBERNETES CLUSTER     │
    │                                                              │
    │   Know the 4Cs ──────────────▶   Cloud → Cluster → Container │
    │   (Cloud Native Security)            → Code                  │
    │                                      │                       │
    │   Secure components ──────────▶   API Server, etcd, Kubelet  │
    │   (Cluster Component Security)     Controller, Scheduler     │
    │                                      │                       │
    │   Apply policies ─────────────▶   Pod Security, RBAC,        │
    │   (Security Fundamentals)           NetworkPolicies, Secrets │
    │                                      │                       │
    │   Understand threats ─────────▶   Trust Boundaries, Attack   │
    │   (Threat Model)                     Vectors, Mitigations    │
    │                                      │                       │
    │   Harden platform ────────────▶   Supply Chain, Admission    │
    │   (Platform Security)              Control, Service Mesh     │
    │                                      │                       │
    │   Ensure compliance ──────────▶   NIST, CIS, PCI-DSS,       │
    │   (Compliance Frameworks)          SOC2, ISO 27001          │
    │                                                              │
    └──────────────────────────────────────────────────────────────┘

    KCSA EXAM STRATEGY — TOP 10 MISTAKES TO AVOID
    ─────────────────────────────────────────────
    ┌──────────────────────────────────────────────────────────────┐
    │  ❌ COMMON MISTAKES                 ✅ WHAT TO DO INSTEAD    │
    │                                                              │
    │  1. Mixing up the 4Cs layers       Draw the concentric      │
    │     (which is Cloud vs Cluster?)   circles BEFORE starting   │
    │                                                              │
    │  2. Confusing PSP (deprecated)     Know: PSP → PSA (built-in)│
    │     with PSA and OPA/Kyverno       → OPA/Kyverno (extensible)│
    │                                                              │
    │  3. Not knowing Kubernetes         Memorize: API Server =    │
    │     component responsibilities     443 (authN+authZ), etcd = │
    │     (who does what security-wise)  2379 (encryption),        │
    │                                    Kubelet = 10250 (node mgmt)│
    │                                                              │
    │  4. Forgetting authN vs authZ      AuthN = Who are you?      │
    │     difference                     AuthZ = What can you do? │
    │                                                              │
    │  5. Overlooking Falco as runtime   Falco = runtime detection │
    │     security (not just monitoring) (eBPF/kernel module)      │
    │                                                              │
    │  6. Not understanding STRIDE       S=spoof, T=tamper,        │
    │     threat categories              R=repudiation, I=info,     │
    │                                    D=DoS, E=elevation         │
    │                                                              │
    │  7. Confusing mTLS (service mesh)  mTLS = both sides present │
    │     with TLS (ingress only)        certs. TLS = one side.    │
    │                                                              │
    │  8. Not knowing SLSA levels        L0=none, L1=provenance,   │
    │                                    L2=hosted build,           │
    │                                    L3=hardened, L4=hermetic   │
    │                                                              │
    │  9. Forgetting that etcd stores    etcd = ALL cluster state  │
    │     ALL secrets (encrypt them!)    including Secrets.        │
    │                                    EncryptionConfiguration!  │
    │                                                              │
    │  10. Skipping hands-on security    Hands-on > theory.        │
    │      tool practice                 Run Trivy, Falco,         │
    │                                    kube-bench yourself!      │
    └──────────────────────────────────────────────────────────────┘

Chapter 1: The 4Cs of Cloud Native Security
--------------------------------------------------------------------------------
    1.1  What are the 4Cs? — Cloud, Cluster, Container, Code
         - Each layer builds on the one below (defense in depth)
         - If one layer fails, others still protect your app
         - The shared responsibility model: Provider vs You
         - Think of it as 4 concentric security rings around your app
         - Real example: How the 4Cs protect anihpj/jobpost at every layer
         [DIAGRAM: 4 concentric circles — Cloud→Cluster→Container→Code]

         [THE 4Cs VISUALIZED — concentric defense rings]

         │    🌐 CLOUD (Outer Ring) — Provider secures infra        │
