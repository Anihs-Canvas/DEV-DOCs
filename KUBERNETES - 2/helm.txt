    WHAT IS HELM? — THE ELEVATOR PITCH
    ──────────────────────────────────
    Helm is the package manager for Kubernetes. Just like `apt` installs
    software on Ubuntu or `brew` installs software on macOS, Helm installs
    applications on Kubernetes. It packages all your YAML manifests (Deployments,
    Services, ConfigMaps, Secrets, Ingress, etc.) into a single reusable unit
    called a "Chart."

    Think of it like this:
    ┌──────────────────────────────────────────────────────────────┐
    │                                                              │
    │   📦 HELM CHART                    ☸️ KUBERNETES CLUSTER      │
    │                                                              │
    │   templates/                      ┌─────────────────────┐   │
    │   ├── deployment.yaml  ──────▶    │  Deployment          │   │
    │   ├── service.yaml     ──────▶    │  Service             │   │
    │   ├── ingress.yaml     ──────▶    │  Ingress             │   │
    │   ├── configmap.yaml   ──────▶    │  ConfigMap           │   │
    │   └── hpa.yaml         ──────▶    │  HPA                 │   │
    │                                    └─────────────────────┘   │
    │   values.yaml          ──────▶    Customizable settings      │
    │   Chart.yaml           ──────▶    Chart metadata             │
    │                                                              │
    │   ONE COMMAND deploys EVERYTHING:                            │
    │   $ helm install anihpj ./anihpj-chart                       │
    │                                                              │
    └──────────────────────────────────────────────────────────────┘

    COMMON HELM MISTAKES & HOW TO AVOID THEM
    ──────────────────────────────────────────
    ┌──────────────────────────────────────────────────────────────┐
    │  ❌ COMMON MISTAKE                  ✅ CORRECT APPROACH       │
    │                                                              │
    │  1. Hardcoding values in           Put them in values.yaml   │
    │     templates instead of using     and reference via         │
    │     .Values                        {{ .Values.xxx }}        │
    │                                                              │
    │  2. Committing secrets in          Use .helmignore, external │
    │     values.yaml to Git             secrets (ESO/Vault/SOPS)  │
    │                                                              │
    │  3. Not pinning chart versions     Always specify version:   │
    │     (using "latest" or "*")        --version 1.2.3           │
    │                                                              │
    │  4. Skipping helm lint before      helm lint ./chart in CI   │
    │     packaging — broken charts      before every deployment   │
    │     reach production                                         │
    │                                                              │
    │  5. Not using --dry-run before     helm install --dry-run    │
    │     applying changes                                         │
    │                                                              │
    │  6. Forgetting to update chart     helm dependency update    │
    │     dependencies after changing    after editing Chart.yaml  │
    │     Chart.yaml                                               │
    │                                                              │
    │  7. Using --force on upgrades      Use --atomic for auto-    │
    │     without cleanup strategy       rollback on failure       │
    │                                                              │
    │  8. Not setting resource limits    Always template requests  │
    │     in chart templates             and limits in values.yaml │
    │                                                              │
    │  9. Confusing .Values and          .Values = all values      │
    │     .Release in templates          .Release = runtime info   │
    │                                                              │
    │  10. Not using _helpers.tpl        DRY principle: define     │
    │      for repeated template logic   reusable snippets once    │
    └──────────────────────────────────────────────────────────────┘

    2.2 The 4 Core Helm Concepts
        • Chart: the package containing all Kubernetes manifest templates
        • Repository: where charts are stored and shared (like Docker Hub for charts)
        • Release: a running instance of a chart in a Kubernetes cluster
        • Revision: each install/upgrade/rollback creates a numbered revision

    2.4 Release Management — The Full Lifecycle
        • Installing: helm install myapp ./chart
        • Listing: helm list --all-namespaces
        • Upgrading: helm upgrade myapp ./chart --set image.tag=v2

        • Uninstalling: helm uninstall myapp
        • History: helm history myapp — every release change tracked
    2.5 Release Storage & Secrets

        • helm get values myapp — see the values used
        • helm get hooks myapp — see lifecycle hooks executed
