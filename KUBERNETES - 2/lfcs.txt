    1.1  The Problem That Created Linux
         - 1991: Linus Torvalds, a Finnish student at the University of Helsinki, starts Linux
         - Why: UNIX was expensive and proprietary; students couldn't afford it
         - GNU Project (1984): Richard Stallman creates free software tools — but no kernel
         - Linux kernel fills the gap: GNU tools + Linux kernel = complete, free OS
         - Linux = Linux kernel + GNU tools = a free, open-source UNIX-like OS
         - Today: powers 96% of the world's top 1 million web servers
         - Android phones, AWS EC2, Google Cloud, Azure VMs — all run Linux
         - Your anihpj server runs on Linux — understanding it is non-negotiable
         [TIMELINE DIAGRAM: 1969 UNIX → 1984 GNU → 1991 Linux kernel → 2003 CentOS
          → 2004 Ubuntu → 2014 Kubernetes runs on Linux → Today]

    1.2  Linux vs Windows vs macOS — What Makes Linux Different
         - Open source: anyone can read, modify, distribute the code freely
         - Multi-user: designed from the ground up for many users simultaneously
         - Everything is a file: devices, processes, network sockets = files
         - Case-sensitive: "anihpj" ≠ "Anihpj" ≠ "ANIHPJ" — no exceptions
         - No drive letters: one unified tree starting at "/" (not C:\, D:\)
         - Package managers: install software with one command (apt, yum, dnf)
         - SSH-native: designed for remote administration from Day 1
         - Free: no per-server license — critical for scaling anihpj infrastructure

    1.4  The Linux Kernel — The Heart of the OS  🎯
         - Kernel = the core program that talks directly to hardware
         - It manages: CPU time scheduling, RAM allocation, I/O, filesystem, networking
         - User space vs kernel space — separation for stability and security
         - Kernel ring 0 (most privileged) vs ring 3 (user programs)
         - How to check your kernel version: uname -r
         - uname -a → all info: kernel version, hostname, arch, date
         - Kernel modules: dynamically loadable drivers — no reboot needed
         - lsmod → list loaded modules | modprobe → load | rmmod → unload
         - /proc/version → kernel version as readable file
         - Kernel parameters tunable at runtime with sysctl (without rebooting!)

    1.5  Installing Ubuntu 22.04 — Your Practice Lab
         - Download Ubuntu 22.04 LTS ISO from ubuntu.com/download/server
         - Install VirtualBox (free) or VMware Workstation Player
         - Create a VM: 2 vCPU, 4-8 GB RAM, 50 GB primary disk
         - Add a SECOND 10 GB disk (essential for LVM and partition labs)
         - Choose "Ubuntu Server" (no GUI) — never "Ubuntu Desktop" for exams
         - During partitioning: choose "Use entire disk and set up LVM"
         - Enable OpenSSH server during install → SSH access enabled
         - Also set up Rocky Linux 9 in a second VM for dual-distro practice
         - Take a VM snapshot immediately after install (your clean restore point)

    3.1  The Filesystem Hierarchy Standard (FHS)
         - Linux follows a standard: every directory has a defined purpose
         - Everything starts at "/" (root) — the single root of the entire tree
         - No drive letters (no C:\) — /dev/sda1 is mounted INTO the tree
         - Understanding FHS = knowing WHERE to find (and put) things
         [TREE DIAGRAM: Full filesystem hierarchy from / down]

         [THE LINUX FILESYSTEM TREE — complete map]
         ┌──────────────────────────────────────────────────────────────────┐
         │  /                      ← ROOT (the beginning of everything)    │
         │  ├── bin  → /usr/bin    ← Essential user commands (ls, cp, mv)  │
         │  ├── boot               ← Bootloader, kernel images             │
         │  ├── dev                ← Device files (/dev/sda, /dev/null)    │
         │  ├── etc                ← ALL system configuration files ← KEY  │
         │  │   ├── nginx/         ← Nginx config                          │
         │  │   ├── systemd/       ← Service definitions                   │
         │  │   ├── ssh/           ← SSH daemon config                     │
         │  │   └── passwd, fstab  ← Users, mounts                        │

Chapter 4: Linux Permissions — Understanding Who Can Do What  🎯
--------------------------------------------------------------------------------
    4.1  The Permission Model — Three Levels
         - Every file has an OWNER (user), a GROUP, and OTHER (everyone else)
         - Three permission bits: Read (r), Write (w), Execute (x)
         - The permission string: -rwxr-xr-- (10 characters)
         [DIAGRAM: Breaking down -rwxr-xr-- bit by bit]

         [PERMISSION STRING DECODED]
         ┌──────────────────────────────────────────────────────────────────┐
         │   - r w x   r - x   r - -                                       │
         │   │ │ │ │   │ │ │   │ │ │                                       │
         │   │ └─┴─┘   └─┴─┘   └─┴─┘                                       │
         │   │  OWNER   GROUP   OTHER                                       │
         │   │                                                              │
         │   └─ File type: - = regular, d = dir, l = link                  │
         │                                                                  │
         │  r = Read    (4) → view file contents / list directory          │
         │  w = Write   (2) → modify file / create files in directory      │
         │  x = Execute (1) → run as program / enter directory             │
         │  - = No permission (0)                                           │
         │                                                                  │
         │  EXAMPLE: -rwxr-xr--                                            │
         │    Owner  (rwx) = 7  → can read, write, execute                 │
         │    Group  (r-x) = 5  → can read and execute                     │
         │    Other  (r--) = 4  → can only read                            │
         │    Written as octal: 754                                         │
         └──────────────────────────────────────────────────────────────────┘

    4.2  chmod — Changing Permissions  🎯
         - Symbolic mode: chmod u+x file  (add execute for user)
         - Octal mode:    chmod 755 file  (owner=rwx, group=rx, other=rx)
         - Recursive:     chmod -R 644 /var/www/anihpj/
         - Common patterns: 644 (files), 755 (dirs/scripts), 600 (private keys)
         [REFERENCE TABLE: chmod common permission patterns with use cases]

         [CHMOD QUICK REFERENCE — most used permission sets]
         ┌──────────────────────────────────────────────────────────────────┐

         │  -rw-------  │  600  │ Private SSH key (~/.ssh/id_rsa)           │

    4.3  chown & chgrp — Changing Ownership  🎯
         - chown user:group file         → change both owner and group
         - chown owner file              → change only the owner
         - chgrp group file              → change only the group
         - chown -R anihpj:www-data /var/www/anihpj/  → recursive ownership change
         - chown --reference=reffile file  → copy ownership from another file
         - Only root can change the owner; a user can change group to a group they belong to
         [SCENARIO: Setting correct ownership for the anihpj web app]

         [CHOWN SCENARIO — setting up anihpj correctly]
         ┌──────────────────────────────────────────────────────────────────┐
         │  # anihpj app structure — who owns what and why                  │
         │                                                                  │
         │  # Static files need to be readable by nginx (www-data group)   │

    4.4  Special Permission Bits — SUID, SGID, Sticky Bit  🎯
         - SUID (4xxx): run file AS its owner regardless of who calls it
           → /usr/bin/passwd is SUID root — anyone can change their password
           → ls shows 's' in owner execute position: -rwsr-xr-x
         - SGID (2xxx): run as group / new files inherit parent dir's group
           → Shared team directories: new files auto-get the team's group
           → ls shows 's' in group execute position: -rwxr-sr-x
         - Sticky bit (1xxx): only the file OWNER can delete it from the directory
           → /tmp has sticky bit: everyone writes there but only YOU delete your files
           → ls shows 't' in other execute position: drwxrwxrwt
         [REAL EXAMPLES: ls -la /usr/bin/passwd showing the 's' bit]

         [SPECIAL BITS IN PRACTICE]
         ┌──────────────────────────────────────────────────────────────────┐
         │  $ ls -la /usr/bin/passwd                                        │
         │  -rwsr-xr-x 1 root root 68208 Jan 1 /usr/bin/passwd             │
         │       ^──── 's' here = SUID set (runs as root no matter who calls)│
         │                                                                  │
         │  $ ls -la /tmp                                                   │
         │  drwxrwxrwt 12 root root 4096 May 24 /tmp                       │
         │            ^── 't' here = Sticky Bit (you can't delete others' files)│
         │                                                                  │
         │  Set SUID:   chmod u+s file  OR  chmod 4755 file               │
         │  Set SGID:   chmod g+s dir   OR  chmod 2755 dir                │
         │  Set Sticky: chmod +t dir    OR  chmod 1777 /tmp               │
         │                                                                  │
         │  Find SUID files (security audit): find / -perm -4000 -type f  │
         └──────────────────────────────────────────────────────────────────┘

    4.5  umask — Default Permission Mask  🎯
         - umask defines what permissions are SUBTRACTED when creating new files
         - Default umask 022 → new files get 644, new directories get 755
         - More restrictive: umask 027 → files get 640, dirs get 750
         - View current: umask (shows 0022)
         - Change temporarily: umask 027
         - Change permanently: add "umask 027" to ~/.bashrc or /etc/profile
         [DIAGRAM: umask calculation — 666 (file max) or 777 (dir max) minus mask]

         [UMASK CALCULATION TABLE]
         ┌──────────────────────────────────────────────────────────────────┐
         │  HOW umask WORKS:                                                │
         │    New file max = 666 (files can never be executable by default) │
         │    New dir  max = 777                                            │
         │                                                                  │
         │  umask = 022:                                                    │
         │    File: 666 - 022 = 644  (-rw-r--r--)                          │
         │    Dir:  777 - 022 = 755  (drwxr-xr-x)                         │
         │                                                                  │
         │  umask = 027:                                                    │
         │    File: 666 - 027 = 640  (-rw-r-----)  ← group can read only   │
         │    Dir:  777 - 027 = 750  (drwxr-x---) ← other has NO access   │
         │                                                                  │
         │  umask = 077 (most restrictive):                                 │
         │    File: 666 - 077 = 600  (-rw-------)  ← owner-only           │
         │    Dir:  777 - 077 = 700  (drwx------)  ← owner-only           │
         │                                                                  │
         │  For anihpj service user: set umask 027 in the user's profile   │
         └──────────────────────────────────────────────────────────────────┘

    5.4  Links — Hard Links and Symbolic Links  🎯
         - Hard link: another name for the SAME data on disk (same inode)
         - Symbolic link: a shortcut that POINTS to another file (different inode)
         - ln target link_name          → create hard link
         - ln -s target link_name       → create symbolic link (symlink)
         - Symlinks can span filesystems; hard links cannot
         - Deleting original: hard link still works; symlink becomes BROKEN
         - /usr/bin/python → /usr/bin/python3.11  (classic system symlink)
         - Nginx config: /etc/nginx/sites-enabled/ → ../sites-available/ (symlinks)
         [DIAGRAM: inode ← hard link A, hard link B | symlink → original file]

         [HARD LINK vs SYMBOLIC LINK — ILLUSTRATED]
         ┌──────────────────────────────────────────────────────────────────┐
         │                                                                  │
         │  HARD LINK:                                                      │
         │  manage.py  ──┐                                                  │
         │               ├──▶  inode 524308  ──▶  DISK DATA               │
         │  manage_link  ──┘                                                │
         │  (both filenames point to the SAME disk data)                   │
         │  → Delete one: other still works. Data survives.                │
         │  → Cannot cross filesystems. Cannot link to directories.        │
         │                                                                  │
         │  SYMBOLIC LINK:                                                  │
         │  python3  ──▶  inode 99001  ──▶  "points to /usr/bin/python3.11"│

         │                               inode 88400  ──▶  DISK DATA       │
         │  (symlink stores a PATH, not data)                               │

         │           /etc/nginx/sites-enabled/anihpj                       │
         │  (disable site: just remove the symlink, keep the real file)    │

    6.2  Regular Expressions — The Power of Pattern Matching  🎯
         - .         → any single character (except newline)
         - *         → zero or more of the preceding element
         - +         → one or more of preceding (grep -E or egrep)
         - ?         → zero or one of preceding (optional character)
         - ^         → start of line (anchor)
         - $         → end of line (anchor)
         - [abc]     → any single character: a OR b OR c
         - [^abc]    → any character EXCEPT a, b, c
         - [a-z]     → any lowercase letter (range)
         - {3}       → exactly 3 of preceding (grep -E)
         - {2,5}     → between 2 and 5 of preceding
         - \b        → word boundary (grep -E)
         - |         → OR (grep -E): cat|dog matches "cat" or "dog"
         - ()        → group: (ab)+ matches "ab", "abab", etc.
         [REGEX CHEAT CARD with 15 practical examples on /var/log/syslog]

         [REGEX VISUAL CHEAT CARD — with anihpj examples]
         ┌──────────────────────────────────────────────────────────────────┐
         │  PATTERN         │ MATCHES                │ USE CASE            │
         │ ─────────────────────────────────────────────────────────────── │
         │  ^ERROR          │ Lines starting w ERROR │ grep '^ERROR' app.log│
         │  ERROR$          │ Lines ending w ERROR   │ (less common)       │
         │  ERR.*           │ ERR + anything after   │ grep 'ERR.*' app.log │
         │  [0-9]{3}        │ Exactly 3 digits       │ HTTP status codes   │
         │  [0-9]\{1,3\}    │ 1 to 3 digits (BRE)   │ IP address segment  │
         │  ^$              │ Empty lines            │ sed '/^$/d' file    │
         │  ^#              │ Comment lines          │ grep -v '^#' nginx  │
         │  [A-Z][a-z]*     │ Capitalized word       │ Proper nouns        │
         │                                                                  │
         │  IP ADDRESS PATTERN (extended regex):                           │
         │  grep -E '[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}'     │
         │  (extract IPs from nginx access log)                            │
         │                                                                  │
         │  BASIC (BRE) vs EXTENDED (ERE) vs PERL (PRE):                  │
         │  grep 'pattern'     → BRE (basic, \ needed for +?{})           │
         │  grep -E 'pattern'  → ERE (extended, no escaping needed)       │
         │  grep -P 'pattern'  → PRE (Perl, supports \d \w \s lookahead)  │
         └──────────────────────────────────────────────────────────────────┘

    6.3  sed — Stream Editor  🎯
         - sed 's/old/new/' file          → replace first match per line
         - sed 's/old/new/g' file         → replace ALL matches per line
         - sed -i 's/DEBUG/INFO/g' file   → edit file IN PLACE
         - sed -n '5,10p' file            → print only lines 5-10
         - sed '/^#/d' file               → delete comment lines
         - sed 's/localhost/anihpj.com/g' → update domain in config
         [SCENARIO: Bulk-update Django settings.py for production deployment]

    6.4  awk — Column-Based Data Processing  🎯
         - awk '{print $1}' file             → print first column (space-delimited)
         - awk -F: '{print $1}' /etc/passwd  → use : as field separator (usernames)
         - awk '$3 > 1000' /etc/passwd       → filter: only users with UID > 1000
         - awk '{sum += $1} END {print sum}' → sum column 1 across all rows
         - awk '/ERROR/ {print $0}' app.log  → print lines matching pattern
         - awk '{print NR, $0}' file         → add line numbers (NR = Number of Record)
         - awk 'END {print NR}' file         → count total lines (= wc -l)
         - awk '{print $NF}' file            → last column (NF = Number of Fields)
         [TABLE: awk vs grep vs sed — when to use which]

         [awk vs grep vs sed — WHEN TO USE WHICH]
         ┌──────────────────────────────────────────────────────────────────┐
         │  TOOL  │ BEST FOR                          │ EXAMPLE             │
         │ ─────────────────────────────────────────────────────────────── │
         │  grep  │ Finding matching lines            │ grep "ERROR" app.log│
         │  sed   │ Substituting/transforming text    │ sed 's/old/new/g'   │
         │  awk   │ Processing columns & arithmetic   │ awk '{print $3}'    │
         │                                                                  │
         │  DECISION TREE:                                                  │
         │  "I want to FIND lines"          → grep                         │
         │  "I want to REPLACE text"        → sed                          │
         │  "I want to EXTRACT columns"     → awk or cut                   │
         │  "I want to DO MATH on data"     → awk                          │
         │  "I want ALL THREE"              → pipe them: grep|sed|awk      │

         │  ANIHPJ LOG ANALYSIS PIPELINE:                                   │
         │  cat /var/log/nginx/access.log                                   │

    6.5  cut, sort, uniq, tr — The Data Pipeline Toolkit
         - cut -d: -f1 /etc/passwd        → first field, colon-delimited (usernames)
         - cut -d: -f1,3 /etc/passwd      → fields 1 AND 3 (username + UID)
         - sort file                      → alphabetical sort (A-Z)
         - sort -n file                   → numeric sort (1, 2, 10 not 1, 10, 2)
         - sort -rn file                  → reverse numeric (largest first)
         - sort -k2 -n file               → sort by column 2 numerically
         - sort -u file                   → sort + remove duplicates (= sort | uniq)
         - uniq file                      → remove ADJACENT duplicates (sort first!)
         - uniq -c file                   → prefix each line with occurrence count
         - uniq -d file                   → print only DUPLICATE lines
         - tr 'a-z' 'A-Z'                → translate lowercase to uppercase
         - tr -d '\r'                     → remove Windows carriage returns (CRLF fix)
         - tr -s ' '                      → squeeze repeated spaces into one
         [PIPELINE: cat log | grep ERROR | awk '{print $4}' | sort | uniq -c | sort -rn]

    7.2  gzip, bzip2, xz — Compression Tools
         - gzip file           → compress (creates file.gz, removes original)
         - gzip -d file.gz     → decompress (= gunzip file.gz)
         - gzip -k file        → compress and KEEP the original file
         - gzip -9 file        → maximum compression (slower)
         - bzip2 / bunzip2     → better compression ratio, slower than gzip
         - xz / unxz           → best compression ratio, slowest (ideal for backups)
         - zip / unzip         → Windows-compatible, for cross-platform sharing
         - zcat / bzcat / xzcat → read compressed file WITHOUT decompressing

          ┌──────────────────────────────────────────────────────────────────┐
          │  STAT CODE │ STATE       │ MEANING                               │
          │ ─────────────────────────────────────────────────────────────── │
          │     R       │ Running    │ Actively using CPU or ready to run    │

Chapter 31: SELinux & AppArmor — Mandatory Access Control  🎯
--------------------------------------------------------------------------------
    31.1  Discretionary vs Mandatory Access Control
          - DAC (regular Linux permissions): owner decides who accesses
          - MAC (SELinux/AppArmor): the system enforces policy beyond permissions
          - Even root can be restricted by MAC policies
          [ANALOGY: DAC = building keys | MAC = security guard that checks ID even with key]

    31.2  SELinux — Security-Enhanced Linux (RHEL/Rocky)  🎯
          - getenforce            → Enforcing / Permissive / Disabled
          - setenforce 0          → temporary Permissive (for debugging)
          - /etc/selinux/config   → persistent SELinux mode
          - ls -Z file            → show SELinux context (user:role:type:level)
          - ps -Z                 → process contexts
          - restorecon -Rv /var/www/anihpj/ → restore default file contexts
          - semanage fcontext     → manage file context policies
          - audit2allow           → create policy from denial log
          - ausearch -c nginx     → search audit log for nginx denials
          [TROUBLESHOOTING BOX: "SELinux is blocking nginx from reading files"]

    31.3  AppArmor — Application Armor (Ubuntu)  🎯
          - aa-status              → current AppArmor status
          - /etc/apparmor.d/       → profile directory
          - aa-enforce /etc/apparmor.d/usr.sbin.nginx  → enforce profile
          - aa-disable /etc/apparmor.d/...             → disable profile
          - dmesg | grep apparmor  → AppArmor denials in kernel log
          [SCENARIO: AppArmor blocks Gunicorn from writing to /var/log/anihpj/]

Chapter 33: Certificates, Keys & Encryption  🎯
--------------------------------------------------------------------------------
    33.1  Symmetric vs Asymmetric Encryption
          - Symmetric: same key for encrypt+decrypt (AES) — fast, good for bulk data
          - Asymmetric: public key encrypts, private key decrypts (RSA/Ed25519) — slower
          - Hybrid (TLS/HTTPS): asymmetric for key exchange, symmetric for data
          [DIAGRAM: How HTTPS uses both to connect to anihpj.com]

    33.2  OpenSSL — Working with Certificates  🎯
          - Generate private key: openssl genrsa -out anihpj.key 4096
          - Generate self-signed cert: openssl req -x509 -new -key anihpj.key
          - View cert info: openssl x509 -in cert.pem -text -noout
          - Check cert expiry: openssl x509 -enddate -noout -in cert.pem
          - Test TLS connection: openssl s_client -connect anihpj.com:443
          [SCENARIO: Create self-signed cert for internal anihpj dev server]

    33.3  GPG — Encrypting Files and Emails
          - gpg --gen-key             → generate GPG key pair
          - gpg -e -r email file      → encrypt file for recipient
          - gpg -d file.gpg           → decrypt file
          - gpg --sign file           → sign file (verify integrity)
          [USE CASE: Encrypt anihpj database backup before sending offsite]

    33.4  SSH Keys — Deep Dive  🎯
          - Key types: RSA (2048/4096), Ed25519 (recommended), ECDSA
          - ssh-keygen -t ed25519 -b 521 -C "anihpj deploy key"
          - Key permissions: 600 for private key, 644 for public key
          - SSH agent: ssh-agent + ssh-add (avoid typing passphrase repeatedly)
          - Certificate-based SSH: for large teams (ssh-keygen -s CA -I identity)

Appendix G: Linux Terminology Glossary
--------------------------------------------------------------------------------
    [A-Z GLOSSARY of key Linux terms]
    | Term            | Definition                                           |
    | bash            | Bourne Again SHell — default shell on most Linux distros|
    | cgroup          | Control group — limit/isolate process resources       |
    | daemon          | Background service process (e.g. sshd, nginx)         |
    | ext4            | Extended filesystem version 4 — Linux default FS      |
    | FQDN            | Fully Qualified Domain Name (anihpj.com)               |
    | GID             | Group ID — numeric identifier for a group             |
    | inode           | Data structure storing file metadata (not filename)    |
    | kernel          | Core OS component managing hardware                    |
    | LVM             | Logical Volume Manager — flexible disk management      |
    | namespace       | Linux isolation primitive (used by containers)         |
    | NFS             | Network File System — share files over network         |
    | PID             | Process ID — unique number for a running process       |
    | POSIX           | Standard defining Unix-like OS interfaces              |
    | runlevel        | System state (replaced by systemd targets)             |
    | SELinux         | Security-Enhanced Linux — Mandatory Access Control     |
    | socket          | Endpoint for process communication (Unix or network)   |
    | symlink         | Symbolic link — a file pointer to another file         |
    | systemd         | Init system and service manager (PID 1)               |
    | TCP             | Transmission Control Protocol — reliable transport     |
    | UID             | User ID — numeric identifier for a user               |
    | umask           | Default permission mask for new files                  |
    | UEFI            | Modern firmware replacing BIOS                        |
    | VFS             | Virtual File System — abstraction layer in kernel      |
    | zombie          | Process that finished but parent hasn't reaped         |
