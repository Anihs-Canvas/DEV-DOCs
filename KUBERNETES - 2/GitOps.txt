    WHAT IS GITOPS? — THE ELEVATOR PITCH
    ─────────────────────────────────────
    GitOps is a way of managing your applications and infrastructure
    where Git is the SINGLE SOURCE OF TRUTH. Instead of manually
    running kubectl commands or clicking buttons, you describe what
    you want in Git. A GitOps agent (like ArgoCD or FluxCD) then
    automatically makes your cluster match what's in Git.

    Think of it like this:
    ┌──────────────────────────────────────────────────────────────┐
    │                                                              │
    │   📝 YOU (Developer)          🤖 GITOPS AGENT                │
    │                                                              │
    │   git push ───────────────▶   Detects change                │
    │   (change YAML in Git)         │                             │
    │                                ▼                             │
    │                              Compares Git vs Cluster         │
    │                                │                             │
    │                                ▼                             │
    │                              Updates Cluster to match Git    │
    │                                                              │
    │   YOU NEVER touch kubectl for deployments!                  │
    │   Git is ALWAYS the single source of truth.                  │
    │                                                              │
    └──────────────────────────────────────────────────────────────┘

    TRADITIONAL CI/CD vs GITOPS — THE KEY DIFFERENCE
    ─────────────────────────────────────────────────
    ┌──────────────────────────────────────────────────────────────┐
    │                                                              │
    │  ❌ TRADITIONAL CI/CD (PUSH-BASED)                           │
    │  ┌──────────┐    ┌──────────┐    ┌──────────┐               │
    │  │ CI Build  │───▶│ Push to  │───▶│ Deploy   │               │
    │  │ & Test    │    │ Registry │    │ Script   │               │
    │  └──────────┘    └──────────┘    └──────────┘               │
    │       CI/CD pipeline PUSHES code to production               │
    │       Cluster credentials exposed in CI pipeline             │
    │       Manual "kubectl apply" or helm install                │
    │                                                              │
    │  ✅ GITOPS (PULL-BASED)                                      │
    │  ┌──────────┐    ┌──────────┐    ┌──────────┐               │
    │  │ CI Build  │───▶│ Git Repo │◀───│ GitOps   │               │
    │  │ & Test    │    │ (Config) │    │ Agent    │               │
    │  └──────────┘    └──────────┘    └────┬─────┘               │
    │                                       │                      │
    │                                       ▼                      │
    │                                  ┌──────────┐               │
    │                                  │ K8s      │               │
    │                                  │ Cluster  │               │
    │                                  └──────────┘               │
    │       GitOps agent PULLS from Git, applies to cluster        │
    │       No cluster credentials in CI pipeline                  │
    │       Git is always the single source of truth               │
    │                                                              │
    └──────────────────────────────────────────────────────────────┘

    GITOPS CORE PRINCIPLES (THE 4 PILLARS)
    ──────────────────────────────────────
    ┌──────────────────────────────────────────────────────────────┐
    │                                                              │
    │  1️⃣  DECLARATIVE CONFIGURATION                               │
    │     Everything is described as YAML/JSON in Git              │
    │     "I want 3 replicas of anihpj on port 8000"              │
    │                                                              │
    │  2️⃣  VERSIONED & IMMUTABLE                                   │
    │     Every change is a Git commit with full history           │
    │     Rollback = git revert                                    │
    │                                                              │
    │  3️⃣  PULLED AUTOMATICALLY                                    │
    │     GitOps agent INSIDE the cluster pulls from Git           │
    │     No external push needed — cluster is self-healing        │
    │                                                              │
    │  4️⃣  CONTINUOUSLY RECONCILED                                 │
    │     Agent constantly watches for drift                       │
    │     If someone manually changes cluster → agent reverts it   │
    │                                                              │
    └──────────────────────────────────────────────────────────────┘

    1.2  GitOps Defined — The Simple Explanation
         - Official definition: "GitOps is a set of practices for managing
           infrastructure and application configurations using Git as the
           single source of truth."
         - In plain English: Instead of telling Kubernetes what to do,
           you tell Git what you want. A robot (ArgoCD/FluxCD) makes it happen.
         - Key analogy: Thermostat — you set the temperature (Git), 
           thermostat maintains it (GitOps agent)
         [DIAGRAM: Thermostat analogy — Set temp in Git = set desired state]

    1.4  GitOps vs Traditional CI/CD — Detailed Comparison
         [COMPARISON TABLE: Push-based CD vs Pull-based GitOps]
         | Aspect                 | Traditional CI/CD (Push)     | GitOps (Pull)               |
         | Deployment Method      | CI tool PUSHES to cluster    | GitOps agent PULLS from Git |
         | Credentials Location   | Stored in CI pipeline (RISK!)| Inside cluster only (SAFE!) |
         | Rollback Process       | Re-run old pipeline job      | git revert + auto-sync      |
         | Drift Detection        | None (manual check needed)   | Continuous automatic detect |
         | Audit Trail            | CI pipeline logs only        | Full Git commit history     |
         | Self-Healing           | None                         | Auto-revert detected drift  |
         | Disaster Recovery      | Manual restore from backup   | Point Git to new cluster    |
         | Security Posture       | Pipeline = attack vector     | Git + agent = minimal attack|
         | Who Deploys?           | CI bot (push credentials)    | Cluster agent (pull config) |

         [PUSH vs PULL — VISUALIZED WITH ANIHJP EXAMPLE]
         ┌──────────────────────────────────────────────────────────────┐
         │                                                              │
         │  TRADITIONAL PUSH:                                           │
         │  ┌──────────────────────────────────────────────────────┐   │
         │  │ 1. git push anihpj app code                           │   │

    7.2  How ArgoCD Works — The Reconciliation Engine
         - Git repository → Repository Server clone
         - Application Controller reads manifests
         - Compares desired (Git) vs actual (K8s)
         - Syncs if there's a difference
         - Health assessment after sync
         [STEP-BY-STEP FLOW: Reconciliation cycle]

         [RECONCILIATION LOOP — step by step]
         ┌──────────────────────────────────────────────────────────────┐
         │                                                              │
         │  EVERY 3 MINUTES (by default):                               │
         │                                                              │
         │  STEP 1: FETCH                                               │
         │  ┌──────────────────────────────────────────────────────┐   │
         │  │  Repo Server: git pull origin main                   │   │
         │  │  "Has the config repo changed?"                       │   │
         │  │  If NO → skip to end (nothing to do)                 │   │
         │  │  If YES → continue to Step 2                         │   │
         │  └──────────────────────────────────────────────────────┘   │
         │           │                                                   │
         │           ▼                                                   │
         │  STEP 2: RENDER                                               │
         │  ┌──────────────────────────────────────────────────────┐   │
         │  │  Read deployment.yaml (or run Kustomize/Helm)        │   │
         │  │  Generate final manifests:                           │   │
         │  │    apiVersion: apps/v1                               │   │
         │  │    kind: Deployment                                  │   │
         │  │    spec:                                             │   │
         │  │      replicas: 3  ← THIS IS WHAT GIT WANTS          │   │
         │  └──────────────────────────────────────────────────────┘   │
         │           │                                                   │
         │           ▼                                                   │
         │  STEP 3: COMPARE                                              │
         │  ┌──────────────────────────────────────────────────────┐   │
         │  │  kubectl get deployment anihpj -o yaml                │   │
         │  │    spec:                                             │   │
         │  │      replicas: 2  ← THIS IS WHAT CLUSTER HAS         │   │
         │  │                                                      │   │
         │  │  DIFF: Git=3, Cluster=2 → OUT OF SYNC!               │   │
         │  └──────────────────────────────────────────────────────┘   │
         │           │                                                   │
         │           ▼                                                   │
         │  STEP 4: SYNC (if auto-sync enabled)                         │
         │  ┌──────────────────────────────────────────────────────┐   │
         │  │  kubectl apply -f deployment.yaml                    │   │
         │  │  → Cluster now has 3 replicas                        │   │
         │  │  → Status: SYNCED ✅                                  │   │
         │  └──────────────────────────────────────────────────────┘   │
         │           │                                                   │
         │           ▼                                                   │
         │  STEP 5: HEALTH CHECK                                         │
         │  ┌──────────────────────────────────────────────────────┐   │
         │  │  Are pods running? Are they healthy?                  │   │
         │  │  → 3/3 pods running → HEALTHY ✅                      │   │
         │  └──────────────────────────────────────────────────────┘   │
         │                                                              │
         │  Result: App shows: "Synced" + "Healthy" 🟢                  │
         │                                                              │
         └──────────────────────────────────────────────────────────────┘

          - Encrypting secrets in Git repos

          [DIAGRAM: Secret management flow in GitOps]

          [THE GITOPS SECRET PROBLEM — illustrated]
          ┌──────────────────────────────────────────────────────────────┐
          │                                                              │
          │  ❌ THE PROBLEM:                                              │
          │  Git config repo needs secrets (DB password, API keys)       │
          │  But Git stores everything in PLAINTEXT!                      │
          │                                                              │
          │  ┌──────────────────────────────────────────────────────┐   │
          │  │  # secret.yaml — DON'T DO THIS!                       │   │
          │  │  apiVersion: v1                                       │   │
          │  │  kind: Secret                                         │   │
          │  │  metadata:                                            │   │
          │  │    name: db-credentials                               │   │
          │  │  data:                                                │   │
          │  │    password: c3VwZXJzZWNyZXQ=  ← BASE64, NOT ENCRYPT│   │
          │  │                                                       │   │
          │  │  ⚠️ Anyone with repo access can decode!               │   │
          │  │  ⚠️ Appears in git log FOREVER                        │   │
          │  │  ⚠️ Even force-push doesn't remove from history       │   │
          │  └──────────────────────────────────────────────────────┘   │
          │                                                              │
          │  ✅ THE SOLUTIONS (4 approaches):                             │
          │  ┌──────────────────────────────────────────────────────┐   │
          │  │  1. Sealed Secrets  ← Encrypt, commit encrypted blob │   │
          │  │  2. ESO            ← Pull from cloud secret manager  │   │
          │  │  3. SOPS           ← Encrypt with GPG/Age/KMS        │   │
          │  │  4. Vault          ← Centralized secret server       │   │
          │  └──────────────────────────────────────────────────────┘   │
          │                                                              │
          └──────────────────────────────────────────────────────────────┘

          [SEALED SECRETS — how it works]
          ┌──────────────────────────────────────────────────────────────┐
          │                                                              │
          │  1. DEVELOPER (laptop):                                      │
          │  ┌──────────────────────────────────────────────────────┐   │
          │  │  $ kubeseal --scope cluster-wide \                    │   │
          │  │    --from-file=secret.yaml \                          │   │

          │  │                                                       │   │
          │  │  # secret.yaml:  password=supersecret                  │   │
          │  │  # sealed-secret.yaml:  encrypted blob (SAFE for Git) │   │
          │  └──────────────────────────────────────────────────────┘   │
          │           │                                                   │
          │           │ git commit & push (encrypted blob is SAFE)       │
          │           ▼                                                   │
          │  2. GIT REPOSITORY:                                          │
          │  ┌──────────────────────────────────────────────────────┐   │
          │  │  anihpj/sealed-secret.yaml ← SAFE in Git!            │   │

          │  │  3. Creates regular Kubernetes Secret                 │   │
          │  │  4. Pods can now access db-credentials                │   │
          │  │                                                       │   │
          │  │  🔑 Private key NEVER leaves the cluster!             │   │
          │  │  🔒 Nobody outside the cluster can decrypt             │   │
          │  └──────────────────────────────────────────────────────┘   │
          │                                                              │
          └──────────────────────────────────────────────────────────────┘

    20.1 Detailed Comparison
          [COMPARISON TABLE: Comprehensive Flux vs ArgoCD]
          | Aspect               | ArgoCD                      | FluxCD                      |
          | UI                   | Excellent web dashboard     | CLI-focused, basic UI       |
          | Architecture         | Monolithic server           | Micro-controllers           |
          | Dependencies         | Redis, Repo Server          | Each controller standalone  |
          | Multi-tenancy        | Projects with RBAC          | Cross-namespace references  |
          | Helm                 | Native via source           | HelmRelease CRD             |
          | Image Automation     | Separate Image Updater      | Built-in Image Automation   |

         [GITOPS TROUBLESHOOTING — decision tree]
         ┌──────────────────────────────────────────────────────────────┐
         │  APP NOT SYNCING?                                             │
         │  ├── Check ArgoCD UI: What's the error?                      │
         │  │   ├── "Repository not found" → Check repo URL + creds    │
         │  │   ├── "Permission denied" → Check RBAC + namespace       │
         │  │   ├── "Invalid YAML" → Check manifest syntax              │
         │  │   ├── "ImagePullBackOff" → Check registry + image tag    │
         │  │   ├── "CrashLoopBackOff" → Check app logs                 │
         │  │   └── "OutOfSync" but no diff → Check ignoreDifferences  │
         │  │                                                           │
         │  APP SHOWS HEALTHY BUT NOT WORKING?                          │
         │  ├── kubectl port-forward to pod → test directly             │
         │  ├── Check Service selector matches pod labels               │
         │  ├── Check Ingress hostname + path rules                     │
         │  └── Check NetworkPolicy isn't blocking traffic              │
         │                                                              │
         │  RECONCILIATION LOOP STUCK?                                   │
         │  ├── Check argocd-application-controller logs                │
         │  ├── Too many apps? Increase controller replicas             │
         │  ├── Redis cache issue? Restart argocd-redis                 │
         │  └── Git repo unreachable? Check network + credentials       │
