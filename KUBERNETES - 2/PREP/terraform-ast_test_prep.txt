Before diving into the exam domains, this section builds your mental model
of what Infrastructure as Code IS, why Terraform exists, and how everything
fits together. Essential for novices; useful refresher for experienced engineers.

F.1 What Is Infrastructure? — The Physical → Virtual → Code Journey
    • The "Old Way": Rack servers, phone calls to data centers, weeks of waiting
    • The "Cloud Way": AWS EC2 console — click, click, click... now do it 50 times
    • The "IaC Way": Define once, `terraform apply` — repeatable, versioned, auditable
    • The Snowflake Server Problem — why manual config leads to unreproducible environments
    • Infrastructure as Code = treating your servers like software
    • Day 0 (Provision), Day 1 (Configure), Day 2 (Operate) — where Terraform fits
    🟢 Novice

F.2 Cloud Computing 101 — AWS as Our Playground
    • What is "the cloud"? — Someone else's computer, available via API
    • Regions vs Availability Zones — where your stuff physically lives
    • AWS services we'll use for anihpj/jobpost:
      - EC2 (virtual machines) — running Django + Gunicorn
      - VPC (virtual private cloud) — your own isolated network
      - RDS (managed PostgreSQL) — the anihpj database
      - S3 (object storage) — static files, backups, state files
      - IAM (identity & access) — who can do what
      - EKS (managed Kubernetes) — when we go container-native
      - ECR (container registry) — storing Docker images
      - ALB (load balancer) — distributing traffic to anihpj-web
      - Route53 (DNS) — anihpj-jobpost.com → your infrastructure
    • The AWS Free Tier — what you can use without paying
    • AWS CLI vs Console vs Terraform — three ways to do the same thing
    🟢 Novice

F.3 Terraform vs The Competition — Why Terraform?
    • Terraform vs AWS CloudFormation — multi-cloud vs single-cloud
    • Terraform vs Ansible/Chef/Puppet — provisioning vs configuration management
    • Terraform vs Pulumi — HCL vs general-purpose languages
    • Terraform vs ClickOps (AWS Console) — repeatability, versioning, collaboration
    • Terraform vs CDK (Cloud Development Kit) — declarative vs imperative
    • The HashiCorp Stack: Terraform + Vault + Consul + Nomad + Packer + Vagrant
    • When to use Terraform AND Ansible together (provision with TF, configure with Ansible)
    🟢 Novice

F.5 HCL (HashiCorp Configuration Language) — Your First Syntax Lesson
    • HCL is NOT JSON or YAML — it's its own language designed for humans
    • Blocks: resource "type" "name" { ... } — the fundamental building block
    • Arguments: key = value — the simplest form of configuration
    • Expressions: "${var.name}", "${aws_instance.web.id}" — referencing values
    • Types in HCL: string, number, bool, list(...), set(...), map(...), object(...)
    • Your first Terraform file — from zero to an EC2 instance in 10 lines
    • Comments: # single-line, // single-line, /* multi-line */
    • .tf vs .tf.json — both work, .tf is preferred
    🟢 Novice

    │ 🔬 UNDER THE HOOD 8.2: Count vs for_each — When to Use Which    │
    │ (Toggle section — side-by-side comparison for anihpj)           │
    ├─────────────────────────────────────────────────────────────────┤
    │                                                                 │
    │  SCENARIO: Create S3 buckets for dev, staging, prod             │
    │                                                                 │
    │  USING count (ORDERED — index-based):                           │
    │  ┌────────────────────────────────────────────────────────────┐ │
    │  │ variable "environments" {                                  │ │
    │  │   type    = list(string)                                   │ │

    │  │ }                                                          │ │
    │  │                                                            │ │
    │  │ resource "aws_s3_bucket" "env_buckets" {                   │ │
    │  │   count  = length(var.environments)                        │ │
    │  │   bucket = "anihpj-${var.environments[count.index]}"       │ │
    │  │ }                                                          │ │
    │  │                                                            │ │
    │  │ # Addresses: aws_s3_bucket.env_buckets[0] = "anihpj-dev"  │ │
    │  │ #           aws_s3_bucket.env_buckets[1] = "anihpj-staging"│ │
    │  │ #           aws_s3_bucket.env_buckets[2] = "anihpj-prod"   │ │
    │  │                                                            │ │
    │  │ # ⚠️ If you remove "staging" from the middle:              │ │
    │  │ #    [0] stays "dev", [1] becomes "prod"                   │ │
    │  │ #    old [2] "prod" gets DESTROYED                          │ │
    │  │ #    old [1] "staging" gets DESTROYED                       │ │
    │  │ #    → "prod" bucket destroyed and recreated! 💥           │ │
    │  └────────────────────────────────────────────────────────────┘ │
    │                                                                 │
    │  USING for_each (KEYED — no index shifting):                    │
    │  ┌────────────────────────────────────────────────────────────┐ │
    │  │ variable "environments" {                                  │ │
    │  │   type = map(object({                                       │ │
    │  │     region    = string                                     │ │
    │  │     size      = string                                     │ │
    │  │   }))                                                      │ │
    │  │   default = {                                              │ │
    │  │     dev     = { region = "us-east-1", size = "t3.micro" }  │ │
    │  │     staging = { region = "us-east-1", size = "t3.small" }  │ │
    │  │     prod    = { region = "us-west-2", size = "t3.medium" } │ │
    │  │   }                                                        │ │
    │  │ }                                                          │ │
    │  │                                                            │ │
    │  │ resource "aws_instance" "anihpj_api" {                     │ │
    │  │   for_each      = var.environments                         │ │
    │  │   ami           = data.aws_ami.ubuntu.id                   │ │
    │  │   instance_type = each.value.size                          │ │
    │  │   tags = {                                                 │ │
    │  │     Name        = "anihpj-api-${each.key}"                 │ │
    │  │     Environment = each.key                                 │ │
    │  │   }                                                        │ │
    │  │ }                                                          │ │
    │  │                                                            │ │
    │  │ # Addresses:                                               │ │
    │  │ #   aws_instance.anihpj_api["dev"]     → i-aaa             │ │
    │  │ #   aws_instance.anihpj_api["staging"] → i-bbb             │ │
    │  │ #   aws_instance.anihpj_api["prod"]    → i-ccc             │ │
    │  │                                                            │ │
    │  │ # ✅ If you remove "staging" from the map:                 │ │
    │  │ #    "staging" instance gets DESTROYED                      │ │
    │  │ #    "dev" and "prod" remain UNTOUCHED!                     │ │
    │  └────────────────────────────────────────────────────────────┘ │
    │                                                                 │
    │  RULE OF THUMB:                                                 │
    │  • Use count for IDENTICAL copies (e.g., 3 identical web VMs)  │
    │  • Use for_each for UNIQUE resources (e.g., per-environment    │
    │    configs with different properties)                           │
    │  • for_each prevents resource shuffling when items are removed │
    └─────────────────────────────────────────────────────────────────┘
