🚀 Getting Started

Commands for deploying, upgrading, and removing Istio from your Kubernetes cluster. These are the first commands you'll use when setting up a service mesh for the anihpj/jobpost project.

istioctl install

INSTALL Deployment Setup Core

Install Istio on a Kubernetes cluster using an IstioOperator custom resource

The istioctl install command generates an Istio install manifest and applies it to a cluster. It's the primary way to deploy Istio for the anihpj Django project with jobpost application.

For the anihpj project, this command:

  • Deploys istiod (control plane) into istio-system namespace
  • Sets up ingress/egress gateways for jobpost traffic
  • Configures mTLS, telemetry, and sidecar injection
  • Supports profiles: default, demo, minimal, ambient, empty

Syntax

# Basic installation
istioctl install [flags]

# Install with a specific profile
istioctl install --set profile=demo

# Install with custom settings
istioctl install --set components.cni.enabled=true

# Dry-run to preview manifests
istioctl install --dry-run

# Install a specific revision (canary)
istioctl install --set revision=1-23

Parameters

ParameterTypeDescription
--set profilestringInstallation profile: default, demo, minimal, ambient, empty, openshift
--set -sstringArrayOverride IstioOperator values (e.g., --set meshConfig.enableTracing=true)
--revision -rstringTarget control plane revision for canary upgrades
-f, --filenamestringSlicePath to IstioOperator YAML file (can be specified multiple times)
--dry-runboolConsole/log output only — don't apply changes
-y, --skip-confirmationboolSkip confirmation prompt (auto-yes)

--contextstringKubernetes configuration context

Complete Installation Configuration
# istio/anihpj-iop.yaml
apiVersion: install.istio.io/v1alpha1
kind: IstioOperator
metadata:
  name: anihpj-istio
  namespace: istio-system
spec:
  profile: demo
  revision: 1-23
  meshConfig:
    enableTracing: true
    accessLogFile: /dev/stdout
    defaultConfig:
      holdApplicationUntilProxyStarts: true
  components:
    ingressGateways:
    - name: istio-ingressgateway
      enabled: true
      k8s:
        service:
          type: LoadBalancer
          ports:
          - name: http
            port: 80
            targetPort: 8080
          - name: https
            port: 443
            targetPort: 8443
    egressGateways:
    - name: istio-egressgateway
      enabled: true
  values:
    global:
      proxy:
        resources:
          requests:
            cpu: 100m
            memory: 128Mi
          limits:
            cpu: 500m
            memory: 512Mi

istioctl uninstall

REMOVE Cleanup Teardown

Uninstall Istio from a cluster

The istioctl uninstall command removes Istio from a Kubernetes cluster. It cleans up all Istio components including istiod, gateways, and webhooks. Use --purge to remove ALL revisions and shared resources.

For the anihpj project, this command handles:

  • Removing istiod deployments and services
  • Cleaning up ingress/egress gateway resources
  • Deleting mutating webhook configurations
  • Optional: purging all Istio resources across all revisions

Syntax

# Uninstall a specific revision
istioctl uninstall --revision <revision>

# Uninstall using IstioOperator file
istioctl uninstall -f iop.yaml

# Purge ALL Istio resources (all revisions)
istioctl uninstall --purge -y

# Dry-run to preview what will be removed
istioctl uninstall --dry-run --purge

Parameters

ParameterTypeDescription
--purgeboolDelete ALL Istio resources for all versions/revisions
--revision -rstringTarget control plane revision to uninstall
-f, --filenamestringPath to IstioOperator YAML file
--dry-runboolPreview only — don't actually remove
-y, --skip-confirmationboolSkip confirmation prompt
--forceboolProceed even with validation errors
-v, --verboseboolVerbose output
-i, --istioNamespacestringIstio system namespace default: istio-system
-c, --kubeconfigstringKubernetes configuration file

Return Value

Exit CodeDescription
0Uninstallation completed successfully
1Error occurred (resources not found, cluster unreachable)

istioctl upgrade

UPGRADE Maintenance Versioning

Upgrade Istio in-place (alias for install command)

The istioctl upgrade command is an alias for istioctl install. It performs an in-place upgrade of Istio. ⚠️ Not recommended for production — use canary upgrades with --set revision instead.

For the anihpj Django project, upgrade planning is critical for:

  • Zero-downtime canary upgrades of the jobpost mesh using revision-based deployment
  • Safely migrating sidecars from old to new control plane without restarting all pods at once
  • Validating new Istio versions in test namespaces before production rollout
  • Rolling back quickly if the new revision causes issues with jobpost-api traffic
⚠️ ICA Exam Tip: NEVER use istioctl upgrade in production scenarios. Always use canary upgrades: istioctl install --set revision=NEW to install alongside existing, then migrate workloads namespace by namespace.

Syntax

# In-place upgrade (same as install)
istioctl upgrade [flags]

# Canary upgrade (RECOMMENDED for production)
istioctl install --set revision=1-23 -y

Parameters

ParameterTypeDescription
Same parameters as istioctl install — see above section for full parameter list.
