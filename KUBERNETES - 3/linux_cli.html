📂 File System Navigation

Commands for browsing directories, locating files, and understanding the filesystem layout. These are the most-used commands in daily Linux work for the anihpj environment.

ls

LIST Navigation Core LFCS Domain 1

List directory contents — the most frequently used command in any Linux session

The ls command lists files and directories, displaying names, permissions, ownership, sizes, and timestamps. It's the first command every Linux user learns and the one used most often — dozens of times daily in any sysadmin workflow.

For the anihpj/jobpost project, ls is essential for:

  • Checking what's deployed in /lpj/ before running scripts
  • Verifying log files exist in /lpj/jobpost/
  • Inspecting Kubernetes manifests in /lpj/k8s/
  • Checking permissions on SSL certificates in /lpj/k8s/base/
  • Listing Dockerfiles before building images

Syntax

ls [OPTIONS]... [FILE]...

# Common patterns:
ls                    # List current directory
ls -la                # Long format with hidden files
ls -ltr               # Long format, sorted by time, reversed (newest last)
ls -lh                # Human-readable sizes
ls -d */              # List only directories

Parameters

FlagDescription
-a, --allShow all entries including hidden files (starting with .)
-lLong listing format — permissions, owner, size, date, filename
-h, --human-readablePrint sizes in human readable format (1K, 234M, 2G)
-tSort by modification time, newest first
-r, --reverseReverse order while sorting
-R, --recursiveList subdirectories recursively
-SSort by file size, largest first
-i, --inodePrint the index number (inode) of each file
-d, --directoryList directories themselves, not their contents
-1List one file per line
--color[=WHEN]Colorize output: always, never, auto
-F, --classifyAppend indicator: /=dir, *=exec, @=symlink, |=fifo
-ZPrint SELinux security context of each file

Return Value

Exit CodeDescription
0Success — directory contents listed
2Error — file or directory not found, or permission denied

find

SEARCH Navigation File Search Scripting LFCS Domain 1

Search for files and directories in a directory hierarchy — the most powerful filesystem search tool

find recursively searches a directory tree for files matching criteria like name, type, size, modification time, permissions, ownership, and more. It's an SRE's swiss army knife for file discovery, cleanup, and batch operations.

For the anihpj/jobpost project, find is used for:

  • Finding all .py files modified today: find /lpj/apps -name "*.py" -mtime -1
  • Cleaning old log files: find /lpj/k8s/logs -name "*.log" -mtime +30 -delete

  • Finding large files consuming disk: find /lpj -type f -size +100M
  • Batch-executing commands on matched files with -exec

Syntax

find [PATH...] [EXPRESSION]

# Common patterns:
find . -name "*.py"                     # Find by name (case sensitive)
find . -iname "*.log"                   # Find by name (case insensitive)
find . -type f                          # Files only
find . -type d                          # Directories only
find . -type f -size +100M              # Files larger than 100MB
find . -type f -mtime -7               # Modified in last 7 days
find . -type f -mtime +30 -delete       # Older than 30 days → delete
find . -user alice -type f              # Files owned by alice
find . -perm 0777                       # Files with 777 permissions
find . -empty                           # Empty files/directories
find . -name "*.pyc" -exec rm {} \;     # Delete all .pyc files
find . -maxdepth 2 -name "Dockerfile"   # Limit search depth

Parameters

ExpressionDescription
-name PATTERNFile name (case sensitive, supports *, ?, [])
-iname PATTERNFile name (case insensitive)
-type fRegular files only
-type dDirectories only
-type lSymbolic links only
-size +N[c/k/M/G]Size: +100M (over 100MB), -10k (under 10KB), 0 (empty)
-mtime NModified exactly N*24h ago: -7 (last 7d), +30 (older than 30d)
-atime NAccessed N*24h ago
-ctime NMetadata changed N*24h ago
-mmin NModified N minutes ago
-user NAMEOwned by user NAME
-group NAMEOwned by group NAME

-emptyFile or directory is empty
-newer FILEModified more recently than FILE
-maxdepth NDescend at most N levels (must come before other tests)
-mindepth NDescend at least N levels

-deleteDelete matched files (use with extreme caution!)
-print0Null-delimited output (for xargs -0)
-not or !Negate the following expression
-o or -orOR between expressions

Exit CodeDescription
0Success — all paths traversed (may have zero matches)
1Error — some paths could not be traversed (permissions, etc.)

type

type is a shell builtin that reveals how the shell would interpret a given command name — whether it's a builtin, an alias, a function, an external binary, or a keyword. Unlike which, it sees everything the shell sees.

For the anihpj/jobpost project, type is used for:

dirs / pushd / popd

NAVIGATE Shell Builtin Directory Stack LFCS Domain 1

Directory stack management — navigate complex directory structures without losing your place

pushd, popd, and dirs are shell builtins that manage a LIFO stack of directories. pushd pushes the current directory onto the stack and changes to a new one. popd removes the top of the stack and changes back. dirs displays the stack.

For the anihpj/jobpost project, the directory stack is used by:

  • Carol bouncing between /lpj/k8s/, /lpj/jobpost/, and /lpj/k8s/ingress/ during incident response
  • Alice switching between multiple Django app directories while debugging
  • Scripts that need to temporarily change directories and return

Syntax

# dirs — display the directory stack
dirs [-clpv] [+N | -N]

# pushd — push directory onto stack and change to it
pushd [DIRECTORY | +N | -N]

# popd — pop directory off stack and change to it
popd [-n] [+N | -N]

# Common patterns:
pushd /lpj/kubernetes       # Save current dir, cd to /lpj/k8s
pushd /lpj/k8s/logs        # Save /lpj/kubernetes, cd to /lpj/k8s/logs
dirs -v                     # Show numbered stack
popd                        # Pop top, return to /lpj/k8s
popd                        # Pop again, return to original dir
pushd +2                    # Rotate stack: jump to 3rd entry

Parameters

Flag / ArgApplies ToDescription
-cdirsClear the directory stack
-ldirsLong listing — expand ~ to full paths
-pdirsPrint one entry per line
-vdirsPrint with index numbers (best for interactive use)
+Npushd/popdRotate stack: jump to Nth entry (0-indexed from left)
-Npushd/popdRotate stack: jump to Nth entry (0-indexed from right)
-npushd/popdSuppress directory change — manipulate stack without cd
DIRECTORYpushdPush current dir onto stack, then cd to DIRECTORY

Return Value

Exit CodeDescription
0Success — operation completed
1Error — invalid argument, empty stack (popd), or directory not found
