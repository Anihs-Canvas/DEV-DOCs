DECISION TREES (15 Trees: DT1-DT15)
═══════════════════════════════════════════════════════════════════════
Quick diagnostic flowcharts for the 15 most common CKAD issues.
Start at the symptom, answer yes/no questions, arrive at the fix.

  DT1:  Pod Stuck in Pending
        Decision path: Check Events → Node resources? → nodeSelector match? →
        Taints/Tolerations? → PVC binding? → ResourceQuota?

  DT2:  CrashLoopBackOff
        Decision path: Check logs (--previous) → Exit code? → OOMKilled (137)? →
        Config error? → Missing env var? → Probe failure?

  DT3:  ImagePullBackOff
        Decision path: Image name correct? → Tag exists? → Private registry? →
        imagePullSecrets? → Registry auth? → Network to registry?

  DT4:  Service Not Reachable
        Decision path: DNS resolves? → kubectl get endpoints? → Selector match? →
        targetPort correct? → NetworkPolicy blocking? → Pod readiness?

  DT5:  Deployment Rollout Stuck
        Decision path: kubectl rollout status? → Insufficient resources? →
        Failed pods? → Probe failures? → Quota exceeded? → Immutable field changed?

  DT6:  ConfigMap Update Not Reflected
        Decision path: ConfigMap actually updated? → Volume mount or env var? →
        subPath used? → Pod restarted? → Reloader installed? → immutable?

  DT7:  OOMKilled (Exit Code 137)
        Decision path: Memory limit set? → Limit too low? → Memory leak? →
        QoS class? → Node memory pressure? → Increase limit or fix leak?

  DT8:  Readiness Probe Failing
        Decision path: Probe path correct? → Port correct? → Timeout too short? →
        App actually ready? → Dependency available? → Check app logs?

  DT9:  Liveness Probe Killing Healthy Pod
        Decision path: Probe too aggressive? → Startup time long? → Needs startup probe? →
        failureThreshold too low? → periodSeconds too short? → timeoutSeconds?

  DT10: NetworkPolicy Blocking Legitimate Traffic
        Decision path: Default-deny active? → Allow rules exist? → podSelector match? →
        namespaceSelector match? → Port correct? → CNI supports NetworkPolicy?

  DT11: ConfigMap/Secret Missing Key
        Decision path: Key name exact match? → ConfigMap exists? → Correct namespace? →
        optional: true? → Case sensitivity? → Created from correct source?

  DT12: RBAC Permission Denied
        Decision path: ServiceAccount correct? → Role exists? → RoleBinding exists? →
        Correct namespace? → Verb correct? → API group correct? → Test with auth can-i?

  DT13: Ingress Not Routing Correctly
        Decision path: Ingress controller running? → IngressClass set? → Host matches? →
        Path matches? → Backend Service exists? → Backend port correct? → TLS?

  DT14: Pod Can't Access External Service
        Decision path: DNS resolves external host? → Egress NetworkPolicy? → Proxy required? →
        NAT gateway? → Firewall/security group? → Test with busybox debug pod?

  DT15: Multi-Container Pod Communication Failure
        Decision path: Shared localhost? → Port correct? → Container order? →
        initContainer succeeded? → Shared volume permissions? → postStart hook?

BEYOND CKAD: CROSS-CERTIFICATION BRIDGE (CKA + CKS + REAL-WORLD DEVOPS)
═══════════════════════════════════════════════════════════════════════
This document prepares you for CKAD AND lays the foundation for CKA/CKS.
Use this bridge section to identify your next steps after CKAD mastery.

🚀 CKA BRIDGE (Certified Kubernetes Administrator):
   CKAD → CKA Path: CKAD covers ~40% of CKA topics (Deployments, Services,
   ConfigMaps, Secrets, NetworkPolicy). After CKAD, you need to learn:
   • Cluster Architecture & etcd (backup/restore, quorum, defragmentation)
   • kubeadm (init, join, upgrade, reset, cert renewal)
   • Node management (cordon, drain, taints, kubelet config)
   • CNI/CSI/CRI deep dive (network plugins, storage drivers, container runtimes)
   • HA control plane (stacked vs external etcd, load balancers)
   • Cluster troubleshooting methodology (systematic approach)
   📎 See: cka_test_prep.html for the complete CKA preparation system

🚀 CKS BRIDGE (Certified Kubernetes Security Specialist):
   CKAD → CKS Path: CKAD covers ~30% of CKS topics (SecurityContext, RBAC,
   NetworkPolicy, Secrets, Admission Control). After CKAD, you need to learn:
   • Supply chain security (SBOM, image signing, vulnerability scanning, cosign)
   • Runtime security (Falco, seccomp, AppArmor, SELinux, container escape)
   • System hardening (CIS benchmarks, kernel hardening, least-privilege IAM)
   • Cluster hardening (etcd encryption, audit logging, OPA/Gatekeeper, Kyverno)
   • Threat detection & incident response (behavioral analytics, forensics)
   📎 See: cks_test_prep.html for the complete CKS preparation system

🚀 REAL-WORLD DEVOPS/SRE BRIDGE (Beyond Certifications):
   After CKAD (and optionally CKA/CKS), apply your skills in production:
   • GitOps: ArgoCD / Flux CD — continuous delivery with declarative Git
   • Service Mesh: Istio / Linkerd — mTLS, traffic splitting, observability
   • Observability Stack: Prometheus + Grafana + Loki + Tempo (LGTM)
   • Secrets Management: HashiCorp Vault, AWS Secrets Manager, SealedSecrets
   • Policy-as-Code: OPA/Gatekeeper, Kyverno, Checkov, tfsec
   • Progressive Delivery: Argo Rollouts, Flagger (canary, blue/green automated)
   • Developer Portals: Backstage (Spotify) — service catalog for your org
   • FinOps: Kubecost, OpenCost — Kubernetes cost monitoring and optimization
