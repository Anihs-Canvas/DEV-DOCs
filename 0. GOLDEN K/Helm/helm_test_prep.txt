PRE-LEARNING: HELM FOUNDATIONS (Novice Foundation)
═══════════════════════════════════════════════════════════════════════
Before diving into the 200 MCQs, this section builds your mental model
of what Helm IS, why it exists, and how it transforms Kubernetes
application management. Essential for novices; useful refresher for all.

F.1 What Problem Does Helm Solve?
    • The "Wall of YAML" Problem — deploying an app needs 10+ YAML files
    • Copy-paste-modify anti-pattern — why it breaks at scale
    • The DRY (Don't Repeat Yourself) principle applied to Kubernetes manifests
    • Helm = Kubernetes Package Manager (like apt/yum/brew for your OS)
    • Helm 2 vs Helm 3 — why Tiller was removed (security + complexity)
    • Real example: anihpj/jobpost needs 14 YAML files — Helm reduces to 1 command
    🟢 Novice

F.2 Helm Core Concepts — The "Big Picture" Mental Model
    • Chart = Package (analogy: .deb or .rpm file)
    • Repository = Package Registry (analogy: apt repo or Docker Hub)
    • Release = Running Instance of a Chart (analogy: installed package)
    • Revision = Versioned Snapshot of a Release (every upgrade creates one)
    • Values = Configuration Input (analogy: config file passed to installer)
    • Templates = YAML Blueprints with Variables (analogy: Jinja2 for Python, ERB for Ruby)
    • The Helm Architecture Diagram — Client-only (no server-side component!)
    🟢 Novice

    • Web tier: Django templates + nginx static files — anihpj-web
    • API tier: Django REST Framework + gunicorn — anihpj-api
    • Database tier: PostgreSQL 15 StatefulSet — anihpj-db
    • Cache/Queue tier: Redis (Celery broker + cache) — anihpj-redis
    • How these tiers connect: Service DNS (anihpj-db.anihpj.svc.cluster.local)

F.4 Helm vs Raw kubectl vs Kustomize — When To Use What
    • Raw kubectl apply: Simple, but repetitive — good for 1-2 YAML files
    • Kustomize: Template-free overlays, patches, native in kubectl — good for env variants
    • Helm: Full package management, templating, release lifecycle — good for distributing apps
    • Decision matrix: When to choose Helm vs Kustomize vs raw YAML
    • Can you use both? Yes! Helm + Kustomize post-renderer pattern
    • Real example: Converting anihpj k8s/ → anihpj helm/ step by step
    🟢 Novice

F.5 Your 6-Cluster Lab — How Helm Fits In
    • Your clusters: kubeadm (production-like), kind × 3 (multi-cluster), minikube (dev)
    • ksw — switching clusters (always verify context before helm install!)
    • Installing Helm: curl | bash or package manager (apt/brew/choco)
    • helm version — verify installation and Kubernetes connection
    • First command: helm repo add bitnami https://charts.bitnami.com/bitnami
    • First install: helm install my-release bitnami/nginx
    • First uninstall: helm uninstall my-release
    • Safety: Test on kind-cka-lab before kubeadm
    🟢 Novice

CATEGORY 1: TEMPLATE RENDERING & DEBUGGING (20 Scenarios)
───────────────────────────────────────────────────────────────────────  S1-S20
"Template rendering is the #1 Helm failure point. Go templating is
powerful but strict — a single missing {{ end }}, wrong whitespace
control, or nil pointer dereference can break everything."

  S1:  helm install fails — Missing {{ end }} in deployment.yaml
       🖥️ ksw → 2 (kind-cka-lab)
       Bug: {{ if .Values.ingress.enabled }} block never closed with {{ end }}
       Symptom: "parse error: unexpected EOF" at line 42
       Fix: Add {{ end }} after the readinessProbe block
       Tenet: Count if/end pairs — every {{ if }} needs {{ end }}

  S2:  helm template renders empty YAML — Whitespace chomping disaster
       🖥️ ksw → 6 (minikube)
       Bug: {{- -}} used incorrectly, stripping ALL whitespace including YAML structure
       Symptom: Rendered YAML is zero bytes or missing indentation
       Fix: Change {{- -}} to {{ }} on YAML structure lines, keep chomping only on template directives
       Tenet: Whitespace control goes on template directives, NOT on YAML keys

  S3:  nil pointer evaluating interface — Missing nested value check
       🖥️ ksw → 2 (kind-cka-lab)
       Bug: {{ .Values.postgres.auth.password }} referenced but postgres.auth is nil
       Symptom: "nil pointer evaluating interface {}.auth"
       Fix: Add {{ if .Values.postgres.auth }} guard or use {{ .Values.postgres.auth.password | default "" }}
       Tenet: Always guard nested values — Helm doesn't auto-vivify missing keys

  S4:  wrong number of args for include — Missing context argument
       🖥️ ksw → 2 (kind-cka-lab)
       Bug: {{ include "anihpj.labels" }} — missing the dot (.) context argument
       Symptom: "wrong number of args for include: want 2 got 1"
       Fix: Change to {{ include "anihpj.labels" . }}
       Tenet: include ALWAYS needs two arguments — template name AND context (.)

  S5:  function "uppper" not defined — Typo in Sprig function name
       🖥️ ksw → 2 (kind-cka-lab)
       Bug: {{ .Values.name | uppper }} — "upper" misspelled as "uppper"
       Symptom: "function 'uppper' not defined"
       Fix: Change uppper → upper
       Tenet: Sprig function names are case-sensitive — use helm lint to catch typos

  S6:  range over nil — Iterating over undefined list
       🖥️ ksw → 6 (minikube)
       Bug: {{ range .Values.ingress.hosts }} but .Values.ingress is not set
       Symptom: "range can't iterate over nil"
       Fix: Add {{ if .Values.ingress }}{{ range .Values.ingress.hosts }}...{{ end }}{{ end }}
       Tenet: Always check the parent exists before iterating over children

  S7:  template not defined — Named template called before definition
       🖥️ ksw → 2 (kind-cka-lab)
       Bug: {{ include "anihpj.fullname" . }} used in deployment.yaml but _helpers.tpl has typo in define name
       Symptom: "template 'anihpj.fullname' not defined"
       Fix: Match define name exactly — {{ define "anihpj.fullname" }} must match include call
       Tenet: Template names are case-sensitive and must match EXACTLY

  S8:  YAML indent disaster — nindent vs indent confusion
       🖥️ ksw → 6 (minikube)
       Bug: {{ include "anihpj.labels" . | indent 4 }} used instead of nindent
       Symptom: Labels block has no leading newline — YAML parser rejects it
       Fix: Replace indent → nindent (adds newline BEFORE indentation)
       Tenet: indent for in-line; nindent for block-level (newline + indent)

  S9:  toYaml without nindent — Inline YAML with wrong indentation
       🖥️ ksw → 2 (kind-cka-lab)
       Bug: {{ toYaml .Values.resources }} — no indentation, breaks YAML structure
       Symptom: Rendered resources block at wrong indent level
       Fix: Add | nindent N where N = parent indentation level
       Tenet: toYaml ALWAYS needs nindent after it

  S10: quote missing on integer — YAML type coercion bug
       🖥️ ksw → 2 (kind-cka-lab)
       Bug: {{ .Values.service.port }} not wrapped in quote — port 8000 becomes integer in YAML
       Symptom: Service port rendered without quotes, some parsers reject bare integers
       Fix: {{ .Values.service.port | quote }}
       Tenet: Always quote values that could be misinterpreted as non-strings

  S11: .Values scope lost inside range — The dot changes!
       🖥️ ksw → 2 (kind-cka-lab)
       Bug: Inside {{ range .Values.ingress.hosts }}, referencing {{ .Values.replicaCount }} fails
       Symptom: "can't evaluate field Values in type string" — dot is now the host string!
       Fix: Save root with {{ $root := . }} before range, use {{ $root.Values.replicaCount }}
       Tenet: Inside range/with, the dot CHANGES — always save root scope first

  S12: with block — Scope change causes missing .Release

       Symptom: "can't evaluate field Release" inside with block
       Fix: Use {{ $.Release.Name }} (global scope) or save root before with
       Tenet: $ is the GLOBAL root scope — use it inside scope-changing blocks

  S13: tpl function fails — String contains invalid template syntax
       🖥️ ksw → 6 (minikube)

  S14: required function fails — Mandatory value not set

  S18: .Capabilities.KubeVersion not matching — API version detection failure
