    • The OpenShift AI component ecosystem (diagram):
      Workbenches → Pipelines → Model Registry → KServe → Monitoring

F.2 AI/ML Fundamentals — The Concepts You MUST Know
    • What IS a machine learning model? (weights, biases, inference — in plain English)
    • Types of ML: Supervised, Unsupervised, Reinforcement Learning
    • Training vs Inference — the "cooking vs serving" analogy
    • LLMs (Large Language Models) — transformers, tokens, embeddings
    • RAG (Retrieval-Augmented Generation) — giving LLMs access to your data
    • GPU vs CPU — why AI needs accelerators (CUDA cores, tensor cores, vRAM)
    • Model formats: ONNX, PyTorch, TensorFlow, GGUF — what they are & when to use
    • Quantization: FP16, INT8, INT4 — smaller models, faster inference
    • Embeddings, vector databases, and semantic search
    • The anihpj/jobpost AI features: resume-to-job matching (embeddings),
      job description generation (LLM), salary prediction (regression model)
    🟢 Novice | 🟡 Intermediate: Model architecture deep dive, attention mechanisms

F.3 OpenShift AI Platform — The "Big Picture" Mental Model
    • OpenShift Container Platform → OpenShift AI Operator → Components
    • RHOAI (Red Hat OpenShift AI) Self-Managed architecture diagram
    • Data Science Project = Namespace + AI tooling
    • Workbench = JupyterLab/VS Code + GPU + Python packages + Storage
    • Pipeline Server = Argo Workflows + KubeFlow Pipelines (KFP)
    • Model Registry = versioned OCI artifacts + metadata + deployment targets
    • Model Serving = KServe (RawDeployment or Serverless) + runtimes
    • Monitoring = Prometheus + TrustyAI (bias/drift) + hardware metrics
    • The dashboard (OpenShift AI Console) — what you see as a data scientist vs admin
    🟢 Novice | 🟡 Intermediate: Operator lifecycle, CRD deep dive, multi-tenancy

F.4 The anihpj/jobpost AI Application Stack
    • anihpj-web: Django + HTMX — serves job board UI
    • anihpj-api: Django REST Framework — REST API endpoints
    • anihpj-db: PostgreSQL 15 — stores jobs, users, applications, model metadata
    • anihpj-redis: Redis — Celery task queue + embedding cache
    • anihpj-ml-pipeline: KubeFlow pipeline — data prep → train → evaluate → register
    • anihpj-model-server: KServe InferenceService — serves job-matching model
    • anihpj-rag: LlamaStack + Milvus vector DB — RAG for job description generation
    • anihpj-monitor: TrustyAI + Prometheus — bias/drift monitoring dashboards
    • How these tiers talk to each other (Service discovery via DNS + S3 data connections)
    • Complete file tree diagram of the AI-augmented Django project
    🟢 Novice

F.5 Docker/Podman vs OpenShift — A Mental Bridge
    • Dockerfile → Container image → OCI artifact → Model Registry
    • docker-compose.yml → Kubernetes YAML → OpenShift Templates
    • Why OpenShift AI when you can docker run a Jupyter container?
    • The "Day 2" AI problem: GPU sharing, model versioning, drift detection, scaling
    • OpenShift vs Stock Kubernetes — the security and operator advantages
    • Podman vs Docker — Red Hat's container engine (rootless, daemonless)
    🟢 Novice

    S51: anihpj job-match model deploy — InferenceService Creating stuck
        → Fix: Add missing storageUri field in predictor spec
    S52: Model storage URI — "s3://anihpj-models/v1" returns 403
        → Fix: Create SA with S3 read IAM + attach to predictor
    S53: Predictor pod OOM — model too large for allocated 4GB
        → Fix: Increase memory limit to 16GB + enable model caching
    S54: ServingRuntime not found — "tgis-runtime" CRD missing
        → Fix: Create ServingRuntime CR or verify operator installed
    S55: Transformer preprocessing — input JSON malformed, returns 400
        → Fix: Add input validation + error handling in transformer code
    S56: Knative cold start — first inference takes 30 seconds
        → Fix: Set minReplicas=1 or use RawDeployment mode
    S57: Multi-model serving — ModelMesh servingRuntime conflict
        → Fix: Use unique servingRuntime name per model group
    S58: Canary deployment — 10% traffic to new model returns 500s
        → Fix: Verify new model health before routing traffic
    S59: External URL not accessible — Route hostname DNS not resolving
        → Fix: Verify Route created + add DNS entry or use nip.io
    S60: Auth enabled — inference calls return 401 Unauthorized
        → Fix: Pass Bearer token from SA in inference request header

S61–S68: LLM Serving Scenarios
    S61: Deploy Llama-3-8B with vLLM — OOM on single GPU
        → Fix: Enable AWQ quantization or use tensor-parallel=2
    S62: vLLM server — "model not found" in HuggingFace cache
        → Fix: Pre-download model to PVC + mount in predictor
    S63: TGIS max_sequence_length — job descriptions truncated
        → Fix: Increase MAX_INPUT_LENGTH + MAX_TOTAL_TOKENS env vars
    S64: Streaming response — client receives JSON all at once
        → Fix: Use stream=True + SSE Content-Type in request header
    S65: Multi-LoRA adapter — "adapter not found" error
        → Fix: Correct LoRA adapter path + verify base model compatibility
    S66: Tokenizer mismatch — gibberish output from LLM
        → Fix: Match tokenizer to exact model checkpoint
    S67: GPU memory fragmentation — vLLM server restarts every hour
        → Fix: Set gpu_memory_utilization=0.85 + enable prefix caching
    S68: Continuous batching — throughput drops under concurrent load
        → Fix: Tune max_num_seqs + max_num_batched_tokens

S69–S75: Model Registry & Catalog
    S69: Model registration — "manifest not found" OCI error
        → Fix: Build model image with correct OCI media type annotation
    S70: Model versioning — overwriting v1 when registering v2
        → Fix: Use unique version tag: anihpj-jobmatch:v1, v2, v3
    S71: Deploy from registry — InferenceService references missing model
        → Fix: Verify model exists in registry + correct oci:// URI format
    S72: Model catalog — Hugging Face model import timeout (30GB model)
        → Fix: Increase PVC + use HF_HUB_ENABLE_HF_TRANSFER=1
    S73: Model promotion — "Staging" to "Production" transition blocked
        → Fix: Add approval annotation or use admin account
    S74: Registry API query — empty results due to wrong namespace
        → Fix: Specify correct namespace: oc get models -n anihpj-prod
    S75: Model evaluation — LMEval custom task YAML validation fails
        → Fix: Correct task YAML schema: task, dataset_path, metric

DECISION TREES (15) — Systematic AI Troubleshooting

15 decision trees providing step-by-step flowcharts to diagnose common
OpenShift AI issues. Each tree: START → NODE 1 → NODE 2 → ... → FIX.

DT1: Workbench Won't Start
    → Image pull? GPU? PVC? Tolerations? ResourceQuota? OAuth?

DT2: Pipeline Run Failed
    → Compile error? Runtime error? Resource OOM? S3 access? DB connection?

DT3: Model InferenceService Not Ready
    → Predictor pod? Storage URI? Runtime? Resource limits? Route?

DT4: GPU Not Detected in Workbench
    → GPU Operator? Node label? Driver? CUDA version? MIG config?

DT5: S3 Data Connection Failing
    → Endpoint? Credentials? Bucket exists? IAM policy? TLS certificate?

DT6: Model Registry Upload Failed
    → OCI auth? Image size? Manifest format? Registry URL? RBAC?

DT7: LLM Serving OOM (Out of Memory)
    → Model size? Quantization? GPU vRAM? Batch size? Context length?

DT8: TrustyAI Not Receiving Data
    → Model endpoint configured? Payload logger deployed? NetworkPolicy?

DT9: Pipeline Step Hangs Forever
    → Resource wait? Deadlock? Artifact dependency? Timeout? Node cordoned?

DT10: RBAC — User Cannot Access Dashboard
    → OAuth config? Group membership? RoleBinding? ClusterRole?

DT11: Model Accuracy Degraded After Deployment
    → Data drift? Concept drift? Preprocessing change? Batch effect?

DT12: Multi-Model Serving Conflict
    → ServingRuntime collision? Port conflict? Memory sharing? ModelMesh?

DT13: Disconnected (Air-Gapped) Install Failure
    → Mirror registry? ICSP? CatalogSource? Image pull secret?

DT14: Operator Upgrade Stuck
    → CSV phase? InstallPlan? Dependency conflict? Manual approval?

DT15: Full AI Platform Health Check
    → Operators → Projects → Workbenches → Pipelines → Serving → Monitoring
