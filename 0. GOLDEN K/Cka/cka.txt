  SECTION 2 — THE VISUAL COMPONENT CATALOG  (the art direction)
================================================================================
    These are the ONLY building blocks used to render content. The rule:
    "NEVER a wall of text." Every subsection must contain >=1 of these.
    Each entry = [WHAT it is] + [WHEN to use it] + an ASCII mock for the
    HTML generator to follow. cka_1.html's diagrams are a good base — REUSE
    the good ones, but AUGMENT (color, labels, legend, captions) and EXPAND.

    2.1  CONCEPT CARD GRID          — 2-4 cards, icon + title + 1-line idea.
         WHEN: introduce a set of sibling concepts (e.g. 4 Service types).
         [ 📦 Pod ][ 🔄 Deploy ][ 🔌 Service ][ 🌍 Ingress ]

    2.2  ANATOMY CALLOUT            — label every field of a YAML/command.
         WHEN: first time a manifest or command is shown.
         kubectl  get   pods   easypj-web   -n easypj
         └cmd──┘ └verb┘ └kind┘ └──name───┘ └namespace┘

    2.3  COMPARISON TABLE          — side-by-side feature matrix.
         WHEN: "X vs Y" decisions (VM vs container, RWO vs RWX).

    2.4  DECISION TREE 🧭          — branching "which one do I use?" guide.
         WHEN: choosing among options (Deployment vs StatefulSet vs DaemonSet).

    2.5  SEQUENCE / FLOW DIAGRAM   — numbered steps with arrows (left->right
         or top->down). WHEN: a process over time (pod creation, TLS handshake).

    2.6  ARCHITECTURE DIAGRAM      — boxed components + connections + legend.
         WHEN: showing how parts of the system relate spatially.

    2.7  MENTAL-MODEL / ANALOGY 🧠 — relate K8s to everyday life.
         WHEN: a concept is abstract (etcd = the cluster's memory/brain).

    2.8  COMMAND CHEAT-CARD 🔑     — grouped, copy-paste commands with notes.
         WHEN: end of every chapter ("most-used commands to remember").

    2.9  YAML SKELETON (annotated) — minimal manifest, every line commented.
         WHEN: teaching the shape of a resource; also used inside lab answers.

    2.10 UNDER THE HOOD 🔧         — collapsible deep-dive (internals, etcd
         keys, controller loops, packet paths). WHEN: once per chapter.

    2.11 GOTCHA BOX ⚠️            — the trap + why it happens + the fix.
         WHEN: a place learners reliably fail (indent, wrong ns, deprecated API).

    2.12 SPEED TIP ⚡             — exam time-saver (dry-run, aliases, $do).
         WHEN: an imperative shortcut beats writing YAML.

    2.13 DAILY-LIFE OPS 🏢        — "in a real job you would..." scenario.
         WHEN: connecting a tested skill to actual administration.

    2.14 TROUBLESHOOTING FLOW 🩺  — symptom -> checks -> cause -> fix tree.
         WHEN: any failure mode (CrashLoopBackOff, NotReady, Pending).

    2.15 BEFORE / AFTER SPLIT     — "without K8s" vs "with K8s" two-panel.
         WHEN: motivating why a feature exists.

    2.16 LIFECYCLE PILLS          — state badges joined by arrows
         (Pending -> Running -> Succeeded/Failed). WHEN: object states.

    2.17 STAT / PROGRESS BARS     — weights, adoption %, exam-domain %.
         WHEN: quantitative emphasis.

    2.18 RELATIONSHIP / MIND MAP  — central node with labeled spokes.
         WHEN: "how everything connects" (object relationship map).

    2.19 KEY TAKEAWAYS BANNER     — ✅ bullet recap + 🎯 exam relevance +
         🔑 commands. WHEN: end of every chapter AND every part.

    2.20 VISUAL SUMMARY           — one big picture that re-tells the whole
         chapter/part in a single diagram. WHEN: closing every chapter/part.

    2.21 PRACTICE DRILL 🧪        — short timed checklist task (do-it-now).
         WHEN: mid/after a chapter, before the formal lab questions.

    2.22 LAB Q&A CARD 🧪          — exam-style question + Show Answer +
         Show Explanation (with YAML/diagram). WHEN: 10+ per chapter, end.

    2.23 EXAM-TOPIC BADGE 🎯      — inline tag marking graded competencies.

    2.24 KEY TERM / GLOSSARY POP 📖 — bold term + tight definition box.

    HTML RENDER RULES (carried from cka_1.html, augmented):
      • Dark GitHub theme; collapsible 3-level sidebar (Part>Chapter>Section).
      • Prism.js syntax highlighting for yaml/bash/python/docker/json.
      • Mac-style code window header (red/yellow/green dots + lang label).
      • Responsive: Desktop >=1000px sidebar pinned (body margin-left);
        Tablet 768-999px sidebar = overlay; Mobile <768px slide-over,
        touch targets >=44px.
      • Smooth-scroll + scrollspy active-link highlight.
      • Every anchor id must exist and be linked from the sidebar.

  SECTION 5 — THE RUNNING PROJECT: easypj / jobpost
================================================================================
    Everything in this guide is taught on ONE real application so concepts
    compound instead of resetting each chapter.

    5.1  WHAT IT IS
         📖 easypj   = the Django PROJECT (the deployable unit / repo root).
         📖 jobpost  = the Django APP inside it (a job-board: post & browse
                       jobs, skills, employers, locations).
         Real code (Dem/easypj): Python 3.13, Django 5.2.5.

    5.2  THE DATA MODEL  (real models from jobpost/models.py)
         ┌──────────────────────────────────────────────────────────────┐
         │  User (django.contrib.auth)                                    │
         │     │ 1─1                                                       │
         │     ▼                                                          │
         │  Author(company, designation)                                  │
         │     │ 1─many (jobpost)                                          │
         │     ▼                                                          │
         │  JobPost(title, description, salary, type, slug, expiry, date) │
         │     ▲ 1─1            ▲ many─many                                │
         │     │                │                                         │
         │  Location(...)     Skills(name)                                │
         └──────────────────────────────────────────────────────────────┘
         API surface (jobpost/urls.py + views.py):
           GET /jobs/             -> jobpost_list   (JSON list of jobs)
           GET /jobs/<int:id>/    -> jobpost_detail (one job, 404 if missing)
           GET /skills/           -> skills_list    (JSON list of skills)

    5.3  THE CONTAINERIZATION STORY  (the through-line)
         🐳 Dev:    runserver + SQLite (db.sqlite3) — what the repo ships.
         🐳 Build:  multi-stage Dockerfile -> small gunicorn image easypj:vN.
         ☸️ Deploy: Pods (Deployment) + Service + Ingress/Gateway, config via
                    ConfigMap/Secret, data via PostgreSQL (StatefulSet + PVC).
         📖 Why swap SQLite -> PostgreSQL? SQLite is a single file on local
            disk — it cannot be shared by multiple replicas across nodes.
            Kubernetes scales easypj horizontally, so the database must be a
            networked, concurrent server: PostgreSQL (🐘). This swap is the
            single most important "why" that motivates Services, PV/PVC,
            StatefulSets, Secrets, and NetworkPolicy later in the guide.

    5.4  TARGET ARCHITECTURE  (what we build by the end)
         ┌─────────────────────── NAMESPACE: easypj ───────────────────────┐
         │  🌍 Ingress / 🚪 Gateway  (easypj.example.com)                    │
         │              │                                                    │
         │       🔌 Service: easypj-web (ClusterIP)                          │
         │        ┌─────┼───────────────┐                                   │
         │     📦 web-0  📦 web-1  📦 web-2   (Deployment, replicas=3, 📈HPA) │
         │        │  envFrom ⚙️ ConfigMap + 🔒 Secret                        │
         │        ▼                                                          │
         │       🔌 Service: easypj-db (headless)                            │
         │        │                                                         │
         │     🐘 postgres-0  (StatefulSet) ── 💾 PVC ── 🧱 StorageClass     │
         │                                                                   │
         │  🛡️ RBAC(SA+Role)  🧯 NetworkPolicy  PDB  CronJob(db-backup)      │
         └───────────────────────────────────────────────────────────────────┘

    5.5  WHERE THE PROJECT APPEARS (mapping)  — every part advances easypj:
         P1 understand it · P2 deploy it · P3 run it on a real cluster ·
         P4 scale/schedule it · P5 connect/expose it · P6 give it storage ·
         P7 secure it · P8 maintain it · P9 troubleshoot it · P10 observe it ·
         P11 ship it (CI/CD) · P12 extend/harden it · P13 prove it (exam).

  [HOW A POD IS BORN — kubectl apply -f easypj-deploy.yaml]
   1  kubectl ─►📡 apiserver         (HTTPS + client cert)
   2  apiserver ─► authN ─► authZ(RBAC) ─► admission   (who? allowed? valid?)
   3  apiserver ─►🗄️ etcd            (Deployment object persisted)
   4  🔄 controller-mgr sees Deployment ─► creates ReplicaSet ─► creates Pod(s)
   5  📋 scheduler sees an unbound Pod ─► filter ─► score ─► binds to Node 2
   6  🤖 kubelet(Node 2) sees its Pod ─►🐋 containerd pulls easypj:v2 ─► starts
   7  🌐 kube-proxy programs Service routing to the new Pod IP
   8  ✅ Pod Running ─► kubelet reports status ─► apiserver ─► etcd
   💡 Each actor only reconciles its OWN slice — no central script.

  [KUBERNETES IS PLUGGABLE — the 3 extension interfaces]
        🤖 kubelet ──CRI──► 🐋 containerd / CRI-O        (RUN containers)
        pod network ──CNI──► 🌐 Calico / Cilium / Flannel (WIRE pods)
        volumes ──CSI──► 🧱 CSI driver (EBS/PD/Ceph/NFS)   (ATTACH storage)
   📖 CRI=runtime · CNI=network · CSI=storage — the three "sockets" of K8s.

  Appendix D: Kubernetes Glossary (120+ terms, A->Z)
  ------------------------------------------------------------------------------
    Legend:  [C]=cluster-scoped  [N]=namespaced  🎯=exam-critical
  ── A ──
    Admission Controller 🎯 — intercepts API requests after authN/authZ, before
       etcd; mutating runs then validating.
    Affinity 🎯 — rules biasing placement (node/pod, required/preferred).
    Aggregation Layer — extends the apiserver via APIService objects.
    Annotation — non-identifying metadata; NOT used for selection (cf. label).
    API Group 🎯 — resource grouping: core "", apps, batch, networking.k8s.io...
    API Server (kube-apiserver) 🎯 — the only front door; authN->authZ->
       admission->etcd.
    AppArmor — kernel LSM restricting a container's file/network access.
  ── B ──
    Base64 🎯 — ENCODING (not encryption) used to store Secret values.
    BGP — routing protocol some CNIs (Calico) use for pod networking.
    BoltDB — the embedded on-disk store etcd uses (with a WAL).
  ── C ──
    cAdvisor — per-node container metrics, embedded in the kubelet.
    Calico — CNI with NetworkPolicy support (BGP or VXLAN).
    Capability (Linux) — granular root privilege; drop ALL to harden.
    cgroup — kernel feature limiting CPU/memory per process group.
    CIDR 🎯 — IP-range notation (e.g. --pod-network-cidr=10.244.0.0/16).
    Cilium — eBPF-based CNI (networking, policy, Hubble observability).
    ClusterIP 🎯 — default Service type; internal virtual IP.
    ClusterRole [C] 🎯 — cluster-wide permission set.
    CNI 🎯 — Container Network Interface; the pod-networking plug point.
    ConfigMap [N] 🎯 — non-sensitive key/value configuration.
    containerd — the default container runtime (implements the CRI).
    Context (kubeconfig) 🎯 — a cluster + user + namespace tuple.
    Control Plane 🎯 — apiserver + etcd + scheduler + controller-manager.
    Controller — reconciliation loop driving actual state -> desired state.
    CoreDNS 🎯 — in-cluster DNS server (Deployment in kube-system).
    Cordon 🎯 — mark a node unschedulable (existing pods stay).
    CRI 🎯 — Container Runtime Interface; the runtime plug point.
    CronJob [N] 🎯 — runs Jobs on a cron schedule.
    CSI 🎯 — Container Storage Interface; the storage plug point.
    CSR 🎯 — CertificateSigningRequest; a cert signed by the cluster CA.
    CRD [C] 🎯 — CustomResourceDefinition; adds a new API type.
  ── D ──
    DaemonSet [N] 🎯 — one pod per matching node.
    Defragmentation — reclaim etcd disk after compaction.
    Deployment [N] 🎯 — manages ReplicaSets for stateless apps + rollouts.
    Descheduler — evicts pods to re-balance against current policy (add-on).
    Drain 🎯 — safely evict all pods from a node for maintenance.
    Dynamic Provisioning 🎯 — a StorageClass auto-creates a PV for a PVC.
  ── E ──
    eBPF — kernel tech powering modern CNIs/observability (Cilium).
    emptyDir 🎯 — ephemeral pod-scoped volume (scratch/sidecar).
    Endpoint / EndpointSlice 🎯 — pod IP:ports backing a Service.
    etcd 🎯 — distributed KV store holding ALL cluster state (Raft).
    Eviction — removing a pod due to node pressure or a drain.
  ── F ──
    Finalizer — blocks deletion until cleanup completes.
    Flannel — simple VXLAN CNI (NO NetworkPolicy support).
    FQDN 🎯 — <svc>.<ns>.svc.cluster.local service name.
    fsGroup — supplemental GID applied to mounted volumes.
  ── G ──
    Gateway API 🎯 — role-based successor to Ingress (GatewayClass/Gateway/
       HTTPRoute).
    GitOps — git as source of truth; a controller syncs (ArgoCD/Flux).
    Guaranteed (QoS) 🎯 — requests == limits for all resources.
  ── H ──
    HA 🎯 — High Availability: >=3 control planes + quorum etcd + LB.
    Headless Service 🎯 — clusterIP: None; per-pod DNS (StatefulSets).
    Helm 🎯 — package manager; templated, versioned releases (charts).
    hostPath 🎯 — node-filesystem volume (dev/agent only).
    HPA [N] 🎯 — Horizontal Pod Autoscaler; scales replicas on metrics.
  ── I ──
    Informer — client-side cache/watch powering controllers.
    Ingress [N] 🎯 — L7 HTTP(S) routing rules (needs a controller).
    Ingress Controller 🎯 — implements Ingress (e.g. nginx).
    initContainer — runs to completion before app containers start.
    IPVS — high-performance kube-proxy mode.
  ── J ──
    Job [N] 🎯 — run-to-completion workload.
    JSONPath 🎯 — query language for kubectl -o jsonpath.
  ── K ──
    kubeadm 🎯 — bootstraps & upgrades clusters.
    kubeconfig 🎯 — clusters/users/contexts file (~/.kube/config).
    kubectl 🎯 — the CLI / REST client.
    kubelet 🎯 — node agent (a systemd service, NOT a pod).
    kube-proxy 🎯 — programs Service routing (iptables/IPVS/nftables).
    kube-scheduler 🎯 — filter -> score -> bind pod placement.
    Kustomize 🎯 — template-free base + overlays/patches (apply -k).
  ── L ──
    Label 🎯 — key/value used for selection.
    Lease — lightweight object for leader election & node heartbeats.
    LimitRange [N] 🎯 — per-pod/container default/min/max resources.
    Liveness Probe 🎯 — restart the container if it fails.
    LoadBalancer 🎯 — Service type provisioning an external LB.
  ── M ──
    Manifest — YAML/JSON declaring desired state.
    Metrics Server 🎯 — supplies kubectl top & HPA metrics.
    Mirror Pod — the API representation of a static pod.
    Mutating Webhook — admission webhook that can modify a request.
    MVCC — etcd multi-version concurrency (revisions).
  ── N ──
    Namespace [C] 🎯 — virtual cluster for isolation.
    NetworkPolicy [N] 🎯 — pod-level firewall (needs policy-aware CNI).
    Node [C] 🎯 — a worker or control-plane machine.
    NodePort 🎯 — Service type on each node's IP:30000-32767.
    nodeSelector / Node Affinity 🎯 — constrain pods to nodes.
  ── O ──
    OCI — Open Container Initiative image/runtime standard.
    OOMKilled 🎯 — container killed for exceeding its memory limit.
    Operator 🎯 — CRD + controller automating an app's lifecycle.
    OPA Gatekeeper — Rego-based policy engine (webhook).
    ownerReferences — parent links enabling cascading deletion.
  ── P ──
    PV [C] 🎯 — PersistentVolume; cluster storage resource.
    PVC [N] 🎯 — PersistentVolumeClaim; a request for storage.
    PDB [N] 🎯 — PodDisruptionBudget; min available during disruption.
    Pod [N] 🎯 — smallest unit; 1+ containers sharing net/storage.
    Pod Security Standards/Admission 🎯 — privileged/baseline/restricted.
    PriorityClass [C] — pod importance for scheduling/preemption.
    Probe 🎯 — health check (liveness / readiness / startup).
  ── Q ──
    QoS Class 🎯 — Guaranteed/Burstable/BestEffort (eviction order).
    Quorum 🎯 — N/2+1 etcd members required to commit a write.
  ── R ──
    Raft 🎯 — etcd's consensus protocol (leader + followers).
    RBAC 🎯 — Role-Based Access Control.
    Readiness Probe 🎯 — gate traffic by adding/removing from endpoints.
    Reclaim Policy 🎯 — Retain / Delete / Recycle for a PV.
    ReplicaSet [N] 🎯 — maintains a pod count (managed by Deployments).
    ResourceQuota [N] 🎯 — namespace-wide resource caps.
    Role [N] 🎯 — namespaced permission set.
    RollingUpdate 🎯 — gradual pod replacement (default strategy).
  ── S ──
    Secret [N] 🎯 — base64-stored sensitive data (encrypt at rest!).
    SecurityContext 🎯 — per-pod/container security settings.
    seccomp — syscall filtering (RuntimeDefault recommended).
    Selector 🎯 — match labels to pick objects.
    Service [N] 🎯 — stable VIP + DNS fronting pods.
    ServiceAccount [N] 🎯 — pod identity for API auth.
    Sidecar — helper container in a pod (logging/proxy).
    StatefulSet [N] 🎯 — stable identity + per-pod storage.
    Static Pod 🎯 — kubelet-managed pod from /etc/kubernetes/manifests/.
    StorageClass [C] 🎯 — defines dynamic provisioning.
    Startup Probe 🎯 — protects slow-starting containers.
  ── T ──
    Taint / Toleration 🎯 — repel pods from a node unless tolerated.
    TLS 🎯 — mutual TLS secures all control-plane traffic.
    Topology Spread Constraint 🎯 — even pod distribution across domains.
    TokenRequest — short-lived projected ServiceAccount tokens.
  ── U ──
    Uncordon 🎯 — make a cordoned node schedulable again.
    Union FS (OverlayFS) — the layered container filesystem.
  ── V ──
    ValidatingAdmissionPolicy 🎯 — in-cluster CEL policy (no webhook).
    Validating Webhook — admission webhook that accepts/rejects.
    Velero — backup/restore of namespaces + PV snapshots.
    veth pair — virtual ethernet linking a pod to the node bridge.
    volumeClaimTemplates 🎯 — per-pod PVCs in a StatefulSet.
    volumeMode — Filesystem (default) or Block.
    VPA — Vertical Pod Autoscaler (right-sizes requests).
  ── W ──
    WaitForFirstConsumer 🎯 — delay PV binding until a pod schedules.
    WAL — etcd write-ahead log.
    Webhook — HTTP callback used by admission control.
    Worker Node 🎯 — runs application pods.
