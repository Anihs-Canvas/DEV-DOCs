  Purpose: Single-prompt blueprint for Claude to generate a world-class

  Output:  cka.html — dark-themed, interactive, self-contained, responsive
  Context: Uses anihpj/jobpost Django project as running example throughout

═══════════════════════════════════════════════════════════════════════════════
  PHASE 0: GROUND RULES (Read First)
═══════════════════════════════════════════════════════════════════════════════

  1. EVERY concept must be illustrated with at least ONE of:
     - ASCII diagram (┌└├│┤┬┴┼─═ characters)
     - Comparison table
     - Before/After scenario card
     - Evolution timeline strip
     - Stat/progress bar group
     - Code block with real kubectl/Docker commands

  2. NEVER write plain paragraphs without a visual component.
     A wall of text = failure. Every section has at least one diagram/table/card.

  3. ALL examples use the anihpj/jobpost Django project:
     - anihpj = Django project folder
     - jobpost = Django app inside it (models: Skills, User, Author, Location, JobPost)
     - Every kubectl command, YAML manifest, Dockerfile references anihpj

  4. CKA exam framing ALWAYS present:
     - Every chapter states its CKA domain + weight
     - Every chapter has at least one "CKA Exam Tip" callout
     - 30% of exam is Troubleshooting — emphasize debugging patterns

  5. Content depth: The reader should NEVER need external documentation.
     Every concept is explained fully. No "refer to official docs" cop-outs.

  6. This guide covers BOTH the exam AND real-world administration beyond it.

  PHASE 1: GENERATE THE TOC FIRST (cka.txt)
═══════════════════════════════════════════════════════════════════════════════

Before writing any HTML, first produce a detailed Table of Contents as cka.txt.
This is the BLUEPRINT. Everything in cka.html will follow this structure exactly.

STRUCTURE:
  - 11 Learning Parts, 40 Chapters, 9 Appendices
  - Parts organized by CKA domain weight (highest weight areas get most chapters)
  - Each chapter: 5-8 sections + quiz
  - Level badges: 🟢 Beginner | 🟡 Intermediate | 🔴 Advanced
  - Duration estimates per chapter

  PART 1: FOUNDATION                    🟢 Beginner  | Chapters 1-4   | ~7 hrs
  PART 2: GETTING STARTED               🟢 Beginner  | Chapters 5-8   | ~8 hrs
  PART 3: CLUSTER INSTALLATION          🟡 CKA 25%   | Chapters 9-12  | ~6 hrs
  PART 4: WORKLOADS & SCHEDULING        🟡 CKA 15%   | Chapters 13-16 | ~5 hrs
  PART 5: SERVICES & NETWORKING         🟡 CKA 20%   | Chapters 17-20 | ~5 hrs
  PART 6: STORAGE                       🟡 CKA 10%   | Chapters 21-23 | ~4 hrs
  PART 7: SECURITY                      🟡 Intermed  | Chapters 24-27 | ~5 hrs
  PART 8: CLUSTER MAINTENANCE           🔴 Advanced  | Chapters 28-30 | ~4 hrs
  PART 9: TROUBLESHOOTING               🔴 CKA 30%   | Chapters 31-34 | ~4 hrs
  PART 10: PRODUCTION & BEYOND          🔴 Advanced  | Chapters 35-37 | ~4 hrs
  PART 11: EXTENDING & HARDENING        🔴 Advanced  | Chapters 38-40 | ~5 hrs

  APPENDICES (A-I):
    A: kubectl Admin Command Reference
    B: CKA YAML Templates (12 annotated templates)
    C: Common Errors → Cause → Fix table
    D: Kubernetes Terminology Glossary (100+ terms)
    E: Complete anihpj Production Manifests
    F: CKA Exam Prep (format, rules, tips, bookmarks, day-of checklist)
    G: 10-Week Learning Path (week-by-week roadmap)
    H: CKA Exam Simulator (17 timed tasks with weighted scoring)
    I: Labels, Annotations & Taints Reference

For EVERY chapter in the TOC, specify:
  - Chapter number and title
  - Section titles (5-8 per chapter)
  - What diagrams/tables each section should contain
  - What code examples to include
  - What CKA exam tips to highlight

The TOC should be detailed enough that someone could write the HTML from it
without making structural decisions.

Once the TOC is approved, proceed to Phase 2.
