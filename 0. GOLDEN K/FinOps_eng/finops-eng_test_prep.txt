F.1 What Is FinOps & Why Does It Matter? 🟢 Novice
    • The "Cloud Bill Shock" Problem — Why $500/mo becomes $50,000/mo overnight
    • FinOps = Finance + DevOps = Bringing financial accountability to cloud spending
    • The 6 FinOps Principles — The DNA of every FinOps practice:
        1. Teams need to collaborate (Finance + Engineering + Product + Leadership)
        2. Decisions are driven by business value of cloud
        3. Everyone takes ownership of their cloud usage
        4. FinOps data should be accessible and timely
        5. A centralized team drives FinOps
        6. Take advantage of the variable cost model of cloud
    • The FinOps Lifecycle — The never-ending 3-phase cycle:
        📊 INFORM: See it → Know what you're spending and why
        ⚡ OPTIMIZE: Save it → Reduce waste and commit to better rates
        🎯 OPERATE: Govern it → Make cost-conscious decisions continuously
    • Why anihpj/jobpost is your learning lab:
        - Django web tier (EKS): Variable traffic = variable compute cost

        - PostgreSQL (RDS): Steady-state cost + backup storage
        - Redis cache (ElastiCache): Memory-tiered pricing
        - S3 assets: Storage class optimization opportunity
        - CloudFront CDN: Data transfer cost optimization
    • Real-world FinOps impact: Airbnb saved 40%, Netflix saved 25%, Spotify saved 30%

F.2 Cloud Economics 101 — How Cloud Pricing ACTUALLY Works 🟢 Novice
    • The 5 Cloud Cost Dimensions — Every service charges by some combination of:
        1. COMPUTE TIME: Per-second/per-hour VM/container runtime
        2. STORAGE CAPACITY: Per-GB stored, per-IOPS
        3. DATA TRANSFER: Per-GB egress (ingress usually free)
        4. LICENSING: Per-core software licensing
        5. API CALLS: Per-million requests/operations
    • AWS, Azure, GCP Pricing Models Compared:
        - On-Demand: Pay-as-you-go (highest rate, zero commitment)
        - Reserved/Commitment: 1-3 year commitment (30-72% discount)
        - Spot/Preemptible: Bid on spare capacity (60-90% discount, can be reclaimed)
        - Savings Plans: Commit to $/hr spend (flexible across instance family)
        - Enterprise Agreements: Custom negotiated pricing
    • The "Penny Wise, Pound Foolish" Trap — Why cheapest ≠ best:
        - t3.nano ($0.0052/hr) vs t3.medium ($0.0416/hr)
        - The nano is 87% cheaper BUT: max 2 vCPU credits, 0.5GB RAM → crashes under load
    • Cloud Provider Free Tiers & Credits — AWS Free Tier, GCP $300 credit, Azure $200

───────────────────────────────────────────────────────────────────────
Q1-Q50 — "Focuses on evaluating architectural alternatives based on business

Domain Intro (Novice-Friendly):
    Think of cloud architecture like building a house. You could build a
    mansion with 10 bedrooms (over-provisioned) or a tiny studio (under-
    provisioned). Cost-efficient architectural design is about building the
    RIGHT size house that can expand when your family grows.

    This domain tests your ability to make architecture decisions that balance:
    - SPEED (how fast can we ship?)
    - QUALITY (is it reliable and secure?)
    - PERFORMANCE (does it handle load?)

    - Should the API tier be EKS (containers) or Lambda (serverless)?

    - Does the RDS database REALLY need db.r5.large or would db.t3.large suffice?

    📊 Key trade-off: Every architectural decision has a cost dimension.
       "Serverless is cheaper at low traffic, containers win at steady high traffic."

DOMAIN 2: TECHNICAL IMPLEMENTATION OF FOCUS DATA SETS (~25%)
───────────────────────────────────────────────────────────────────────
Q51-Q100 — "Tests the engineer's ability to normalize and handle cross-cloud
usage data. Understanding and processing FOCUS syntax to compare multi-cloud
expenditures uniformly."

Domain Intro (Novice-Friendly):
    Imagine you have bank accounts at 3 different banks (AWS, Azure, GCP).
    Each bank sends you a statement in a DIFFERENT format — different column
    names, different currencies, different granularities. How do you answer
    "How much did I spend total on compute last month across ALL clouds?"

    That's what FOCUS (FinOps Open Cost & Usage Specification) solves. It's a
    standard schema — like agreeing that all banks will use the same column
    names (ServiceName, ChargeType, BilledCost, EffectiveCost). Once your data
    is in FOCUS format, you can query across clouds with ONE set of SQL.

    This domain tests your ability to:
    - Read raw cloud billing data (CUR, Azure billing, GCP BigQuery exports)
    - Understand FOCUS column semantics
    - Normalize multi-cloud data into a unified view
    - Write SQL queries that answer real business questions

    📊 For anihpj/jobpost: "Which cloud provider gives us the best price for
       PostgreSQL at our scale?" → Requires FOCUS-normalized comparison.
