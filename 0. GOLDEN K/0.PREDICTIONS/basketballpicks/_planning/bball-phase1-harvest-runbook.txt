0. WHAT THIS DELIVERS
--------------------------------------------------------------------------------
Two layers, two purposes:
  * DATA / PREDICTOR layer  = box + PBP player data. ALL KEYLESS + FREE. This is
    what feeds the model. You can start harvesting TODAY with zero signups.
  * ODDS / EDGE layer       = de-vig + line-shop feeds. Free but each needs a
    (free, no-card) API key OR is a keyless public-JSON scrape. Unlocks betting
    edge, NOT the predictor. Wired as BudgetedClient factories in
    apps/odds/free_clients.py; see the GAP note in §5.

Run from the Django project root (where manage.py lives). No API keys needed for
this section — both sources are keyless.

Prereqs (one-time): migrations applied (creates core models + ingestion.JobRun),
Postgres up. Env: browser-UA defaults are baked into the client factories.

--- NBA (nba_api, keyless) -----------------------------------------------------
  # default = yesterday's completed slate (NBA runs overnight ET)
  python manage.py harvest_nba

  # a specific day
  python manage.py harvest_nba --date 2026-01-15

  # a backfill window (inclusive; idempotent + resumable)
  python manage.py harvest_nba --from 2026-01-01 --to 2026-01-07

  # add the props usage signal (USG%/pace/off-def rating) — costs 1 extra call/game
  python manage.py harvest_nba --date 2026-01-15 --with-advanced

  # soak/smoke guard: stop after N games (great for a first run)
  python manage.py harvest_nba --date 2026-01-15 --max-games 3

  FLAGS: --date | (--from & --to together) | --with-advanced | --max-games N.
  NB: July is NBA offseason — a July --date returns an empty slate (healthy, see
  §4). Use an in-season date like 2026-01-15 for a live-data smoke test.

4. WHAT A HEALTHY RUN LOOKS LIKE
--------------------------------------------------------------------------------
Every command wraps the harvest in an ingestion.JobRun audit row
(harvest.run_harvest_job) and prints a one-line summary.

STDOUT (healthy, in-season day) — e.g.:
  nba_api 2026-01-15..2026-01-15: games seen=8 (new=8 upd=0), team-box=16
  player-box=~230; calls=17 cache=0 errors=0

HEALTHY = read it like this:
  * games_seen > 0 and games_created + games_updated == games_seen.
  * team_box_rows == 2 x (FINAL games)   (one row per team).
  * player_box_rows roughly 20-30 x FINAL games (both benches).
  * fetch_errors == 0  (a couple of transient errors are tolerated + skipped,
    never raised — but 0 is the target).
  * NO "stopped:" WARNING line (that prints only when a budget is exhausted).
  * A re-run of the SAME slate shows new=0, all upd — proves idempotency (games
    key on (source, external_id); box rows update_or_create in place; a stored
    FINAL is never downgraded and a score is never erased).

JobRun row (in DB): status == OK; stats == the HarvestStats dict
  (games_seen/created/updated, team_box_rows, player_box_rows, players_seen,
  fetch_errors, empty_slates, requests_made, cache_hits, per_day{date:{...}}).
  status == FAILED only on a real raised exception (stats.error set), which also
  re-raises to the beat wrapper.

HEALTHY-BUT-EMPTY (offseason / no games that day): games_seen=0,
  empty_slates=1, errors=0, status=OK. This is a correct no-op, not a failure.
  (Expect this for any July NBA --date.)
