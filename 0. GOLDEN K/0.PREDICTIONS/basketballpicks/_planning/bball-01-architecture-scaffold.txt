--------------------------------------------------------------------------------
(0) THE ONE STRATEGIC FACT THAT SHAPES EVERY DECISION BELOW
--------------------------------------------------------------------------------

basketball-feasibility.txt is blunt: the MAIN market (spread / moneyline /
total) is at least as efficient as soccer's. A points/pace model goes
MARKET-GRADE and stalls at the information ceiling — do NOT rebuild the soccer
"beat the closing line with a smarter model" thesis. The ONE live +EV door is
PLAYER PROPS on soft books + DFS pick'em (Underdog/PrizePicks), plus WNBA / NCAA
/ EuroLeague. And the edge there is NOT forecasting genius — it is a
DEVIG + LINE-SHOP arbitrage: take the sharp consensus (Pinnacle/Circa), remove
the vig to a fair probability, bet any soft/DFS price that beats fair.

Consequences for the scaffold (these recur throughout):

  A. The schema is PLAYER-FIRST. safepicks deliberately left Player as a bare
     name string ("Player table is Phase 3+", ingestion/models.py header).
     basketballpicks INVERTS that: Player, PlayerBoxScore and PropLine are the
     first-class, high-cardinality core (200-400 prop lines/night).

  B. The HERO engine is DEVIG + LINE-SHOP, not a model. safepicks' hero app
     (`apps.safepicks`) selects "safe" picks from its own CORE model's
     probability. Here, `apps.odds.sharp_anchor` — which in safepicks is an
     EVIDENCE-ONLY study ("no gate verdict, no Pick writes") — is PROMOTED to
     the live product core. The model is a SECONDARY input, used only on
     neglected/thin lines where even the sharp consensus is weak.

  C. DFS pick'em is a first-class VENUE and a new PARLAY construct. It is the
     durable, limit-resistant home for the edge, and it needs correlated
     2-6-leg entry math that soccer's singles-only paper ledger never had.

  D. Validation is FORWARD paper-CLV, not deep backtest. Prop odds history only
     reaches ~2023 (too thin for a "Last Dance"-grade backtest); safepicks'
     `paper_clv.py` forward logger becomes the CENTRAL validation harness, not a
     side experiment.

  core         → core         reference + results. NOW ALSO Player + box scores.

  features     → features     TeamRating(+pace); NEW PlayerForm + MinutesProjection.

  predictions  → predictions  ModelVersion/Prediction (team, market-grade, de-emphasised).

                              + the devig/line-shop engine. THE differentiator. ***
  safepicks    → edge         *** HERO PUBLISHER: EdgeRule/EdgePick/ProductionModel/
                              PipelineState/RiskProfile — the +EV selection + gates. ***
  valuebets    → secondary    SecondaryModule flag registry (EuroLeague, in-play, ...).
  backtesting  → backtesting  settle/pnl/CLV engine; forward paper-CLV emphasis.
  portfolio    → portfolio    Bankroll/Bet (singles) + NEW DFSEntry (pick'em parlays).
  dashboard    → dashboard    Django ops templates (reuse).
  api          → api          DRF v1 read surface (reuse shape; new prop routes).

Why props is split OUT of odds/predictions (unlike soccer, where OddsSnapshot
lives in `odds` and probabilities in `predictions`): props are the product, are
player-grained, are two-sided (over/under on one row), and carry their own devig
+ settlement. Giving them a dedicated app keeps them FIRST-CLASS and cohesive.
Team-market odds stay in `apps.odds` and share the pure `odds.devig` math.

(2) CORE POSTGRES DATA MODEL (models.py sketches)
--------------------------------------------------------------------------------

Conventions carried verbatim from safepicks: DecimalField for anything

========================= apps/core/models.py ==================================

class League(models.Model):
    code       = CharField(max_length=16, unique=True)   # NBA, WNBA, NCAAB, EURO
    name       = CharField(max_length=64)
    level      = CharField(max_length=16)                 # pro | college | intl
    source_ids = JSONField(default=dict, blank=True)      # {nba_api:00, odds_api:basketball_nba}

class Season(models.Model):
    league     = FK(League, related_name="seasons")
    name       = CharField(max_length=16)                 # "2025-26"
    start_date = DateField(null=True); end_date = DateField(null=True)
    UniqueConstraint(league, name)

class Team(models.Model):
    canonical_name = CharField(max_length=64)
    abbreviation   = CharField(max_length=8)              # LAL, BOS, ...
    league         = FK(League, related_name="teams")
    conference     = CharField(max_length=16, blank=True) # East|West (nullable college/intl)
    division       = CharField(max_length=24, blank=True)
    UniqueConstraint(canonical_name, league)
# TeamAlias — copy safepicks TeamAlias verbatim (source name resolution queue).

class Player(models.Model):                               # *** FIRST-CLASS (soccer had none) ***
    canonical_name   = CharField(max_length=80)
    current_team     = FK(Team, null=True, on_delete=SET_NULL, related_name="roster")
    primary_position = CharField(max_length=4, blank=True)  # G|F|C|G-F...
    birthdate        = DateField(null=True, blank=True)
    status           = CharField(max_length=16, default="active")  # active|two_way|10day|inactive
    source_ids       = JSONField(default=dict, blank=True)          # {nba_api: 2544, ...}
    UniqueConstraint(canonical_name, current_team)  # + PlayerAlias table (mirror TeamAlias)

class Game(models.Model):                                 # the Match analog
    SCHEDULED/LIVE/FINAL/POSTPONED status choices (mirror Match.STATUS_*)
    season      = FK(Season, related_name="games")
    home_team   = FK(Team, PROTECT, related_name="home_games")
    away_team   = FK(Team, PROTECT, related_name="away_games")
    tipoff_utc  = DateTimeField()
    status      = CharField(...)  # SCHEDULED|LIVE|FINAL|PP
    home_score  = PositiveSmallInt(null=True); away_score = PositiveSmallInt(null=True)
    period_scores = JSONField(default=dict, blank=True)   # {"Q":[..], "OT":[..]}
    num_ot      = PositiveSmallInt(default=0)             # OT changes prop-minutes math
    venue       = CharField(max_length=64, blank=True)
    home_rest_days = SmallInt(null=True); away_rest_days = SmallInt(null=True)  # B2B flag input
    pace        = DecimalField(max_digits=6, decimal_places=2, null=True)  # possessions/48
    source      = CharField(max_length=32); external_id = CharField(max_length=128)
    raw         = JSONField(default=dict, blank=True)
    UniqueConstraint(source, external_id); Index(tipoff_utc), Index(season, tipoff_utc)

class TeamBoxScore(models.Model):
    game = FK(Game, related_name="team_boxscores"); team = FK(Team, PROTECT)
    is_home = BooleanField()
    pts,reb,ast,stl,blk,tov,pf = PositiveSmallInt each
    fgm,fga,tpm,tpa,ftm,fta   = PositiveSmallInt each
    minutes  = DecimalField(6,1)                          # 240 (+25/OT)
    pace     = DecimalField(6,2, null=True)
    off_rtg  = DecimalField(6,2, null=True); def_rtg = DecimalField(6,2, null=True)
    raw = JSONField(default=dict, blank=True)
    UniqueConstraint(game, team)

class PlayerBoxScore(models.Model):                       # *** THE differentiator table ***
    game    = FK(Game, related_name="player_boxscores")
    player  = FK(Player, PROTECT, related_name="boxscores")
    team    = FK(Team, PROTECT)
    started = BooleanField(); dnp = BooleanField(default=False)  # DNP-CD / inactive
    minutes = DecimalField(6,2)                           # 34.5 — the master prop driver
    pts,oreb,dreb,reb,ast,stl,blk,tov,pf = PositiveSmallInt each
    fgm,fga,tpm,tpa,ftm,fta = PositiveSmallInt each
    plus_minus  = SmallInt(null=True)
    usage_rate  = DecimalField(5,2, null=True)           # USG% — the cascade signal
    raw = JSONField(default=dict, blank=True)
    UniqueConstraint(game, player)
    Index(player, -game_id), Index(game, team)
    # PRA / PR / PA / RA / double-double etc. are DERIVED from these columns at
    # settle time (props.settle), never stored — one source of truth.

class PlayByPlay(models.Model):   # OPTIONAL / DEFERRED (nba_api gives it free but

========================= apps/props/models.py ================================
#  *** THE differentiator app — design carefully ***

class PropMarket(models.Model):
    """Catalog of prop market types (the MarketRule-catalog idea, but market
    DEFINITIONS). settle_expr maps a market to PlayerBoxScore columns."""
    key         = CharField(max_length=24, unique=True)   # points|rebounds|assists|
                                                          # pra|pr|pa|ra|threes|blocks|
                                                          # steals|turnovers|double_double
    label       = CharField(max_length=48)
    settle_expr = CharField(max_length=64)   # "pts" | "pts+reb+ast" | "tpm" | "dd(...)"
    is_combo    = BooleanField(default=False)             # PRA / PR etc.
    default_active = BooleanField(default=True)

class PropLine(models.Model):                             # *** the prop odds snapshot ***
    """One book's two-sided quote for one player's one market at one instant.
    Over AND under prices on ONE row (props are two-way — differs from
    OddsSnapshot's one-selection-per-row). Unique key mirrors OddsSnapshot
    but is (game,player,market,book,line,is_closing,captured_at)."""
    game        = FK("core.Game", related_name="prop_lines")
    player      = FK("core.Player", PROTECT, related_name="prop_lines")
    market      = FK(PropMarket, PROTECT)
    bookmaker   = FK("odds.Bookmaker", PROTECT)
    line        = DecimalField(6,2)                       # 24.5
    over_price  = DecimalField(8,3, null=True)            # decimal; DFS pick'em -> ~1.90/None
    under_price = DecimalField(8,3, null=True)
    payout_mult = DecimalField(6,3, null=True)            # DFS: leg payout multiplier (no vig)
    is_closing  = BooleanField(default=False)
    captured_at = DateTimeField()
    source      = CharField(max_length=32); raw = JSONField(default=dict, blank=True)
    UniqueConstraint(game,player,market,bookmaker,line,is_closing,captured_at)
    Index(game,market), Index(player,-captured_at), Index(market,is_closing)

class PropConsensus(models.Model):
    """Devigged SHARP fair number+prob per (game,player,market,line) — the
    line-shop benchmark. Optionally materialised (can also be recomputed at
    read time like safepicks derives DC/DNB). anchor names WHICH sharp book."""
    game=FK; player=FK("core.Player"); market=FK(PropMarket)
    line        = DecimalField(6,2)
    fair_prob_over = DecimalField(6,5)      # Shin/multiplicative-devigged sharp p(over)
    anchor      = CharField(max_length=32)  # "pinnacle" | "circa" | "consensus"
    is_closing  = BooleanField(default=False); captured_at = DateTimeField()
    UniqueConstraint(game,player,market,line,anchor,is_closing,captured_at)

class PropPrediction(models.Model):                       # the MODEL layer (SECONDARY)
    """Minutes->usage Poisson/neg-binom projection for neglected/thin lines.
    dist_params lets prob(over line) be computed for ANY line (like soccer's
    CORE pmf being the source of truth for any AH/total)."""
    game    = FK("core.Game", related_name="prop_predictions")
    player  = FK("core.Player", PROTECT)
    market  = FK(PropMarket, PROTECT)
    model_version = FK("predictions.ModelVersion", PROTECT)
    proj_minutes = DecimalField(6,2)                      # the master driver
    mean    = DecimalField(7,3)                           # projected stat mean
    dist    = CharField(max_length=16, default="neg_binom")   # poisson|neg_binom|normal
    dist_params = JSONField()                             # {"r":..,"p":..} etc.
    created_at = DateTimeField(auto_now_add=True)
    UniqueConstraint(game,player,market,model_version)

class EdgePick(models.Model):                            # *** the product row (Pick analog) ***
    """One published +EV pick. DEVIG-CENTRIC: the benchmark is sharp-fair, not
    the model. prop_prediction is NULLABLE — a pure line-shop pick has no
    model. Candidates that fail a gate write NO row (audit -> publishing JobRun)."""
    prop_line   = FK("props.PropLine", PROTECT, null=True)   # book/line taken (null=team mkt)
    odds_snapshot = FK("odds.OddsSnapshot", PROTECT, null=True)
    prop_prediction = FK("props.PropPrediction", PROTECT, null=True)  # only if model helped
    cell        = CharField(max_length=8)                # EdgeRule.cell at publish
    venue       = CharField(max_length=16)               # DFS|SOFTBOOK
    market_key  = CharField(max_length=24); side = CharField(max_length=8)  # OVER|UNDER|HOME
    line        = DecimalField(6,2, null=True)
    sharp_fair_prob     = DecimalField(6,5)              # the devig benchmark
    book_implied_devig  = DecimalField(6,5, null=True)
    model_prob  = DecimalField(6,5, null=True)           # secondary, when present
    edge        = DecimalField(7,5)                      # price*fair - 1
    ev          = DecimalField(7,5)
    min_acceptable_price = DecimalField(6,3)             # THE floor (relines fast)
    published_at = DateTimeField(); expires_at = DateTimeField()   # tipoff
    status      = OPEN|WON|LOST|PUSH|VOID|EXPIRED|RETRACTED   # +PUSH (whole-number lines)
    settled_at  = DateTimeField(null=True)
    audit       = JSONField(default=dict, blank=True)    # full gate trail + devig inputs
    UniqueConstraint(prop_line, cell)   # + player/game dedupe at publish
    Index(status, expires_at), Index(-published_at)

--------------------------------------------------------------------------------
(3) ETL ORCHESTRATOR + CELERY-BEAT SHAPE (ingest → predict → settle → validate)
--------------------------------------------------------------------------------

Reuse apps/ingestion/etl.py WHOLESALE — same parent/child JobRun pattern, same
no-key-no-crash / no-data-no-crash contracts (ADR 007), same blocking validate
gate that raises non-zero on hard fail. Only the STAGE BODIES change.

STAGES (adapt STAGES tuple in etl.py):

  anchor   (keyless*)   nba_api: schedule -> results (Game SCHEDULED->FINAL) ->
                        TeamBoxScore + PlayerBoxScore ingest. *nba_api needs no
                        key but is IP/rate-limited: treat exactly like a keyless
                        source with network tolerance (a 429/blip = counted+
                        skipped child, never a raised run failure — the ESPN
                        pattern in _run_espn).

  props    (key-gated)  *** the money stage *** The Odds API BUSINESS:
                        - team markets (h2h/spreads/totals) -> OddsSnapshot
                        - player props (player_points/rebounds/assists/pra/
                          threes/...) -> PropLine, capturing SHARP (pinnacle,
                          circa) + soft + DFS books in one pass.
                        Extend odds/sources/the_odds_api.py with the prop
                        market keys; each poll window (t3d/t24/final90) mirrors
                        soccer's t7d/t24/final2h.

  enrich   (mixed)      injuries (ESPN/rotowire KEYLESS -> InjuryReport; the
                        30-min-pre-tip final report is the highest-value poll),
                        DFS pick'em lines (Underdog/PrizePicks scraper -> PropLine
                        rows with payout_mult), optional real-time EV vendor
                        (OddsJam/StatsBench) as a sharp-fair cross-check.

  validate (always)     the blocking gate (validation.py adapted): prop-line
                        coverage per slate, sharp-anchor presence (>= X% of prop
                        lines have a Pinnacle/Circa peer to devig against),
                        box-score completeness, minutes conservation (sum≈240+OT),
                        stale-injury freshness. HARD FAIL -> non-zero exit +
                        Sentry, same as soccer.

SEPARATE beats (NOT in the ETL, mirroring soccer's split of predict/publish/settle):
  predict:  MinutesProjection + PlayerForm rebuild, then PropPrediction (Poisson/
            neg-binom) for NEGLECTED lines, then PropConsensus devig materialise.
  publish:  edge selection -> EdgePick candidates (devig soft/DFS vs sharp-fair,
            apply EdgeRule gates + RiskProfile rails + PipelineState breaker).
  settle:   grade EdgePick / Bet / DFSEntry from PlayerBoxScore; compute CLV.

--------------------------------------------------------------------------------
(6) THE TOP 3 THINGS THAT DIFFER BECAUSE BASKETBALL ≠ SOCCER
--------------------------------------------------------------------------------

1. PLAYER-FIRST SCHEMA. safepicks made Match/Team the grain and left Player a
   bare string (deferred to "Phase 3+"). basketballpicks makes Player,
   PlayerBoxScore and the two-sided PropLine the first-class, high-cardinality
   core (200-400 lines/night). The unit of value shifts from team-match to
   player-game-market.

2. THE HERO ENGINE IS DEVIG + LINE-SHOP, NOT A FORECASTING MODEL. In safepicks,
   sharp_anchor.py is an evidence-only study explicitly forbidden from writing
   Picks; the product came from the CORE model's own probabilities. Here that
   devig-vs-sharp-consensus study is PROMOTED to the live product core (apps/
   edge), and the model (PropPrediction) is a secondary input used only on
   neglected/thin lines. We harvest bookmaker laziness, we do not out-forecast
   the sharp price — because (per the feasibility memo) we cannot.

3. DFS PICK'EM AS A FIRST-CLASS VENUE + PARLAY CONSTRUCT, AND FORWARD-ONLY
   VALIDATION. safepicks is singles-only paper bets vs sportsbooks, validated on
   a deep (2012+) odds archive. basketballpicks adds DFSEntry — correlated
   2-6-leg pick'em combos on Underdog/PrizePicks, the durable limit-resistant
   home for the edge — with new correlation/partial-hit staking math; and
   because prop odds history only reaches ~2023, validation leans on the FORWARD
   paper-CLV harness (paper_clv.py promoted to central) rather than a deep
   backtest. (Bonus structural differences: NBA injuries are league-mandated and
   public — a clean InjuryReport feed vs soccer's "injuries: 2 rows" — and the
   exploitable signal is the SECOND-ORDER usage cascade onto teammates' props
   that soft books reprice slowly across 300 lines.)
