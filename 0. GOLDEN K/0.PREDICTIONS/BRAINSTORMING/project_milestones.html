Project Milestones & Process

Turns the v3.0 SAFE-FIRST plan into an executable project: 11 milestones with task checklists, 5 hard gates with written verdicts, a definition of done for every task, a risk register, and pre-written kill/pivot criteria so the hard decisions are made now — not rationalized in the moment.

Process Framework

🔄0.1 · Working rhythm

  • Work in milestones, not sprints. A milestone is done when its exit gate passes — never on a calendar date. Durations are planning estimates, not deadlines that bend quality.
  • Weekly review (30 min, even solo — write it down): what moved, what is blocked, what did the data say, any gate criteria newly met or broken, decision-log entries.
  • One milestone in progress at a time. Parallel work only inside a milestone's own task list.

✅0.2 · Definition of Done (every task)

  • Code merged to main via PR (even solo — PRs create the audit trail), CI green
  • Tests exist for the new behavior (golden tests for math per [PLAN §10.5])
  • No leakage: feature/data changes re-run the as-of assertion suite
  • Documented: README/docstring updated; schema changes get a migration + CHANGELOG line
  • Reproducible from the repo + seed data alone

🚧0.3 · Gate reviews — hard checkpoints

GateAfterQuestion
G0M1Is the data trustworthy?
G1M4DOES THE EDGE EXIST? (go/no-go)
G2M7Does the engine behave end-to-end?
G3M9Does paper trading match the backtest? (go-live)
G4quarterly ∞Do the cells still earn their place?

A gate verdict is a short written doc: evidence, decision, and what would change the decision. No verbal-only gates.

📜0.4 · Non-negotiable project rules

  • No real money before G3. No exceptions, no "small test bets".
  • Zero picks is a correct output — never tune thresholds to make a day look productive.
  • Every threshold lives in the DB (risk_profile / market_rule), never in code.
  • Nothing writes to main without a PR; backtest datasets are read-only snapshots.

In prose: bootstrap, data, the probability engine and calibration feed the M4 backtest, whose MBI cell report decides GO or NO-GO at gate G1. On GO, the ML layer, live pipeline and safe-pick engine are built and proven end-to-end (G2), the product UI ships, and a minimum 4-week paper trade must match the backtest (G3) before any real stake. Estimated calendar: ~4 months to G3 full-time. The only immovable duration is M9's paper-trade window — real fixtures cannot be compressed; weekends are the data.

M1

Data Foundation

weeks 1–2

🎯Goal: 10+ seasons of trustworthy historical data for the safe-first league set, queryable in PostgreSQL

  • Migrations for reference / fixture / odds tables [PLAN §4]
  • football-data.co.uk ingester: dominant-team leagues (SC0, P1, N1, G1, T1 + extra AUT/SUI) and scoring leagues (D1, D2 + extra NOR/SWE) [ODDS §5] — 10+ seasons each incl. closing odds
  • TeamAlias resolver + fuzzy matcher + admin review queue (expect ~5–10% of names to need manual mapping — do it now)
  • Raw payload storage (JSONB) + idempotent re-runnable parsers
  • Data-quality audit report: matches per league-season, missing-odds %, duplicates, result sanity vs [ODDS §5] base rates
  • Data-completeness scorer v1 (results + odds depth)

GATE G0 "Is the data trustworthy?"

  • Row counts match source counts per league-season (spot-check 10)
  • < 1% of matches missing closing odds in target leagues
  • Base rates computed from OUR db match [ODDS §5] ranges
  • Written verdict committed to /docs/gates/G0.md
M2

Probability Engine

weeks 3–4

🎯Goal: Dixon-Coles + Elo producing a scoreline matrix → S1–S4 probabilities for any historical fixture, leakage-free

  • Elo (home-adv term, goal-diff multiplier, per-league K) + daily historical replay → team_rating rows
  • Dixon-Coles with time decay; validate vs published paper numbers (golden test) — do not skip
  • Scoreline matrix → derived market probabilities: 1X, DNB (draw-excluded renorm), O1.5, AH−1.0 win/push/loss split [PLAN §6.1]
  • feature_snapshot builder v1 (ratings + form windows [PLAN §5.1–5.2]) with as-of enforcement
  • Leakage test suite — a deliberately-leaky fixture must FAIL it (test the tests)

EXIT GATE

  • DC golden tests pass
  • S1–S4 probabilities generated for ≥ 95% of historical matches in target leagues
  • Leakage suite green
M3

Calibration

weeks 4–5 · overlaps M2 tail

🎯Goal: calibrated probabilities with band-ECE measurement — the number the whole product stands on [PLAN §6.3]

  • Shin de-vig + golden tests vs hand-computed cases (multiplicative fallback)
  • Isotonic + beta calibration fit on walk-forward held-out slices
  • Band-ECE metric on [0.80, 0.97], high-resolution bins + reliability diagrams (saved per run)
  • Market baseline B0 (de-vigged closing) stored for every match — MBI becomes a query, not a recomputation

EXIT GATE

  • Band-ECE < 0.02 on held-out seasons for at least S1 and S3 probabilities in ≥ 3 leagues

If not: iterate here. Do NOT proceed to M4 with a miscalibrated engine — garbage in, garbage verdict out.

M4

Backtester + First MBI Cell Report

weeks 5–6GATE G1

🎯Goal: answer THE question — do positive-MBI safe cells exist for us?

  • Walk-forward backtest engine [PLAN §9]: full 8.1 gate pipeline, price floors, flat staking, slippage haircut, void handling
  • Slow-bleed detector (rolling 200-pick ROI bootstrap CI)
  • Cell grid report per (league, S1–S4): model log-loss, B0 log-loss, MBI, hit rate, avg odds, EXPIRED rate, yield, drawdown, sample size → league_metric rows
  • Bootstrap p-value of profit vs luck per candidate cell
  • Sensitivity checks: stable under floor margin ±1%, slippage 1% vs 2%, per-season splits

GATE G1 · GO / NO-GO written verdict → /docs/gates/G1.md

GO requires ALL of:

  • ≥ 5 cells with positive MBI AND positive yield over ≥ 2 full seasons AND ≥ 200 picks each AND p-value < 0.05
  • Combined portfolio (those cells, flat 1.5%) shows positive yield with max drawdown < 15% in walk-forward
  • Findings survive the sensitivity checks

NO-GO or WEAK-GO → §15 pivot options. Do not rationalize a weak result into a GO — this gate exists to protect the bankroll.

M5

ML Layer

weeks 6–8

🎯Goal: binary GBMs beat (or refine) Dixon-Coles per cell; champion/challenger machinery running

  • Feature store finalization (form / H2H / context [PLAN §5])
  • M1 "does 1X cover", M2 "O1.5", M3 "AH−1.0 covers" LightGBM models with monotonic constraints; per-league-cluster variants
  • Stacking meta-learner {DC, M1–M3, market prob} + calibration
  • MLflow tracking + registry; promotion rule implemented: band-ECE AND cell MBI AND yield, ≥ 2 seasons, ≥ 3 leagues [PLAN §9]
  • Optuna tuning (budgeted, walk-forward CV only)
  • Re-run the M4 cell report with challengers; update enabled cells

EXIT GATE

  • Challenger beats DC-only champion on the promotion rule for ≥ 3 cells — or a documented verdict that DC-only remains champion (that is fine!)
  • Cell grid re-report committed; market_rule.enabled updated by evidence; enabled-cell count recorded
M6

Live Data Pipeline

weeks 9–10

🎯Goal: the machine sees the real world — fixtures, odds, lineups — reliably and within budget

  • API-Football client: fixtures, results, LINEUPS, injuries (lineup latency measured — must arrive ~60–75 min pre-kickoff)
  • The Odds API client: multi-book odds; best-odds computation; closing-line capture job
  • Rate-limit/budget wrappers [PLAN §3]: token bucket, backoff, Redis cache, budget degradation order (final-2h protected)
  • Celery Beat schedules (core queue) [PLAN §10.2]; job_run audit rows; Sentry alert on missed beats
  • Live completeness scorer v2 (odds coverage + lineup + injury availability)
  • 2-week soak test: unattended run; measure sync success, odds latency, lineup timing

EXIT GATE 14 consecutive days:

  • ≥ 99% of scheduled jobs succeeded
  • Closing line captured for ≥ 95% of tracked fixtures
  • Lineups present ≥ 90 min pre-kickoff for ≥ 80% of target-league fixtures

M8

Product

🎯Goal: the human-facing layer — trust through transparency

  • DRF API endpoints [PLAN §10.4] + token auth + throttling
  • Notifications: daily digest + retraction alerts (email/Telegram)
  • Playwright smoke test: every page renders, zero-picks state renders, mobile no-overflow

EXIT GATE

  • A non-builder can open the dashboard and answer: "what should I take today, at what minimum odds, and why should I trust it?"
M9

Paper Trading + Hardening

weeks 15–16 + 4–6 wkGATE G3

🎯Goal: prove the live system matches the backtest before money exists

  • Paper-trade mode: every published pick "taken" at best floor-clearing odds, virtual bankroll, full ledger
  • Weekly live-vs-backtest comparison: hit rate, band-ECE, CLV, EXPIRED rate, avg odds vs floor
  • Circuit breakers armed and TESTED (force-trip each one)
  • Ops hardening: Sentry wired, postgres backup/restore drill, odds-volume partitioning if needed, secrets audit
  • Runbook: feeds die on matchday / breaker trips / manual void

GATE G3 · GO-LIVE written verdict → /docs/gates/G3.md

ALL of, over ≥ 4 consecutive weeks and ≥ 60 settled paper picks:

  • Hit rate within its cell-weighted expected band (no gate breach)
  • Positive CLV share ≥ 50%; live band-ECE < 2× backtest
  • Slow-bleed detector green; no unexplained gate failures
  • Every breaker fired correctly in its forced test

If any fail: diagnose, fix, RESTART the 4-week clock. The clock restarting is the process working.

Secondary Modules

optional · only after stable M10

📦Preconditions: ≥ 3 months profitable steady-state; core dials all green; spare API budget

Order of consideration — each gets its own mini-G1 gate:

  1. VALUE tier enablement (/value, quarter-Kelly, [ODDS §9]) — machinery exists; needs its own backtest gate.
  2. Expansion-league safe cells (Croatia/Czech watchlist → data completeness proof first).

15

Kill / Pivot Criteria — The Honest Exits

Written in advance so the decision is pre-made, not rationalized in the moment.

🛑G1 NO-GO — no positive-MBI cells at adequate samples

Pivot options, in order of preference:

  1. Different cells: re-run with S-market variants (DNB away, AH −1.25/−0.75, O1.5 in more leagues) before concluding.
  2. Better data: add xG (Understat) features and retry once.
  3. Reframe product: pure ANALYTICS tool (probabilities + calibration dashboards, no betting claims) — still valuable, zero bankroll risk.
  4. Stop. A clean, evidenced stop after ~6 weeks is a success relative to a slow bleed after 12 months.

⏸️Later exits

  • G3 fails 3 times (3 restarts of the paper-trade clock): backtest and reality disagree — treat as R2 (leakage) or R4 (data) until proven otherwise; freeze go-live indefinitely.
  • In production: any quarter with negative yield AND negative CLV share → stakes to 0.1%, full audit, G1-style re-verdict required to ramp again.
Standing rule: the product's credibility asset is the honest ledger. If a choice ever arises between looking good and reporting truthfully, the ledger wins — that is the whole product.
