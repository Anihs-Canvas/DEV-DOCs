    2.1  SM Architecture — Warp Schedulers and Dispatch Units
         - H100 SM: 128 CUDA Cores, 4 Tensor Cores, 1 RT Core, 256KB Register File
         - Warp scheduler: 32 threads per warp, SIMT execution model
         - Dispatch unit: issues instructions to CUDA Cores / Tensor Cores / LD/ST units
         - Warp stall reasons: memory latency, synchronization, branch divergence

    2.2  Memory Hierarchy — Registers to HBM and Everything Between
         - Register File: 65,536 × 32-bit registers per SM (fastest, private to thread)
         - L1 Cache / Shared Memory: 256KB unified (configurable split)
         - L2 Cache: 50MB on H100 (shared across all SMs)
         - HBM3: 80GB, 3.35 TB/s bandwidth (shared across all SMs)
         - Memory coalescing: how to avoid strided access penalties
         - [🧪 LAB] Profile memory access patterns with Nsight Compute

         [GPU MEMORY HIERARCHY — Speed vs Size Tradeoff]
         ┌──────────────────────────────────────────────────────────────────────────┐
         │                    GPU MEMORY HIERARCHY — H100                              │
         │                                                                          │
         │   FASTEST │  REGISTERS                                              │ 256KB │
         │    (~0 ns)│  ████████████████████████████████████████████████████   │per SM │
         │           │  65,536 × 32-bit per SM. Private to each thread.        │       │
         │           │                                                        │       │
         │    (~20ns)│  SHARED MEMORY / L1 CACHE                              │ 256KB │
         │           │  ████████████████████████████████████████████           │per SM │
         │           │  Programmer-managed (shared) or HW-managed (L1).       │       │
         │           │  Configurable split: up to 228KB shared, 28KB L1.      │       │
         │           │                                                        │       │

         │           │  ███████████████████████████████████████                │Shared │

         │           │                                                        │       │

         │           │  Strided access: serializes memory channels.           │       │

    2.3  Tensor Cores — The AI Engine Inside
         - MMA (Matrix Multiply-Accumulate) instruction set
         - Precision modes: FP64, TF32, FP16, BF16, FP8, INT8, FP4 (Blackwell)
         - Tensor Core throughput: 989 TFLOPS FP16 on H100
         - Async copy: TMA (Tensor Memory Accelerator) on Hopper
         - [🧪 LAB] Benchmark Tensor Core vs CUDA Core matrix multiply

         [TENSOR CORE OPERATION — Matrix Multiply-Accumulate (MMA)]
         ┌──────────────────────────────────────────────────────────────────────────┐
         │                    TENSOR CORE — MMA OPERATION                             │
         │                                                                          │
         │     MATRIX A (FP16)    MATRIX B (FP16)     ACCUMULATOR (FP32)           │
         │     ┌───────────┐      ┌───────────┐       ┌───────────┐                │
         │     │ a a a a   │      │ b b b b   │       │ c c c c   │                │
         │     │ a a a a   │  ×   │ b b b b   │  +  = │ c c c c   │  (FP32 result) │
         │     │ a a a a   │      │ b b b b   │       │ c c c c   │                │
         │     │ a a a a   │      │ b b b b   │       │ c c c c   │                │
         │     └───────────┘      └───────────┘       └───────────┘                │
         │     4×4 FP16           4×4 FP16             4×4 FP32                     │
         │                                                                          │
         │     IN ONE CLOCK CYCLE (H100, 4th Gen Tensor Core):                      │
         │     ┌─────────────────────────────────────────────────────────────────┐  │
         │     │  1 Tensor Core = 1 MMA operation = D = A × B + C               │  │
         │     │  1 SM = 4 Tensor Cores = 4 MMA operations per clock             │  │
         │     │  1 H100 = 132 SMs × 4 Tensor Cores = 456 MMA ops/clock         │  │
         │     │  989 TFLOPS FP16 = 456 × 1.98 GHz × 1024 ops/MMA               │  │
         │     └─────────────────────────────────────────────────────────────────┘  │

Chapter 3: GPU Memory Management — Professional Techniques

    3.1  CUDA Memory Types — When to Use What
         - Global Memory (HBM): large, slow, all threads accessible
         - Shared Memory: small, fast, block-level sharing
         - Constant Memory: read-only, cached, uniform access pattern
         - Texture Memory: spatially cached, 2D access optimized
         - Unified Memory: CPU+GPU single address space (convenience vs performance)
         - Pinned Memory: page-locked host memory for faster PCIe transfers

         - [LAB] Optimize anihpj's attention mechanism with shared memory tiling

    3.4  Memory Pool and Stream-Ordered Allocation

         ┌──────────────────────────────────────────────────────────────────────────┐

         │  │   └── Persistent? → RMA GPU or NVSwitch module                        │

         │  ├── XID 79: GPU Fell Off Bus                                             │
         │  │   ├── Check PCIe: lspci | grep nvidia (is GPU visible?)               │

         │  │   └── >100 pages → Urgent RMA, GPU memory failing                     │

         │  │                                                                        │
         │  └── XID Unknown or Multiple                                              │
         │      └── Run: nvidia-bug-report.sh → Attach to NVIDIA support ticket     │
         │                                                                          │
         │  🎯 KEY TOOL: nvidia-bug-report.sh — generates complete debug bundle     │
